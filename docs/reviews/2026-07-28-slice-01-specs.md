## Находки

### 1. important — тест границы не стережёт «бэкенд не знает про Qt»

**Место:** `tests/backend/test_layers.py:47-52` — список запрещённого есть только
для `client`; для `backend` запрещён единственный корень `client`.

**Суть.** CLAUDE.md, раздел «Решения»: «Интерфейс не знает про SQLAlchemy и
httpx, **бэкенд не знает про Qt**». `docs/specs/2026-07-27-async-and-qt.md:23`:
«Бэкенд тестируется без Qt. Обычный `pytest`, никакого окна»; там же строка 44:
«Ни один объект бэкенда не должен хранить ссылку на виджет… единственная надёжная
защита — не иметь такой возможности». Сегодня `import PySide6` в любом файле
`backend/` проходит все три теста молча. Симметрия правила держится только с
одной стороны.

**Оговорка (это не нарушение плана).** Проверку добавляет план 5, задача 1,
шаг 2 (`docs/plans/2026-07-27-client-shell.md:150-151`):
`assert offenders("backend", {"PySide6"}) == []`. То есть дыра запланированная,
а не забытая.

**Почему всё же important.** Между сегодняшним днём и планом 5 пишется весь
бэкенд целиком — планы 2, 3 и 4: источники, репозитории, сервисы, сборка. Всё
это время сторож стоит вполоборота, а обнаружится нарушение только тогда, когда
бэкенд уже написан. Цена закрытия — три строки в уже существующем файле, помощник
`offenders` для этого готов.

**Предложение.** Перенести `test_backend_does_not_import_qt` из плана 5 в
`tests/backend/test_layers.py` сейчас, а в плане 5 шаг 2 сократить до второй
проверки. Красной фазы у неё нет, и план 5 сам это оговаривает
(`client-shell.md:154-156`).

Там же замечу для будущего исполнителя плана 5: `test_client_does_not_import_the_image_library`
из того же шага дублирует уже действующую проверку — `PIL` входит в
`BANNED_IN_CLIENT` (`test_layers.py:6`) с плана 1, и `test_client_does_not_import_storage_libraries`
его ловит. Отдельный тест ничего не добавляет.

### 2. minor — докстринг третьей проверки приводит пример, который сам же разрешает

**Место:** `tests/backend/test_layers.py:56-61`.

**Суть.** Докстринг объясняет, почему проверки по корневым именам мало, примером
`backend.model.link`: «такой же `backend`, как и `backend.model`, а тянет за
собой репозитории, сессию и синхронный поход к базе мимо рантайма». Пример
неверен дважды. Во-первых, реализованный список разрешает его: условие
`module.startswith(name + ".")` при `name == "backend.model"` пропускает
`backend.model.link` (`test_layers.py:69-70`). Во-вторых, `backend/model/link.py`
по плану 3 — это `ExternalLink` и `parse_link`, чистый разбор строки без базы и
сети (`card-writing.md:2366-2400`), и клиент импортирует `parse_link` совершенно
законно (`client-modals.md:2840, 3083`).

Правило 11 манифеста: комментарий объясняет неочевидное решение, а не вводит в
заблуждение. Тот же текст лежит и в плане (`storage.md:271-276`), то есть код
переписан верно — ошибка унаследована.

**Предложение.** Заменить пример на тот, который проверка действительно ловит, —
`backend.storage.repository.library` или `backend.service.search`, — и поправить
план 1 в том же месте.

### 3. minor — ключи API не обрезаются по краям, в отличие от `DATA_DIR` и `LOG_LEVEL`

**Место:** `backend/config.py:34-39` против `config.py:32, 41`.

**Суть.** `DATA_DIR` и `LOG_LEVEL` проходят через `.strip()`, потому что в
`.env.example` объявлены пустыми и пробелы там ожидаются (тест
`test_blank_data_dir_falls_back_to_default`). Ключи читаются без обрезки, хотя
объявлены в том же файле теми же пустыми строками. Ключ из одного пробела
окажется «заполненным», и вместо «ключа нет» источник получит `401`.

Спека такого требования не предъявляет, поведение при пустом ключе нигде не
описано — поэтому minor, а не important. Код точно повторяет план
(`storage.md:420-424`).

**Предложение.** Либо `.strip()` на все шесть строковых значений одинаково, либо
короткий комментарий, почему ключи трактуются иначе.

### 4. minor — тест среднего утверждает поведение для значения вне шкалы

**Место:** `tests/backend/test_model.py:26-27`,
`test_zero_is_a_value_and_not_an_absence`.

**Суть.** `data-model.md:331` задаёт шкалам диапазон 1–10, `sections.md:102`
подтверждает десять столбцов. Ноль в шкалу не входит, то есть тест закрепляет
поведение на значении, которого в данных не бывает. По существу он стережёт
`is not None` против проверки на истинность — законная цель, но формулировка
«ноль — это значение, а не отсутствие» читается как утверждение о предметной
области, которого спека не делает.

Помечаю как наблюдение: качество тестов — линза другого агента, здесь важно
лишь то, что противоречия со спекой в самом коде нет.

**Предложение.** Ничего не менять либо переименовать тест в терминах реализации
(«пустая шкала отличается от нулевой»).

### 5. minor — в локальном `.env` остались ключи отвергнутого источника

**Место:** `.env` (в репозиторий не попадает) — строки `IGDB_CLIENT_ID` и
`IGDB_CLIENT_SECRET`.

**Суть.** IGDB отвергнут (CLAUDE.md, «Решения»), в `.env.example` его нет,
`backend/config.py` его не читает — то есть код и шаблон верны. Осталась только
локальная копия, унаследованная от предшественника.

**Предложение.** Убрать две строки при случае. На код не влияет.
