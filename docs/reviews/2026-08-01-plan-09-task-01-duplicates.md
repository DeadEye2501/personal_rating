# Ревью: повторы по картам — план 9, задача 1

**Дата:** 01.08.2026
**Измерение:** повторы во всём проекте по трём картам (`docs/module-map.md`,
`docs/front-map.md`, `docs/not-duplicates.md`). Дифф не читался.
**Объём:** весь проект. Особое внимание — новые `Field.svelte`, `Button.svelte`,
`CardModal.svelte`, `state/card.js`, `styles/cardform.css` против уже
существующих компонентов и файлов оформления.

Порядок: карты прочитаны целиком, кандидаты собраны по описаниям и по совпадению
формы, каждый подтверждён чтением **обоих** мест в коде. Неподтверждённые в
находки не попали и перечислены отдельным списком в конце.

## Strengths

- **Общее у строк ввода вынесено, а не скопировано.** Слайс не завёл третью копию
  правил подсказки: `.newtag__input { color, ::placeholder, :hover, :focus }`
  уехали из `newtag.css` в `field.css` общим списком селекторов
  (`client/styles/field.css:36-48`). Это ровно то, что велит правило 3, и сделано
  до ревью.
- **`Field.svelte` не поглотил соседей — и правильно.** Взять на себя ввод
  `SearchField.svelte` и `NewTag.svelte` можно было бы только доводами `type`,
  `maxlength` и `bind:this`, у которых сегодня нет потребителя (правило 8).
  Общее у трёх полей — класс `field__input` и его правила, и оно уже общее.
- **Оболочка окна расширена признаком, а не копией.** `Modal.svelte` получил
  четвёртый модификатор `card` рядом с `narrow`, `ask`, `danger`; второй
  оболочки под окно карточки не завелось.
- **`state/card.js` лежит в своём слое и ничего не знает про разметку.**
  Компонент `CardModal.svelte` сидит в `app/` и берёт только `components/` и
  `state/` — направление зависимостей не нарушено.
- **Питоновская зона чиста по этому проходу.** Новых пар, не разобранных в
  `docs/not-duplicates.md`, по карте модулей и карте данных не нашлось; слайс
  питона не касался.

## Issues

### Critical (Must Fix)

### Important (Should Fix)

#### 1. Кнопка ответного ряда объявлена дважды: компонентом и разметкой

**Где:** `client/components/Button.svelte:6` и `client/app/CardModal.svelte:49-56`
против `client/components/Confirm.svelte:12-16`.

**Что не так.** `.modalfoot` с двумя кнопками `.btn` есть ровно в двух местах
проекта, и написаны они по-разному. Новое окно карточки зовёт компонент:

```svelte
<Button variant="btn--cancel" onclick={onclose}>…</Button>
<Button variant="btn--go" onclick={() => onsave(form)}>…</Button>
```

а `Confirm.svelte` — предшественник — пишет ту же кнопку руками:

```svelte
<button type="button" class="btn btn--cancel" onclick={onclose}>Отмена</button>
<button type="button" class="btn" class:btn--danger={danger}
        class:btn--go={!danger} onclick={onyes}>{ok}</button>
```

Потребителей у `modalfoot.css` всего два, и оба они здесь. То есть у одного дела
теперь два имени: «кнопка окна» — это и `Button.svelte`, и три атрибута,
набранные по месту.

**Почему важно.** Компонент заведён ровно затем, чтобы вид кнопки правился одним
местом. Пока второй потребитель пишет её сам, любая правка `Button.svelte` —
добавленный `disabled`, `aria-*`, признак занятости при сохранении — молча минует
подтверждение удаления, а именно у него кнопка самая опасная. Машинная проверка
дублей это не ловит: она сравнивает тела функций питона и блоки CSS, а не
разметку Svelte.

**Как чинить.** Остаётся `client/components/Button.svelte`. `Confirm.svelte`
импортирует его и зовёт дважды; вариант согласия у него вычисляемый, и текущий
довод `variant` это уже позволяет:

```svelte
<Button variant={danger ? 'btn--danger' : 'btn--go'} onclick={onyes}>
  {#snippet children()}{ok}{/snippet}
</Button>
```

Обёртку `<div class="modalfoot">` можно оставить обоим — это одна строка, и
выносить её отдельным компонентом не за чем.

#### 2. `.field` повторяет `.newtag`: пять объявлений и правило фокуса дословно

**Где:** `client/styles/field.css:6-17` против `client/styles/newtag.css:5-15`.

**Что не так.** Приём «строка ввода без рамки, под фокусом проступает акцентная
черта» записан двумя блоками. Совпадают дословно пять объявлений и целое правило:

```
display: flex;
align-items: center;
padding: 0 2px;
border-bottom: 2px solid transparent;
transition: border-color .18s;
…:focus-within { border-bottom-color: var(--primary) }
```

Своего у `.field` — `min-width: 0` и `min-height: var(--field-h, 46px)`, у
`.newtag` — `gap: 8px`, `min-height: 34px`, `margin-top: 10px`. Блок `.newtag`
старше слайса, `.field` написан сейчас, то есть это ровно второе появление,
которое правило 3 велит выносить.

**Почему важно.** Машинная проверка дублей CSS сравнивает блоки по набору
объявлений целиком — здесь наборы разошлись на две-три строки, и она молчит.
Докстринг `field.css` при этом уже объявляет себя домом общего у трёх строк
ввода («общее у поиска в шапке, формы нового тега и полей карточки»), а держит
общим только внутренний `.field__input`: обёртка осталась скопированной. То есть
файл о себе говорит не всю правду, и следующая строка ввода спишет обёртку
третьим разом.

**Как чинить.** Остаётся объявление в `client/styles/field.css` — там же, где уже
живёт общее у этих двоих. Общая часть пишется списком селекторов, `newtag.css`
оставляет себе только своё:

```css
/* field.css */
.field,
.newtag { display: flex; align-items: center; padding: 0 2px;
          border-bottom: 2px solid transparent; transition: border-color .18s }
.field:focus-within,
.newtag:focus-within { border-bottom-color: var(--primary) }
```

Порядок каскада от этого не ломается: `main.js:14` подключает `field.css` раньше
`newtag.css:33`, специфичность у обоих одинаковая, и собственные `min-height`,
`gap` и `margin-top` формы тега по-прежнему перебивают общее.
Комментарий в `.field` («обёртка есть только у полей окна карточки») после
правки становится неправдой и правится вместе с кодом.

### Minor (Nice to Have)

#### 3. Системная полоса прокрутки гасится двумя одинаковыми парами объявлений

**Где:** `client/styles/field.css:64-70` против `client/styles/scrollarea.css:13-17`.

**Что не так.** Оба места отключают системную полосу одинаково —
`scrollbar-width: none` плюс `::-webkit-scrollbar { display: none }`, — и в обоих
по одной причине: рисовать полосу должна своя. В `field.css` это сказано вслух:
«вместо неё своя, та же, что в списках тегов». Третьего такого места в проекте
нет (проверено по всем 28 файлам оформления).

**Почему важно (немного).** Приём на два объявления, и цена ошибки маленькая, но
это ровно второе появление, а блок короче четырёх объявлений машинная проверка не
сравнивает вовсе.

**Как чинить.** Решить, кто здесь на самом деле прокручивается. Синопсис в
`CardModal.svelte:38-43` завёрнут в `Scrollarea`, у которой своя прокручиваемая
коробка, и при этом сам `textarea` тоже прокручивается и тоже прячет полосу —
одно из двух объявлений лишнее по существу, а не только как повтор. Если
прокрутка остаётся за `Scrollarea`, объявление должно остаться в
`scrollarea.css`, а `.field--area .field__input` теряет обе строки; если за
`textarea` — наоборот, снимается обёртка. Проверять это на живом окне, а не по
чтению: у второго вопроса измерение своё.

#### 4. Коробка постера 2:3 описана вторым блоком

**Где:** `client/styles/cardform.css:47-58` против `client/styles/film.css:60-73`.

**Что не так.** Совпадают пять объявлений из десяти:
`align-self: flex-start`, `aspect-ratio: 2 / 3`, `display: grid`,
`place-items: center`, `border-radius: 8px`. Различия — про вид и про размер:
у ленты ширина числом и градиентная подложка, у формы ширина переменной, рамка,
курсор и переход по наведению.

**Почему важно (немного).** Само по себе это геометрия, повторённая второй раз;
опасно оно тем, что задача 3 плана 9 положит в форму настоящую картинку, и
правило `img { width: 100%; height: 100%; object-fit: cover }` из `film.css:80`
попросится туда же третьим экземпляром.

**Как чинить — развилка, и решает её исполнитель.** Либо геометрия выносится
своим файлом оформления (`film.css` домом быть не может: он про карточку ленты, и
зависимость окна карточки от него — импорт вверх по смыслу), либо пара
признаётся разной и ложится строкой в `docs/not-duplicates.md` с доводом
«общая только пропорция, а содержание блока — вид: подложка ленты против места
под заливку». Выносить советую не раньше задачи 3: сегодня `.cardform__poster` —
пустая заглушка, и вынесенное придётся переписывать вместе с ней.

## Проверено и повтором не признано

Эти пары разобраны чтением обоих мест; в находки не идут. Строки для
`docs/not-duplicates.md` пишет исполнитель на шаге починки.

- `client/state/card.js:OWN` ≠ `client/components/Facts.svelte:ROWS` — оба знают
  про роли трёх типов, но отвечают на разные вопросы: `OWN` — какие поля показать
  **форме** по типу, `ROWS` — какие строки фактов показать **карточке** по тому,
  какие титры приехали; по типу `ROWS` не ветвится вовсе. Общего кода нет.
- `client/state/card.js:emptyCard` ≠ `backend/model/item.py:Item` и
  `bridge/library.py:_manual` — второе объявление имён полей нарочно, ровно тот
  же довод, что записан для пары `bridge/feed.py:FILTER_FIELDS` ≠
  `backend/model/query.py:Filters`: имя поля и есть контракт со страницей, и
  назвать его надо там, где собирают словарь формы.
- `client/components/Button.svelte` ≠ `client/components/ToolButton.svelte` —
  общее слово в имени. Первая — надпись в ответном ряду окна (`.btn`), вторая —
  круглая кнопка шапки (`.tools__btn`) с `aria-pressed`, иконкой и стрелкой
  направления сортировки.
- `client/components/Field.svelte` ≠ `client/components/SearchField.svelte` ≠
  `client/components/NewTag.svelte` — общее у трёх вводов вынесено в CSS
  (`field__input`). Слить разметку можно было бы только доводами без сегодняшнего
  потребителя: `type="search"` и обработчик Enter у поиска, `maxlength` и возврат
  фокуса у формы тега.
- Пять таблиц «по типу содержимого» — `state/card.js:OWN`,
  `state/kinds.js:NOUNS`, `app/App.svelte:ACCENTS`,
  `app/FiltersModal.svelte:GENRE_KINDS`, `app/Topbar.svelte` — совпадают только
  ключами: поля формы, падежи, акцент, пространство жанров и подписи вкладок.
  Предметы разные, общего кода нет.
- `bridge/refs.py:_of` ≠ `backend/service/people.py:PeopleSearch._entities` —
  оба переводят домен `people`/`companies` в репозиторий, но по разные стороны
  границы: мост берёт поле собранного `Backend`, сервис — свои внедрённые
  репозитории и `Backend` не видит вовсе. Слить нельзя механически.
- `client/styles/cardform.css:.modal--card` рядом с `.modal--narrow`,
  `.modal--ask`, `.modal--danger` в `modal.css` — совпадающих объявлений нет ни
  одного; вопрос «модификаторы одного блока в двух файлах» — про место (правила
  2 и 6), а не про повтор, и адресован соседнему измерению.
