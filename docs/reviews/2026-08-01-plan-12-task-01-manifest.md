### Important (Should Fix)

**1. `client/app/SearchScreen.svelte:215-217` — комментарий разметки врёт, и
неправдой его сделал этот же слайс. Правило 11.**

```
     Оценка кандидата сначала заводит карточку: `item_id` у него нет, и звать
     `marks.score` не с чем. Оценка вторым действием появится вместе с окном
     карточки. -->
```

Второе действие — это ровно `rate` на `:204-207`, написанное шагом 3 этой же
задачи: `const full = view.item_id ? view : await asked(view)` и следом
`patch(full, await put(full))`. То есть комментарий обещает в будущем то, что
стоит на двадцать строк выше. Первая его половина при этом верна и полезна —
почему заведение идёт первым.

*Чинить:* оставить первое предложение, второе снять. Заодно проверить соседний
абзац про `onmore` — он верен и остаётся.

**2. Предикат «строка узнаётся парой» объявлен дважды. Правило 3.**

Оба места открыл и прочитал:

- `client/app/reread.js:13-15`
  ```js
  views.filter((each) => gone.item_id != null
    ? each.item_id !== gone.item_id
    : !(each.source === gone.source && each.source_id === gone.source_id))
  ```
- `client/app/SearchScreen.svelte:141-142`
  ```js
  const same = (each, view) =>
    each.source === view.source && each.source_id === view.source_id
  ```

Это одно и то же выражение, написанное в двух файлах в один день. Машинная
проверка дублей его не видит — два тела короче пяти инструкций, и одно из них
внутри тернарника, — то есть сторожа у этой пары нет никакого.

Третьим объявлением того же знания стоит `SearchScreen.svelte:132`:
`` const key = `${view.source}:${view.source_id}` `` — та же пара, выраженная
строкой ключа.

*Какое объявление остаётся:* `same` в `reread.js`, с экспортом. Модуль уже
владеет вопросом «как раздел находит свою строку в списке» — об этом написаны
оба его докстринга (`:8-11` и `:24-26`), — и `without` тогда читается как
`gone.item_id != null ? byId : same`, а `SearchScreen` перестаёт объявлять
предикат у себя. Ключ `adopting` тоже стоит вывести из общего объявления, чтобы
пара не жила в файле третьим написанием.

**3. `client/app/App.svelte:112-119` — комментарий у `removed` больше не
описывает то, что там лежит. Правило 11.**

```js
  // Только что удалённая карточка: номер и момент. Раздел убирает её у себя, не
  // перечитывая ленту ...
  let removed = $state(null)
```

После правки `askRemoval` (`:196-200`) в `removed` кладётся и
`{ item_id: null, source, source_id, at }` — строка, которой в базе не было
вовсе и которую никто не удалял. Комментарий — единственное описание формы этого
сигнала, а его читают три потребителя: оба раздела и `without`. Сейчас он
утверждает «номер и момент», и по нему нельзя догадаться, что номера может не
быть.

*Чинить:* назвать оба состояния значения — «удалённая карточка либо кандидат,
ушедший из выдачи; у второго номера нет, и узнают его парой».

## Recommendations

**Прямые ответы на четыре вопроса слайса.**

- **`patch` в `SearchScreen:153-155` против `patch` в `LibraryScreen:109-112` —
  не повтор.** Открыл оба. Тела совпадают целиком, кроме предиката
  (`same(each, view)` против `each.item_id === view.item_id`), и предикат тут —
  всё содержание: одна строка узнаётся номером, вторая парой, потому что номера у
  неё может не быть вовсе. Слить можно только приняв предикат параметром, то есть
  функцией высшего порядка длиннее обеих. Довод у проекта уже записан дважды —
  `merge_fields` ≠ `overwrite_fields` и `_included` ≠ `_excluded` в
  `docs/not-duplicates.md`. **Пару надо записать туда же**, иначе следующий проход
  по картам разберёт её заново.
- **`rating.js` лежит там, где надо** — разбор в Strengths. В `state/` его
  положить нельзя: он ходит в `$api/`.
- **`adopting` и его `Map` — не абстракция на вырост**, потребителей два, оба
  сегодняшние.
- **`without` с ветвлением ответственность не размазывает.** Знание «как узнать
  строку» в `reread.js` и есть его дело; размазан не `without`, а предикат —
  находка 2.

**Записать в `docs/not-duplicates.md` три пары** (пишет исполнитель на шаге
починки):

- `client/app/SearchScreen.svelte:patch` ≠ `client/app/LibraryScreen.svelte:patch`
  — довод выше;
- `client/app/rating.js` ≠ `client/state/scores.js` — совпало слово «оценка»:
  первый пишет свою оценку через мост, второй только считает нотацию (ярлык,
  ступень, среднее, доля звезды) и в `api/` не ходит вовсе;
- `SearchScreen.started` ≠ `visible.js:asked` — обе помнят, что по карточке уже
  начато, и обе не сводятся: `asked` — политика квот, живёт весь сеанс и
  переживает смену раздела нарочно; `started` — снятие гонки двух поводов, живёт
  до `finally`.

**Унаследованное, в прирост не вменяю:** `again(done)` объявлен дословно
одинаково в обоих разделах (`SearchScreen:173-178`, `LibraryScreen:130-135`) и
различается одним доводом `refreshed` — этот повтор старше слайса, диффом не
тронут. Стоит взять в итоговое ревью плана вместе с двумя одинаковыми
`$effect`-ами по `removed`.
