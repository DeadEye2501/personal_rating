# Ревью повторов — план 4, задача 7 (внешний поиск и снятие дублей)

Измерение: повторы во всём проекте, не в диффе. Дифф не читался.

## Рассмотренные кандидаты

1. `name` — `TmdbClient`, `SteamClient`, `GogClient`
2. `_genres_of` (`backend/service/search.py`) против `resolved_genres`
   (`backend/service/genres.py`) и `GenresRepository.resolve`
3. `GenresRepository.index` против `GenresRepository.resolve`
4. `merge_results` (`backend/model/view.py`) против `_weave`
   (`backend/service/search.py`)
5. `ExternalSearch` против `Found`/`Missing`/`Refusal`
   (`backend/sources/errors.py`) и против прочих типов модели
6. `FakeSources` (`tests/conftest.py`) против `FakeCatalog`
   (`tests/backend/test_search.py`) и подставных объектов в
   `tests/backend/sources/`
7. `SearchService.local` против `SearchService.external`

Итого рассмотрено: **7**. Подтверждённых повторов, требующих действия: **0**.
Один пограничный случай (№1) — подтверждённый текстуальный повтор, но с
обоснованным решением «оставить», а не переносить в код.

## Разбор по каждому

### 1. `name` в трёх каталожных клиентах — повтор подтверждён, действие не требуется

Прочитаны все три места целиком:
`backend/sources/tmdb/client.py:71-75`, `backend/sources/steam/client.py:44-48`,
`backend/sources/gog/client.py:39-43`.

Тело и докстрока совпадают дословно:

```python
@property
def name(self) -> str:
    """Под этим именем источник назовётся в отказе — в том числе в отказе,
    который соберёт не он сам, а поймавший его исключение сервис."""
    return self._http.name
```

Это настоящий повтор — не «похоже, но разное». Три реализации, а не две:
формально порог правила 7 («абстракция со второй реализацией») пройден.

Тем не менее выносить не стоит. Причины:

- В проекте прямо решено: у клиентов источников нет общего базового класса, и
  добавление седьмого источника не должно требовать правок в существующих.
  Примесь — это наследование, и три из шести клиентов получили бы общего
  предка, которого сейчас нет ни у одного.
- Тело — одна инструкция, форвардинг приватного поля `self._http.name` наружу
  ради контракта, который спрашивает только `SearchService._broke`. Как
  Protocol, так и функция-помощник избавили бы только от повторной докстроки,
  а не от самого объявления `name = property(...)` на каждый класс — выигрыш
  не окупает выбор второй архитектуры ради трёх строк.
- В проекте уже есть прецедент того же рода: `docs/not-duplicates.md`
  документирует двухстрочную идиому раннего возврата, буквально повторённую в
  восьми файлах десять раз, и решение по ней — оставить, потому что вынести
  можно только вместе со сменой контракта `SourceHttp.get`. Докстроки классов
  `SteamClient` и `GogClient` тоже дословно совпадают («Аргумент `kind` есть
  ради общего контракта каталожных клиентов и игнорируется») — то есть
  дословное повторение мелких мест в каталожных клиентах уже принятый в
  проекте стиль, а не недосмотр.

Решение: **оставить как есть**. Это не пара «разное по существу, совпало по
виду» — фактически тела одинаковы, — поэтому формально в `not-duplicates.md`
не просится (файл про пары, ошибочно принимаемые за повтор). Записывать
отдельным пунктом не стал: изменений в код это не требует, а описанное выше
обоснование уже лежит в этом отчёте.

### 2. `_genres_of` / `resolved_genres` / `GenresRepository.resolve` — не повтор

Прочитаны `backend/service/search.py:108-130`, `backend/service/genres.py`
целиком, `backend/storage/repository/genres.py:18-57`.

Все три переводят чужие метки в наши жанры, но механизм и результат разные:

- `GenresRepository.resolve(source, ext_ids)` — один запрос в `genre_map` по
  конкретному пространству и конкретному набору идентификаторов, отдаёт
  **список id** (`list[int]`).
- `resolved_genres` (сервис) группирует `(space, ext_id)` по пространству и
  зовёт `resolve` на каждое — по одному запросу на пространство, на **запись
  одной карточки**. Тоже отдаёт id, для `set_for_item`.
- `_genres_of` не делает запросов вовсе: она читает уже построенный `index`
  (результат `GenresRepository.index`, вызванного заранее по одному разу на
  пространство для **всей страницы** кандидатов), и отдаёт **`Genre`-объекты**
  для показа в карточке выдачи.

Разница — тот же довод, что уже зафиксирован в `not-duplicates.md` для пары
«одна карточка против страницы»: `resolved_genres` отвечает про одну запись
здесь и сейчас через прямой запрос, `_genres_of` — про пачку кандидатов через
предзагруженный индекс, чтобы не бить в базу на каждый хит поиска. Слитые, они
дали бы либо N запросов на страницу выдачи (потеря, ради которой заведён
`index`), либо id вместо `Genre` там, где нужен объект для отрисовки.

Не повтор.

### 3. `GenresRepository.index` / `GenresRepository.resolve` — не повтор

Оба читают `genre_map`, но отвечают на разные вопросы: `resolve` — «каким id
соответствуют вот эти идентификаторы одного пространства» (фильтр по
`ext_id.in_(...)`, результат — id), `index` — «всё соответствие целиком по
пространству» (без фильтра, джойн на `genre`, результат — словарь
`ext_id -> Genre`, отсортированный по имени). Тот же случай «одна карточка
против страницы», что и в п. 2: `resolve` используется там, где известен
конкретный набор идентификаторов и не нужен захват всей таблицы, `index` — там,
где дешевле один раз прочитать всё пространство, чем спрашивать по хиту.
Не повтор.

### 4. `merge_results` / `_weave` — не повтор

`merge_results` (`backend/model/view.py:89-114`) снимает дубли между своей
библиотекой и уже собранной внешней выдачей по ключу «источник +
идентификатор», работает над `CardView` и вызывается на последнем шаге, вне
сервиса поиска. `_weave` (`backend/service/search.py:37-54`) переплетает
несколько **необработанных** ответов `SearchHit` от разных клиентов одного
типа контента (Steam и GOG) вперемешку по кругу, до перевода в `CardView`, и
дублей не снимает вовсе — это про порядок показа, а не про уникальность.
Разные слои, разные типы данных, разные задачи. Не повтор.

### 5. `ExternalSearch` — не повтор

`ExternalSearch` (`backend/service/search.py:28-34`) — агрегат по итогам
опроса нескольких внешних источников сразу: уже сконвертированные `CardView` и
собранные `Refusal`. `Found`/`Missing`/`Refusal` (`backend/sources/errors.py`)
— union одного исхода одного запроса одного клиента; `ExternalSearch` в этот
union не входит и не оборачивает его — он строится из результатов `Outcome` за
всех клиентов сразу, отдельно копя `views` и `refusals`. Похожих на
`ExternalSearch` типов «выдача плюс отказы» больше нигде в `backend/model` не
найдено (проверено поиском по `refusals` — совпадение одно, в самом
`search.py`). Не повтор.

### 6. `FakeSources` / `FakeCatalog` / подставные объекты в `tests/backend/sources/` — не повтор

`FakeSources` (`tests/conftest.py:94-105`) — фальшивый реестр уровня
`Sources`: у него один метод `catalog_for`, отдающий заранее заданных клиентов.
`FakeCatalog` (`tests/backend/test_search.py:20-33`) — фальшивый клиент
уровня `TmdbClient`/`SteamClient`: `search`, `name`, журнал вызовов `asked`. Это
две ступени одной иерархии подстановки, не повтор одного и того же: в
`test_search.py` `FakeSources` оборачивает именно экземпляры `FakeCatalog`. В
`tests/backend/sources/` (проверено — там нет ни одного класса `Fake*`, кроме
не связанного `FakeClock`) клиенты тестируются целиком через настоящий
`SourceHttp` с подменённым транспортом, а не через фальшивые объекты клиента —
другой уровень имитации. Не повтор.

### 7. `SearchService.local` / `SearchService.external` — не повтор

Общее — только сигнатура `(kind, query)`. `local` — две строки, прямая
композиция `LibraryRepository.search` и `ViewsRepository.in_order`. `external`
— 25 строк: `asyncio.gather` по нескольким клиентам, разбор трёх исходов,
переплетение, отказы, конвертация в `CardView`. Общих тел нет. Не повтор.

## Вердикт

Из семи кандидатов подтверждён один настоящий текстуальный повтор — свойство
`name` в трёх каталожных клиентах, — и по нему обосновано решение оставить как
есть, без изменений в коде. Остальные шесть при чтении обоих мест оказались
разными по существу: либо разный слой и структура данных, либо тот же
принятый в проекте довод «одна карточка против страницы».

**Готово к коммиту: Да**
