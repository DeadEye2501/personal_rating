# Ревью среза 01: качество тестов

Предмет — 18 тестов из `tests/backend/test_layers.py`, `test_config.py`,
`test_model.py` и код, который они охраняют: `backend/config.py`,
`backend/model/*`. Линза одна: **может ли тест упасть, если сломается ровно то,
ради чего он написан.**

Метод — мутационная проверка руками. 32 поломки внесены в рабочее дерево по
одной, после каждой прогон `pipenv run pytest -q`, после прогона откат
`git checkout -- <файл>`. Ни одна правка не осталась: `git status` в конце пуст.

Исходное состояние: `18 passed in 0.08s`.

## Счёт

| | |
|---|---|
| Поломок внесено | 32 |
| Поймано | 18 |
| **Прошло молча** | **14** |

Находок: **0 блокирующих, 6 важных, 5 мелких.**

Половина непойманного — не дыры, а незаконченное покрытие однотипных мест: из
семи замороженных датаклассов проверен один, из двадцати восьми членов
перечислений — два. Но именно так и выглядит тест, который перестаёт ловить: он
не ломается, он просто не смотрит в соседнее поле.

## Важные

### И1. `test_keys_are_read_and_missing_ones_are_empty` проверяет один ключ из шести

`tests/backend/test_config.py:29`, код — `backend/config.py:35-39`.

Имя обещает ключи во множественном числе. Тело читает `TMDB_API_KEY` и смотрит,
что `omdb_key` пуст. Пять оставшихся сопоставлений «поле ↔ имя переменной» не
проверяет никто.

Мутация: `mdblist_key=env.get("POISKKINO_API_KEY", "")` → **18 passed.**

Это ровно тот класс опечатки, ради которого блок из шести одинаковых строк и
опасен: копипаста с недоправленным именем. Последствие тихое — MDBList получает
ключ Кинопоиска, отвечает отказом, отказ классифицируется как «источник не
ответил», и оценка агрегатора просто не приезжает. Ровно «тихо перестаёт
работать» из `docs/specs/2026-07-27-testing.md:3`.

Чинится в том же тесте: подать словарь из шести разных значений и сверить шесть
полей.

### И2. Чтение `LOG_LEVEL` из окружения не проверено вовсе

`tests/backend/test_config.py:35`, код — `backend/config.py:40`.

Единственный тест на `log_level` проверяет значение по умолчанию. Того, что
переменная вообще читается, не проверяет ничто.

Мутация: `log_level="INFO"` вместо `env.get("LOG_LEVEL", "").strip() or "INFO"`
→ **18 passed.**

То есть половина строки — чтение из окружения и `.strip()` на нём — не покрыта.
Пользователь ставит `LOG_LEVEL=DEBUG` в `.env`, идёт смотреть подробный лог,
получает `INFO` и никакой ошибки. Для `DATA_DIR` три случая (умолчание,
переопределение, пустая строка) разобраны честно; для `LOG_LEVEL` из тех же трёх
есть один.

### И3. `test_enum_values_match_the_schema` проверяет 2 значения из 28

`tests/backend/test_model.py:62`, код — `backend/model/kinds.py`.

Имя говорит «значения перечислений совпадают со схемой», комментарий рядом верно
объясняет почему: они ложатся в базу текстом. В теле — два `assert`:
`Kind.SERIES` и `Source.MANUAL`. Перечислений семь, членов двадцать восемь.

Мутации:

| Поломка | Результат |
|---|---|
| `Kind.MOVIE = "film"` | 18 passed |
| `Source.TMDB = "themoviedb"` | 18 passed |
| `GenreKind.FILM = "movie"` | 18 passed |

Все три значения — буквально текст схемы:
`docs/specs/2026-07-27-data-model.md:352` (`movie | series | game`), `:246`
(`manual | tmdb | steam | gog`), `:96` (`film | game`). Дальше по спеке ещё
`IdSource` (`:262`), `RatingSource` (`:278`), `PersonRole` (`:215`),
`CompanyRole` (`:251`) — не проверен ни один член.

Цена расхождения не в исключении, а в молчании: справочник жанров зашит в
миграцию строками `film`/`game` (задача 8 плана хранилища), и разъехавшееся
значение даст пустую выборку, а не ошибку.

Чинится параметризацией: список пар «член → строка» и один `assert` по нему.
Заодно это единственное место, где список значений схемы будет записан целиком.

### И4. Замороженность проверена у одного датакласса из семи

`tests/backend/test_model.py:30`.

`test_item_is_frozen` честно ловит своё: снятие `frozen=True` с `Item` даёт
`DID NOT RAISE`. Но кроме `Item` в модели есть `Rating`, `Credit`, `Genre`,
`ExternalId`, `ExternalRating` и `Config` — и ни один не проверен.

Мутации (каждая — снятие `frozen=True`, `slots=True` оставлен):

| Класс | Файл | Результат |
|---|---|---|
| `Rating` | `backend/model/rating.py:13` | 18 passed |
| `Config` | `backend/config.py:8` | 18 passed |
| `Credit` | `backend/model/credit.py:6` | 18 passed |
| `Genre` | `backend/model/genre.py:6` | 18 passed |
| `ExternalRating` | `backend/model/external.py:13` | 18 passed |

Замороженность здесь не украшение. Это типы границы слоёв: они уезжают в главный
поток и живут там, пока карточка на экране. Незамороженный `Rating` — это виджет,
который правит объект у себя, а бэкенд об этом не знает; в пуле переиспользуемых
карточек (`docs/specs/2026-07-27-feed-rendering.md`) правка переживёт
перепривязку и уедет в чужую строку.

Чинится одним параметризованным тестом по списку классов границы — он же будет
ловить новый датакласс, заведённый без `frozen`.

### И5. Докстрока третьего теста границы называет случай, который тест пропускает

`tests/backend/test_layers.py:55-74`.

Докстрока (`:58-61`) прямо говорит, что проверка по корневым именам пропускает
`backend.model.link`, и что этот тест заведён ради таких случаев. Но правило
разрешения (`:69-70`) пускает не модуль `backend.model`, а всё поддерево
`backend.model.*`:

```python
if any(module == name or module.startswith(name + ".")
       for name in ALLOWED_FROM_BACKEND):
```

Мутация: `client/__init__.py` получает `from backend.model.link import Link` →
**18 passed.** Ровно та строка, что названа в докстроке как ловимая.

Тест при этом не пустой — `import backend.repository` он ловит (проверено).
Расходятся именно обещание и поведение, а это худший вид расхождения: читающий
через полгода поверит докстроке.

Чинить надо одно из двух, и выбор за автором:

- либо докстрока врёт и её надо переписать: поддерево `backend.model.*` открыто
  клиенту сознательно, потому что это и есть типы границы, а `backend.model.link`
  как пример репозитория выбран неудачно;
- либо открыт должен быть только сам пакет, и тогда `startswith(name + ".")`
  лишний — заодно он не делает ничего для `backend.config` и `backend.app`,
  которые модули, а не пакеты.

Моё чтение: верен первый вариант, правило разумное, а пример в докстроке взят
неудачно. Но пока эти два текста противоречат друг другу, тест нельзя считать
проверяющим то, что заявлено.

### И6. Никто не проверяет, что бэкенд не знает про Qt

`tests/backend/test_layers.py:47` — единственный тест про бэкенд, и он банит одно
корневое имя: `client`.

Мутация: `backend/config.py` получает `from PySide6.QtCore import QObject` →
**18 passed.**

Решение из `CLAUDE.md` симметрично: «Интерфейс не знает про SQLAlchemy и httpx,
бэкенд не знает про Qt», и линза ревью (`docs/reviews/README.md:20`) повторяет
его дословно. Проверена только одна половина: у клиента список из пяти
запрещённых корней, у бэкенда — один, и Qt в нём нет.

Импорт Qt в бэкенде — не абстрактная опасность. Он появляется естественным путём:
понадобился `QByteArray` для постера или `Signal` для уведомления, и граница
потоков ломается ровно там, где её и заводили
(`docs/specs/2026-07-27-async-and-qt.md`).

Чинится добавлением `PySide6` в набор запрещённого в бэкенде.

## Мелкие

### М1. `test_optional_fields_have_sane_defaults` проверяет 3 поля из 8

`tests/backend/test_model.py:43`. Проверены `year`, `original_title`,
`seasons_count`; не проверены `released_at`, `synopsis`, `poster_url`, `runtime`,
`episodes_count`.

Мутация `runtime: int | None = 0` → **18 passed.** Ноль вместо `None` доедет до
базы и до карточки, где сериал получит «0 мин».

То же у `Rating`: `test_rating_of_a_film_carries_no_aspects`
(`tests/backend/test_model.py:57`) проверяет три шкалы, но не `review`. Мутация
`review: str = None` → **18 passed**, а `review` — тот самый `TEXT`, который
уедет в базу как `NULL` вместо пустой строки.

Оба закрываются перебором полей с умолчаниями внутри уже написанных тестов.

### М2. Защита в `test_layers.py` ловит «пакета нет», но не «ничего не просмотрено»

`tests/backend/test_layers.py:37`.

Проверено:

| Случай | Результат |
|---|---|
| папки `client` нет | 2 failed — защита сработала |
| папка `client` есть, но пуста (ни одного `.py`) | 18 passed |
| маска `rglob("*.py")` → `rglob("*.pyx")` **плюс** реальный `import httpx` в клиенте | 18 passed |

Первое — то, ради чего защита писалась, и она работает. Второе и третье —
оставшаяся щель: тест зеленеет, когда просмотрел ноль файлов. Сегодня это
безобидно (в `client/` лежит один пустой `__init__.py`), но опечатка в маске
разоружает разом все три теста границы и не оставляет следа.

Закрывается в `offenders`: посчитать просмотренные файлы и потребовать, чтобы их
было больше нуля.

### М3. Оба теста про клиента сегодня структурно пусты

`tests/backend/test_layers.py:51` и `:55`. В `client/` лежит единственный пустой
`__init__.py` — обходить нечего, оба теста проходят на пустоте по построению.

Это нормально для среза, где клиента ещё нет: тест написан раньше кода
сознательно (задача 1 плана хранилища так и говорит). Записываю, чтобы эти два
теста не засчитывались как покрытие: их первый настоящий прогон случится в
плане 5.

### М4. `backend.app` в `ALLOWED_FROM_BACKEND` — разрешение без предмета

`tests/backend/test_layers.py:13`. Модуля `backend/app.py` в проекте нет. Правило
8 манифеста запрещает заводить ветку без сегодняшнего потребителя; здесь это
безобидно, но проверить это разрешение нечем, и до плана 4 оно останется строкой,
влияющей на результат теста и не покрытой ничем.

### М5. Ноль как значение шкалы — вне диапазона спеки

`tests/backend/test_model.py:26` подаёт `average_score(0, 10, None)`. Спека
(`docs/specs/2026-07-27-data-model.md:331`) объявляет шкалы как «1–10».

Тест при этом полезен и трогать его не надо — он единственный ловит подмену
`is not None` на `if aspect`. Но стоит понимать: он держится на значении, которое
по спеке в шкалу попасть не должно, а диапазон не проверяется нигде. Отдельный
тест на валидацию не предлагаю: самой валидации в коде нет, и правило 8 манифеста
велит не заводить её впрок.

## Чего не поймает ни один тест: сводка

По `backend/config.py`:

1. любое перепутанное имя переменной окружения, кроме `TMDB_API_KEY` (И1);
2. `LOG_LEVEL` перестал читаться из окружения (И2);
3. `Config` перестал быть замороженным (И4);
4. в бэкенд заехал Qt (И6).

По `backend/model/`:

5. любое значение любого перечисления, кроме `Kind.SERIES` и `Source.MANUAL` (И3);
6. `Rating`, `Credit`, `Genre`, `ExternalId`, `ExternalRating` перестали быть
   замороженными (И4);
7. умолчания пяти полей `Item` и поля `review` у `Rating` (М1).

По границе слоёв:

8. клиент тянет из `backend.model.*` что угодно, включая не типы границы (И5);
9. просмотр не нашёл ни одного файла — по пустой папке или по сломанной маске (М2).

Ни одна из девяти дыр не требует нового тестового файла: восемь закрываются
дописыванием в существующие тесты, девятая — строкой в `offenders`.
