# Ревью задачи 3 плана 13 — повторы по картам

Измерение одно: **повторы во всём проекте**, на фоне нового кода. Дифф не
читался ради диффа; читались обе карты, `not-duplicates.md` и оба места каждого
кандидата в коде.

Предмет слайса: седьмой источник — `backend/sources/oldgames/` (`client.py`,
`parse.py`), `tests/backend/sources/test_oldgames.py`, пять записанных страниц в
`tests/fixtures/oldgames/`, плюс `Source.OLD_GAMES`, реестр и сборка.

## Сильные стороны

- **Общее позвано там, где оно есть.** Новый клиент зовёт `SourceHttp`,
  `refuse_undocumented`, `parsed`, а не пишет своё: рукописного `try/except`
  вокруг разбора в нём нет ни одного, `Refusal` по неописанному коду он не
  строит руками. Это ровно то место, где седьмой клиент по образцу шести ломается
  чаще всего, — и оно чисто.
- **Общее не позвано там, где смысл другой, и это объяснено рядом.** `asked()`
  не зовётся, потому что `503` у этого сайта — «занят», а не отказ, и `asked`
  превратил бы его в `refuse_code`; `AT_ONCE` не уехал в `SourceHttp` с доводом,
  записанным прямо у константы (пятый довод конструктора переваливает предел
  правила 5, а политика разговора с одним сайтом остальным шести не нужна).
  Оба решения названы словами в самом коде.
- **`parse.py` не изобрёл ни одной готовой функции `convert.py`**, кроме одной
  (см. Important-1): `Credit`, `SearchHit`, `SourceCard`, `Item` собираются
  конструкторами модели, а не своими обёртками.
- **Разбор ломается громко, и это записано отдельным правилом в докстринге
  модуля.** У остальных шести источников такого правила нет, и оно не повтор
  чужого, а своё: перезапроса у игр не бывает.
- **`docs/other/not-duplicates.md` обслужен по ходу слайса, а не после.** Пара
  `GenreSource ≠ Source` протухла ровно так, как сама себе и предсказала, и
  разобрана заново с честным пересмотром довода. Записи про `SteamClient.card`,
  `_items`, `poster_url`, `genres`, `to_wire` продлены с датой 03.08.

### Important

#### Important-1. `_year` у Steam и у old-games — дословная копия

- `backend/sources/steam/parse.py:29` — `YEAR = re.compile(r"(?:19|20)\d{2}")`
- `backend/sources/steam/parse.py:144-150` — `_year(value: str | None)`
- `backend/sources/oldgames/parse.py:55-57` — `_year(written: str)`

Тела совпадают целиком:

```python
# steam                                  # oldgames
found = YEAR.search(value or "")         found = re.search(r"(?:19|20)\d{2}", written)
return int(found.group()) if found else None
```

Совпадает и **регулярное выражение** — `(?:19|20)\d{2}`, знак в знак, — и способ
чтения найденного, и тип возврата. Единственная разница косметическая: у Steam
шаблон вынесен константой модуля и допускается `None`, у old-games собран по
месту вызовом `re.search`.

Почему важно. Это **второе появление**, то есть ровно тот случай, который правило
3 велит выносить, а не копировать с правками. Машинная проверка дублей его не
увидела и не могла: тело в две инструкции, а сравнивается от пяти, — то есть
единственный сторож здесь этот проход. Цена расхождения не теоретическая: шаблон
у обоих задаёт, какие годы вообще существуют, и правка его на одной стороне
(например, `(?:18|19|20)` ради игр XIX века из каталога old-games) молча оставит
вторую сторону на прежнем поведении.

Отдельно: пара `backend/sources/convert.py:year ≠ backend/sources/steam/parse.py:_year`
уже разобрана и записана в `not-duplicates.md:56` — «первый берёт первые четыре
знака машинной даты, второй ищет год регулярным выражением». Довод верен и
сегодня, но **он про другую пару**: он развёл `year` с `_year`, а не два `_year`
между собой. Новый источник встал по ту же сторону, что и Steam, и второго
вердикта на этом месте нет.

**Какое объявление должно остаться:** одно, в `backend/sources/convert.py`, рядом
с `year` — это «кусок чужого ответа, который источники переводят одинаково», то
есть ровно ответственность этого модуля, и он уже держит парой соседей `year` и
`identifier` с тем же расхождением по способу. Имя должно называть способ, а не
предмет, иначе два `year` в одном модуле неразличимы: например `year_in_text`
против `year` («год из машинной даты» против «год, найденный в написанном
человеком»). Константа `YEAR` уезжает туда же; `steam/parse.py:_year` и
`oldgames/parse.py:_year` исчезают оба, докстринг Steam про «18 мая. 2015 г.»
переезжает к общей — он объясняет, почему поиск, а не срез, и нужен именно там.

### Minor

#### Minor-1. Пролог `_tried` повторяет `asked` на три строки из четырёх

- `backend/sources/undocumented.py:26-42` — `asked(http, url, params)`
- `backend/sources/oldgames/client.py:67-80` — `OldGamesClient._tried`

Совпадает тело цикла минус ветка `BUSY`:

```
response = await http.get(url, params=params)
if not isinstance(response, httpx.Response): return response
if response.status_code != 200: return refuse_undocumented(http, ...)
```

Почему не выше по серьёзности: свести это можно **только** параметром «а какой
код повторять», и он же будет всей разницей — тот самый признак, которым проект
отводит слияния (`merge_fields ≠ overwrite_fields`, `GENRE_TWIN ≠ SPELLING`,
`_payload ≠ _title` у GOG). Позвать `asked` как есть нельзя: он уже превратил бы
`503` в `refuse_code`, и достать код обратно можно было бы только разбором строки
`detail="HTTP 503"`. Ветка `BUSY` при этом стоит **между** двумя совпадающими
строками, то есть вынести можно было бы разве что первую пару строк — идиому
«пришёл готовый отказ», которая уже разобрана и оставлена как есть
(`not-duplicates.md:34`, десять мест в восьми файлах).

**Вердикт: разные.** Строка для `not-duplicates.md` — ниже.

#### Minor-2. Таблица «роль → откуда брать имя» стоит вторым местом

- `backend/sources/convert.py:50-60` — `companies(payload: dict)`
- `backend/sources/oldgames/parse.py:107-113` — `_companies(scope: Tag)`

Совпадает форма целиком: кортеж из двух пар `(CompanyRole.DEVELOPER, ...)`,
`(CompanyRole.PUBLISHER, ...)`, генератор, `Credit(name=name, role=role)`,
`tuple(...)`.

Различается то, что стоит вторым элементом пары и как из него достаётся имя: у
`convert.companies` это ключ JSON (`"developers"`, `"publishers"`), и имён по
ключу **много** — `for name in payload.get(key, [])`; у old-games это русская
подпись ячейки HTML (`"Разработчик"`, `"Издатель"`), и имя **одно** —
`if (name := _labelled(scope, label))`.

Свести можно было бы, передав в `convert.companies` функцию «по ключу верни
список имён», — то есть функцию высшего порядка ради шести строк, при том что
таблица подписей у HTML-источника всё равно осталась бы своей: русские подписи
страницы в `convert.py`, «куски чужого ответа, которые **все** источники
переводят одинаково», не переводятся ничем — они принадлежат одному сайту.

**Вердикт: разные.** Строка — ниже. Отмечу для полноты: `Credit` без `source` и
`source_id` собирают оба, и это одно и то же решение проекта («магазины отдают
студии голыми строками, таких склеивают по имени») — здесь оно верно и для
old-games.

#### Minor-3. `name` у клиента источника: седьмая копия без докстринга

- `backend/sources/oldgames/client.py:55-57`
- шесть остальных `*/client.py`, вердикт — `not-duplicates.md:83`

Вердикт «тело и докстринг совпадают дословно у всех пяти, и это общий интерфейс
клиента источника» остаётся верным: примесь ради одной инструкции по-прежнему

Что изменилось: **запись перечисляет пять клиентов, а копий теперь семь**

шестая копия — не «дословно та же», а тело без объяснения. Практического вреда
нет; вреда для записи есть: строка вердикта называет пути пяти сторон, и
отпечаток седьмой ею не покрыт — молча меняться она может.

**Что должно остаться:** сама запись, дополненная шестым путём
`backend/sources/oldgames/client.py:OldGamesClient.name`. Отдельно стоит решить,
нужен ли докстринг: у пяти он объясняет, кто ещё называет источник этим именем, и

#### Important-2. Три рукописных считающих транспорта там, где стоит готовый `counting(...)`

`tests/backend/sources/test_oldgames.py` **не импортирует из `tests/fakes.py`
и `tests/conftest.py` ничего** (импорты, строки 8–16: `asyncio`, `httpx`,

| место в новом файле | что написано руками | чем заменяется |
|---|---|---|
| `test_oldgames.py:251-257` | `asked=[]`, обработчик с `asked.append`, `Response(503, text=...)` | `counting(responding(503, text="<html>Service Unavailable</html>"))` |
| `test_oldgames.py:294-299` | `seen=[]`, обработчик с `seen.append`, `Response(200, text=fixture(...))` | `counting(replay("oldgames/search_dune.txt"))` |

Сторона-оригинал: `tests/fakes.py:138-153` — `counting(transport)`, и её

Почему важно:

1. Это **не первое появление, а двенадцатое-четырнадцатое**, и помощник против
   него уже заведён — то есть правило 3 нарушено не по незнанию формы, а мимо
   готового объявления. Соседние тесты того же пакета зовут его в точности так:
   `tests/backend/sources/test_steam.py:268` —
   `counting(responding(429, text="slow down"))`;
   `tests/backend/sources/test_kinopoisk_unofficial.py:125` —
   `counting(responding(429, text="<html>429</html>"))`;
   `tests/backend/sources/test_tmdb_people.py:100,110,123,139,162` —
   `counting(replay(...))`.
2. Два из трёх мест (`:294-299` и `:310-316`) — **дословные копии друг друга**
   внутри одного нового файла, различающиеся именем файла фикстуры. Машинная
   проверка дублей их не увидела: тела вложенных обработчиков в две инструкции.
3. Два из трёх при этом ещё и сочиняют ответ вместо записанного. У пакета есть
   `replay` (`tests/backend/sources/conftest.py:49-82`) с прямым доводом «код и
   заголовки берутся из записанного ответа, а не сочиняются»; здесь код `200`
   вписан руками рядом с телом из `fixture(...)`, у которого записанный
   `meta.json` тоже говорит `200`. Одно знание в двух местах, и разойтись им
   ничто не мешает.

**Какие объявления должны остаться:** `tests/fakes.py:counting` и
`responding`, `tests/backend/sources/conftest.py:replay` — все три уже есть и
менять их не нужно. Исчезают три рукописных обработчика в `test_oldgames.py`;
`fixture(...)` в двух местах уступает `replay(...)`, потому что проверяемое там
— ушедший запрос, а не тело ответа.

  `omdb/client`, обе половины Кинопоиска) и **`CATALOG` в двух** — общее слово в
  имени над собственным адресом каждого источника. Не повтор по правилам обхода.

## Готовые строки для `not-duplicates.md`

Для Important-1 и Important-2 строк нет намеренно: это повторы, а не разные пары,
и закрываются они выносом, а не вердиктом.

```
- `backend/sources/undocumented.py:asked` ≠ `backend/sources/oldgames/client.py:OldGamesClient._tried` — тело цикла повторяет `asked` на три строки: «не ответ — вернуть», «код не 200 — `refuse_undocumented`». Свести можно только доводом «какой код повторять», а он и есть вся разница: `503` у old-games — «занят сейчас», и `asked` превратил бы его в `refuse_code`, откуда код обратно достаётся разве что разбором строки `detail`. Ветка повтора стоит **между** двумя совпадающими строками, так что вынести можно было бы разве что идиому «пришёл готовый отказ», уже разобранную отдельно
- `backend/sources/convert.py:companies` ≠ `backend/sources/oldgames/parse.py:_companies` — форма общая: таблица из двух пар «роль → откуда брать», генератор, `Credit(name=name, role=role)`. Различает то, что стоит вторым элементом пары, и оно непереносимо: у магазинов это ключ JSON с **списком** имён, у old-games — русская подпись ячейки HTML с **одним** именем. Свести можно было бы функцией «по ключу верни список имён», то есть функцией высшего порядка ради шести строк, а таблица русских подписей всё равно осталась бы у своего источника: `convert.py` — про то, что все источники переводят одинаково, а подписи страницы принадлежат одному сайту
- `tests/backend/sources/test_oldgames.py:busy` ≠ `tests/backend/sources/test_steam_items.py:two_answers` — форма совпадает целиком: список `asked`, вложенный `handler` с `asked.append` первой строкой, развилка, возврат пары «транспорт и список». Различает признак развилки, и он же вся суть каждого: `two_answers` смотрит на адрес, потому что у Steam одна операция ходит в две ручки, `busy` — на порядковый номер запроса, потому что у old-games одна ручка отвечает сначала `503`, а потом страницей. Из общего `counting` не складывается ни тот, ни другой: счёт нужен **до** ответа, а `counting` считает после, оборачивая готовый транспорт
- `tests/backend/sources/test_oldgames.py:searched` ≠ `tests/backend/sources/test_steam_items.py:searched` — совпало имя и форма в четыре шага: собрать клиента на транспорте, спросить выдачу, закрыть, вернуть. Та же семья, что три `ask` строкой выше, и довод тот же — один глагол над разными предметами, общего конструктор в одну строку. Различие есть и оно осмысленное: у old-games закрытие стоит в `finally`, потому что его `search` уходит в повторы и в семафор
- `backend/sources/oldgames/parse.py:parse_search` ≠ `backend/sources/steam/parse.py:parse_search` ≠ `backend/sources/tmdb/parse.py:parse_search` — совпало имя, потому что поверхность разбора у всех источников зовётся одинаково; тот же довод, что записан для двух `parse_ratings`. Тела несводимы механически: на входе строка HTML, список JSON и словарь JSON с типом содержимого
- `backend/sources/oldgames/parse.py:parse_card` ≠ `backend/sources/steam/parse.py:parse_card` — то же имя поверхности, и сходство глубже: обе собирают `SourceCard` с `Item(id=0, kind=Kind.GAME, ...)` по одному набору полей, как и третьим местом `gog/parse.py:parse_catalog`. Общий тут **список полей**, а не код: вынести его значило бы передавать каждое поле доводом — довод, которым уже разведены `view_from_hit` с `view_from_item`
- `backend/sources/oldgames/parse.py:_hit` ≠ `backend/sources/tmdb/parse.py:_hits` ≠ `backend/sources/gog/parse.py:to_hit` — по сборщику кандидата на источник, и входы у них разного рода: строка таблицы HTML, список строк JSON и уже собранная `SourceCard` (у GOG поиск и карточка — один запрос). Третий при этом вообще о другом: он не разбирает чужой ответ, а переводит наш тип в наш
- `backend/sources/oldgames/parse.py:_cover` ≠ `backend/sources/steam/parse.py:_poster` ≠ `backend/sources/tmdb/parse.py:_poster` — третья сторона к паре, разобранной выше: `_cover` читает `og:image` из микроразметки и отбрасывает заглушку сайта по имени файла. Своей «обложки нет» не рисует больше ни один источник, так что отбрасывать эту заглушку некому и незачем
```

Плюс правка существующей строки, а не новая: запись про `name`
(`not-duplicates.md:83`) перечисляет пять путей, а копий тела теперь шесть —
