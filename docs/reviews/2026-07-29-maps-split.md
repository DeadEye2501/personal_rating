## Критические

### К1. Срок годности вердикта снимается обычной пересборкой карт

`scripts/not_duplicates.py:46`

```python
if place in index and follows != index[place]:
    line = line.replace(f"`{place}`", f"`{place}` `{index[place]}`", 1)
```

Условие клеймит не только непроставленное, но и **проставленное неверно** — то
есть ровно тот случай, ради которого отпечаток и заведён. Поэтому протухший
вердикт чинится не разбором пары, а командой пересборки.

Проверено насквозь. Меняем тело `backend/storage/tables/base.py:item_fk`
(`ondelete="CASCADE"` → `"RESTRICT"`), у которого есть вердикт:

```
--check                     → вердикты протухли: item_fk — тело изменилось   EXIT=1
python scripts/module_map.py → карты пересобраны: 53 модулей                 EXIT=0
--check                     → карты свежие, вердикты в силе                  EXIT=0
```

Строка после пересборки:

```
- `...:item_fk` `e5f1d089` `4cd3eea9` ≠ `...:genre_fk` `9df06746` — ...
```

Новый отпечаток встал перед старым, старый остался мусором, `--check` зелёный.
Пара, которую больше никто не разбирал, снова считается разобранной.

Вторая половина беды: **откат кода строку не чинит.** Вернули `item_fk` в
исходное состояние — `--check` красный навсегда (`follows` = `e5f1d089`, индекс =
`4cd3eea9`), а каждая следующая пересборка дописывает ещё один отпечаток:

```
`4cd3eea9` `e5f1d089` `4cd3eea9`
```

Выйти можно только правкой файла руками, о чём инструмент не сообщает.

Обещание, которое этим нарушено, записано в трёх местах:

- `SKILL.md:179-182` — «изменилось тело любой стороны... `--check` краснеет, и
  пара возвращается в разбор. Без этого вердикт глушил бы проверку ровно там,
  где она однажды сработала, — а это уже правило 12»;
- `scripts/not_duplicates.py:7-9` — то же своими словами;
- `docs/not-duplicates.md:7-10` — «**Отпечаток — срок годности вердикта**».

По формулировке самого скилла это и есть правило 12: отпечаток изображает
осознанное решение там, где никто ничего не проверял.

Починка — одно слово:

```python
if place in index and not follows:
```

Она же и есть поломка M1 ниже: **все восемнадцать тестов проходят молча** и с
нею, и без неё.

## Важные

### В1. Формат вердиктов не проверяется; три кривые строки из пяти приняты молча

Прогнано по `places`/`sealed`/`expired` напрямую, индекс
`{a.py:one, b.py:two, c.py:Cls.m}`.

| строка | что вышло |
|---|---|
| `- \`a.py:one\` \`b.py:two\`` (две ссылки подряд, причины нет) | обе заклеймены, вердикт без причины принят молча |
| `- \`a.py:one\` — причина` (одна сторона) | заклеймена, принята молча |
| `- \`a.py:one\` ≠ \`b.py:two\` — общее в \`c.py:Cls.m\`` | `c.py:Cls.m` стал **третьей стороной**, получил отпечаток и теперь гасит вердикт при изменении постороннего кода |
| `- \`nope.py:gone\` ≠ \`b.py:two\` — причина` (нет такого) | `--check` краснеет с верным сообщением — единственный правильно обработанный случай |
| лишняя обратная кавычка в конце строки | разобралось как правильная строка, вреда нет |

Третья строка прямо противоречит докстрингу `places` (`not_duplicates.py:29-31`):
«Прочие обратные кавычки в строке это имена внутри объяснения, и трогать их
нельзя». Отделяет их на самом деле не роль в строке, а случайность записи: у
примера в докстринге (`Repository._mapped`) нет пути, а в самом файле вердиктов
причины ссылаются на объявления **как раз** полными путями — см.
`docs/not-duplicates.md:18` (`_has_item`, `_read`) и `:27` (`Repository._mapped`).
Сегодня они спасаются только тем, что записаны без `.py`.

**Одна и та же сторона, названная в строке дважды, портит файл при каждой
сборке.** `sealed` считает `places` по исходной строке, а `replace(..., 1)` всегда
правит первое вхождение:

```
исходно:  - `a.py:one` ≠ `b.py:two` — см. `a.py:one`
сборка 1: - `a.py:one` `aaaaaaaa` `aaaaaaaa` ≠ `b.py:two` `bbbbbbbb` — см. `a.py:one`
сборка 2: - `a.py:one` `aaaaaaaa` `aaaaaaaa` `aaaaaaaa` ≠ ...
```

Строка растёт без предела, `--check` при этом остаётся красным. Это
единственный найденный ответ «да» на вопрос «портится ли файл при повторной
сборке»; на правильном файле сборка идемпотентна, md5 после двух прогонов тот же.

Общий вывод по формату: разбор **однозначен** (детерминирован и стабилен), но
**не проверен** — ни числа сторон, ни наличия `≠`, ни наличия причины никто не
требует. Что написали, то и заклеймили.

### В2. `seal` и `expired` смотрят на разные множества строк

`seal` клеймит только строки, начинающиеся с `- ` (`not_duplicates.py:55`);
`expired` в `--check` получает **все** строки файла
(`module_map.py:288` → `verdict_lines()`). Упоминание объявления в прозе файла —
не пунктом списка — роняет `--check` навсегда:

```
дописали в шапку файла: Образец разбора смотри в `scripts/not_duplicates.py:places`.

--check                      → протухло: places — тело изменилось   EXIT=1
python scripts/module_map.py → карты пересобраны                    EXIT=0
--check                      → протухло: places — тело изменилось   EXIT=1
```

Сообщение при этом врёт: тело не менялось. Выход — знать, что упоминание надо
убрать; инструмент об этом не говорит.

```
AssertionError: в backend не найдено ни одного файла
```

То есть **ревью по картам нельзя провести там, где ревью проводится**. Замечено и
раньше (`docs/reviews/2026-07-29-duplicates-cleanup.md:20`), обходится копией в
стороннюю папку. Долг прошлого, слайс его не ухудшил; лечится сравнением с
`path.relative_to(ROOT).parts`.

## Итог

Разделение по ответственностям удалось: `project_ast.py` и `not_duplicates.py`
описываются одной фразой каждый, `module_map.py` ужался вдвое, все девять
поломок рисования карт `--check` ловит. Плоский импорт — честное решение с
названной причиной, хотя названа она в скилле, а не в проекте, и цена его
(слепая колонка «Зависит от») нигде не записана.

Новая механика вердиктов, наоборот, не работает как обещано: **отпечаток не
является сроком годности**, потому что пересборка карт снимает его молча, а
испорченную строку не чинит и откат кода. Ни один тест этого не видит, и путь
записи вердиктов не покрыт ничем. Пока К1 и К2 не починены, файл вердиктов
опаснее своего отсутствия — ровно по тому основанию, которое в нём самом и
записано.
