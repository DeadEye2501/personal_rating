# Ревью задачи 2 плана `2026-08-22-books-and-music.md` — «Два типа насквозь»

Измерение: настоящие поломки поведения в рабочем дереве (незакоммиченный диф).
Диапазона коммитов нет, смотрел `git diff` целиком по перечисленным файлам.

## Что сделано хорошо

- `backend/sources/registry.py`: таблица `ROUTES` без умолчания — `ROUTES[kind]`
  роняет `KeyError` на неизвестном типе, ровно то поведение, ради которого
  слайс затевался. Порядок каталожных клиентов игр (`steam, gog, old_games`)
  сохранён один в один со старым `[self.steam, self.gog, self.old_games]`.
  `people_for` возвращает тот же объект-клиент через `getattr`, тождество (`is`)
  не страдает — сервис `Filmographies` по-прежнему сравнивает верно.
- Проверил, что `people` не бывает пустой строкой ни в одной строке `ROUTES`
  (только `str | None`); код `getattr(self, name) if name else None` устойчив и
  к гипотетической пустой строке — не упал бы попыткой `getattr(self, "")`.
- Три охранника `is not Kind.GAME` / `is Kind.GAME` в `service/loading.py`,
  `service/merging.py`, `service/relevance.py` намеренно не тронуты и корректно
  ведут себя для книг и музыки: у них нет каталожных клиентов, выдача пуста,
  раскладка имён по письменности и склейка изданий книгам/музыке не достаются
  — план это прямо запрещает, и не потрогано ничего лишнего.
- Сквозная проверка `client/state/card.js`: `OWN.book = ['author']`,
  `OWN.music = ['performer']` и `emptyCard` синхронно получили `author: []`,
  `performer: []`. Тест `tests/web/card.test.js` («у каждого показанного поля
  есть свой ключ, и он пуст») гоняет это на реальном `KINDS` со всеми пятью
  типами и ловит именно расхождение `OWN`/`emptyCard`, которого опасался
  постановщик задания — расхождения нет.
- `client/state/credits.js`: `author` и `performer` оба `domain: 'people'`,
  что и требуется («автор и исполнитель — люди, не студии»); контрактный тест
  `test_the_card_asks_the_right_two_shelves` в `tests/bridge/test_page_contract.py`
  сверяет привязку роль→полка по `PersonRole`/`CompanyRole`, а не по списку
  имён, и он корректно ловит расхождение.
- `client/app/App.svelte`: `ACCENTS` не даёт значения фильмам (умолчание из
  палитры), для `book`/`music` — токены `var(--accent-book)`/`var(--accent-music)`,
  использование в `$effect` (строка ~177) через `ACCENTS[session.kind]` с
  фоллбеком `removeProperty` на `undefined` — верно и для новых типов.
- Проверил связку тестов границы: `test_the_page_offers_exactly_the_kinds_the_backend_knows`,
  `test_the_page_maps_every_kind_to_a_genre_set_the_base_has`,
  `test_the_page_has_a_word_form_for_every_kind` — все три действительно
  вычисляют ожидаемое из `Kind`/`GenreKind`, а не переписывают список руками, и
  корректно проверяют новые пять типов (перепроверено вручную построчным
  разбором regex и множеств).
- Отклонения от плана все три подтверждены как заявлено и без побочных эффектов:
  - шаг 7 (капсула на две кнопки) действительно закрыт задачей 1 — `seg.css`
    прямо документирует, что ширина 338px замерена на пяти вкладках заранее, и
    `bridge/window.py`/`seg.css`/`topbar.css` в этом дифе не тронуты;
  - `result.views == ()` в новом тесте `test_a_book_is_searched_only_in_our_own_base`
    соответствует реальному типу поля — `ExternalSearch.views: tuple[CardView, ...]`,
    и в сервисе оно всегда собирается через `tuple(...)`;
  - второе утверждение `client.asked == []` действительно нужно и действительно
    работает: прошёл по цепочке `SearchService.external` → `Sources.catalog_for` →
    (для книг) `Filmographies.of_name` → `Sources.people_for`, оба возвращают
    пустое/`None` для `Kind.BOOK`, `client.search` и `client.find_people`
    не зовутся ни разу.
- `tests/fakes.py`: `FakeSources.NOBODY` — самостоятельный дубль правила
  `ROUTES` для книг/музыки, но это осознанный дубль тестового двойника (сам
  реестр проверяется отдельно в `test_registry.py`), а не источник истины —
  поведение сервиса и поведение реестра проверяются раздельно, как и раньше с
  играми.
