## Находки

### 1. Никто не сторожит, чем именно становится `synced_at` — три молчания

Молчат мутации 05, 22 и 35. Самая опасная — **35**:

```python
fields.setdefault("synced_at", datetime.now)   # скобки потеряны
```

В карточке вместо момента оказывается объект функции. Все 13 тестов слайса
зелёные; **весь набор из 218 тестов тоже зелёный**. В работе такая карточка
ляжет в базу мусором или упадёт на вставке.

Причина одна на три мутации: тест `test_a_manual_card_knows_when_it_was_made`
проверяет `item.synced_at is not None` — слабейшее из возможных утверждений, а
имя обещает «карточка знает, когда её завели». Ни один тест не проверяет:

- что **переданный** `synced_at` доезжает до карточки — хотя двенадцать тестов
  из тринадцати передают `synced_at=WHEN` и молча на это опираются
  (`test_given_fields_reach_the_card` сторожит `year` и `seasons_count`, но не
  единственное поле с особой обработкой);
- что **подставленный** `synced_at` — это сейчас, а не что попало.

Чем закрыть (обе проверки прогнаны, ловят 05, 22 и 35):

```python
def test_passed_synced_at_actually_reaches_the_card():
    assert new_manual_item(Kind.MOVIE, "Одиссея", synced_at=WHEN).synced_at == WHEN


def test_default_synced_at_is_now():
    before = datetime.now()
    item = new_manual_item(Kind.MOVIE, "Одиссея")
    assert before <= item.synced_at <= datetime.now()
```

### 2. Новый номер при отвязке не обязан быть номером — два молчания

Молчат 31 (uuid обрезан до одного знака) и 40 (`source_id = str(item_id)`).
Спека говорит прямо: `source_id` — случайный `uuid4` строкой. Тесты требуют от
него только двух вещей: не равен прежнему внешнему и у двух карточек разный.
Обоим требованиям удовлетворяет порядковый номер карточки — а он **предсказуем и
конечен**: заведи вручную карточку с `source_id = "3"` (а руками её и заводят),
и отвязка третьей карточки упрётся в `uq_item_source`.

Тест `test_unlink_gives_a_fresh_identity_to_each_card` берёт две карточки, и на
обрезанном до одного знака uuid он зеленеет в пятнадцати случаях из шестнадцати
— то есть сторожит столкновение почти вслепую.

Чем закрыть (прогнано, ловит 31 и 40):

```python
async def test_unlinked_identity_is_a_uuid(sessions):
    library = LibraryRepository(sessions)
    item_id = await library.create(new_manual_item(Kind.MOVIE, "мой", synced_at=WHEN))
    await library.link(item_id, Source.TMDB, "157336")
    await library.unlink(item_id)
    assert len((await library.get(item_id)).source_id) == 36
```

### 3. `link` — единственная запись в проекте, которая читает часы сама

`LibraryRepository.refresh_series_counts` в том же классе, той же таблице и той
же колонке `synced_at` принимает `now: datetime` параметром. Так же устроены
`RatingsRepository.set_score` и `.set_aspects`, `WishlistRepository.add`,
`PosterStore.put`. `link` вместо этого зовёт `datetime.now()` внутри.

Тест это уже оплатил — первым делом в файле стоит:

```python
# Нарочно в прошлом, а не общий `MOMENT` из conftest: привязка ставит время
# заново через `datetime.now()`, и с датой из будущего проверка бы не сошлась.
WHEN = datetime(2026, 1, 15, 12, 0)
```

То есть тесту пришлось подстроить свои данные под жёстко зашитые часы, и
проверить «поставилось именно это время» он уже не может — только «стало больше
прежнего». Мутация 12 (`synced_at = datetime(2000, 1, 1)`) поймана лишь потому,
что 2000 год меньше `WHEN`; поставь мутация 2027 год — прошла бы молча.

Предложение: `link(item_id, source, source_id, now: datetime)`, как у соседей.
Плану это не противоречит по существу — в нём зафиксировано «`link` ставит
`synced_at` заново», а не откуда берётся момент.

### 4. `str(uuid4())` написан дважды в двух слоях

`backend/model/item.py:39` и `backend/storage/repository/library.py:199`. Правило
«ручная идентичность — это случайный uuid строкой» живёт в двух местах разных
слоёв: поменяется оно (префикс, формат) — чинить придётся оба, и второе легко
не заметить. Машинная проверка дублей сюда не смотрит: выражение короче пяти
инструкций.

По CLAUDE.md — «общее выносится сразу, а не когда заметим третий дубль». Это
второе появление.

### 5. `test_only_the_title_is_required` читает объявление, а не поведение

```python
def test_only_the_title_is_required():
    item = new_manual_item(Kind.MOVIE, "Одиссея", synced_at=WHEN)
    assert item.year is None
    assert item.synopsis == ""
```

Проверяются значения по умолчанию у `dataclass` — то есть объявление
пересказывается само себе. Обещание спеки («Обязательно только название») —
про другое: такая карточка должна **доехать до базы**. Ни один тест слайса не
создаёт карточку без `synced_at` и без прочих полей — отчего мутация 35 и
прошла молча по всему набору.

Чем закрыть (прогнано, ловит 35):

```python
async def test_a_card_with_nothing_but_a_title_lands(sessions):
    library = LibraryRepository(sessions)
    item_id = await library.create(new_manual_item(Kind.MOVIE, "Одиссея"))
    assert (await library.get(item_id)).title == "Одиссея"
```

### 6. Мелочи

- **Мутация 29**: `raise ItemExists(...) from None` вместо `from error` проходит
  молча — цепочка причин ничем не сторожится. Ценность проверки невелика, пишу
  для полноты.
- **Мутация 21** (`id=0` → `id=99`) молчит **по устройству, а не по недосмотру**:
  `_values` не берёт `id`, его выдаёт база. Это не дыра в тестах.
- **`link` по несуществующей карточке молча ничего не делает** — ни ошибки, ни
  признака. Проверено отдельно. Для нынешнего вызывающего (окно карточки, у
  которого карточка на руках) допустимо; отмечаю как известное поведение, не
  как дефект.

## Офлайн-обещание — главный вопрос слайса

Прогнан отдельный сценарий: ручная карточка проживает полную жизнь без единого
внешнего идентификатора и без единого обращения к сети.

Завести (`new_manual_item` + `create`) → оценить (`RatingsRepository`) → повесить
тег (`TagsRepository.create` + `.assign`) → положить в закладки
(`WishlistRepository.add`) → залить постер (`PosterStore.put`) → отредактировать
(`replace_fields`) → показать состав удаления (`deletion_summary`) → удалить
(`delete` вместе с постером). **Всё зелёное.**

Ни один из этих путей не спрашивает `source`, `source_id` или что-либо из
внешнего мира: все они ключуются по `item.id`. `PosterStore` тоже — ключ
`item_id`, адреса картинки не нужно. Отдельно проверено:

- карточка с одним лишь названием доезжает до базы;
- перепривязка с одного внешнего номера на другой работает;
- освобождённый отвязкой внешний номер может занять другая карточка.

Мест, где офлайн-обещание не держится, не найдено.
