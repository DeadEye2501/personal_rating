# Ревью среза 03: оснастка процесса

Предмет — незакоммиченный слайс: новый `scripts/module_map.py` (67 строк),
однострочные докстринги ответственности у восьми модулей `backend/`, снятый
докстринг класса `Credit`. Линза — манифест `keeping-code-clean`, в первую
очередь те пять правил, которых машина не проверяет.

Проверка начата не с диффа, а с запуска самого инструмента:

```
pipenv run python scripts/module_map.py
```

Он и оценивается: карта — это заявка на то, что ревью следующего слайса можно
вести по ней вместо чтения всего кода. Ниже — годится ли она для этого.

Прогоны: `pipenv run pytest -q` → **39 passed in 0.45s**.
`pipenv run python scripts/genre_map.py` → **сходятся: 296 строк genre_map**.
Оба совпали с ожиданием, регрессий слайс не внёс.

Находок: **4 блокирующих, 3 важных, 5 мелких.**

---

## 1. Блокирующее

### Б1. Карта пропускает `__init__.py` — и вместе с ним всю объявленную поверхность пакета

`scripts/module_map.py:39` — `path.name == "__init__.py"` отбрасывается вместе с
`__pycache__`, без оговорок.

`backend/model/__init__.py` — не пустышка: 31 строка, четырнадцать реэкспортов и
явный `__all__`. Это и есть публичное лицо пакета. Больше того — по
`tests/backend/test_layers.py:18` (`ALLOWED_FROM_BACKEND = {"backend.model",
"backend.config"}`) `backend.model` — единственное, что клиенту вообще разрешено
импортировать из бэкенда. То есть карта прячет ровно тот файл, который отвечает
на вопрос из её же первой строки: «что из него торчит наружу»
(`scripts/module_map.py:1`).

Рецензент следующего слайса, читающий карту, увидит восемь отдельных модулей и
ни одного фасада — и не заметит, если новый тип границы забудут добавить в
`__all__`.

Пустые `__init__.py` (`backend/`, `backend/storage/`, `client/` — 0 байт,
проверено) шуметь не должны, но отбор должен идти по содержимому, а не по имени
файла.

### Б2. Отсутствующий пакет печатается как «0 модулей»

`scripts/module_map.py:36-42`. `rglob` по несуществующей папке отдаёт пустоту, а
не исключение. Проверено:

```
>>> module_map.modules('nope')
[]
```

В сегодняшней выдаче есть строка `## client — 0 модулей`. Прочитать её можно
тремя способами: пакет пуст, пакета нет, маска сломалась. Различить их по выводу
нельзя.

Это не гипотеза — это уже пройденная в проекте ошибка. Соседний обходчик
`tests/backend/test_layers.py:39-45` делает тот же обход и несёт в докстринге
записанный урок:

> Пустой ответ — это поломка проверки, а не чистый пакет: и отсутствующая папка,
> и сломанная маска отдают пустоту, а не исключение.

— и защищается двумя `assert`. Новый код обошёл то же дерево, не забрав из
соседа ни защиты, ни знания. Правило 1 нарушено не буквой (совпадает две
строки), а сутью: готовое было, его не посмотрели.

### Б3. `backend/model/external.py:1` — «и» в докстринге, и оно честное

> «Чужие идентификаторы карточки **и** чужие оценки.»

Правило 6 названо буквально про этот случай. В модуле два несвязанных
дата-класса: `ExternalId` (идентичность в чужой базе, строка) и
`ExternalRating` (измерение с отметкой времени, `float | None` + `fetched_at`).
Общего у них — только слово «чужой».

Это не описание, а перечисление содержимого. Резать 19-строчный файл на два
восьмистрочных — хуже, чем оставить; чинить надо формулировку: назвать то одно,
чем оба являются («что карточка знает о себе в чужих базах»). Пока фраза
собрана через «и», она не отвечает на правило 6 — она от него уклоняется.

### Б4. `backend/model/kinds.py:1` — ответственность названа механизмом и указывает не на ту сторону границы

> «Перечисления, которые ложатся в базу текстом.»

Два отдельных изъяна.

**Шире, чем модуль делает.** Фраза описывает не работу, а форму хранения:
`StrEnum`, ложится текстом. Проверка на широту простая — подставить чужое:
`LogLevel(StrEnum)` попадает под это определение целиком, а в модели данных ему
не место. Определение, под которое лезет что угодно того же технического вида,
ответственность не называет. Внутри — семь перечислений трёх разных сортов: тип
содержимого (`Kind`), источники (`Source`, `IdSource`, `RatingSource`), роли
(`PersonRole`, `CompanyRole`), плюс `GenreKind`. Файл на 58 строк резать не
нужно, но описать его надо по предмету — это закрытые словари модели, — а не по
типу базового класса.

**Смотрит не в ту сторону.** Соседи по пакету пишут «на границе слоёв»
(`backend/model/genre.py:1`, `backend/model/item.py:1`), и это подтверждено
тестом слоёв: `backend.model` — то, что разрешено импортировать клиенту
(`tests/backend/test_layers.py:18`). А `kinds.py` описывает себя тем, что
делает **в базе** — то есть той стороной, которую клиент видеть не должен
вовсе. В одном пакете две несовместимые версии того, зачем пакет нужен. Для
слайса, весь смысл которого — «докстринг и есть ответ на правило 6», это
блокирующее: следующий рецензент будет сверяться с враньём.

## 2. Важное

### В1. `backend/storage/session.py:1` — ответственность названа у́же модуля

> «Подключение к основной базе.»

Кроме движка и фабрики сессий модуль владеет правилом сравнения названий:
`fold` (`backend/storage/session.py:14-18`). Его собственный докстринг говорит
прямо — «сравниваем обе стороны одними правилами», то есть функция задумана
как импортируемая тем, кто строит запросы. Она уже импортируется наружу:
`tests/backend/test_session.py:5`.

Правила сравнения текста — не «подключение». Сегодня это терпимо, потому что
`fold` регистрируется в обработчике `connect`; в тот момент, когда первый
репозиторий импортирует `fold`, чтобы свернуть питонью сторону сравнения,
расхождение станет структурным: модуль подключения окажется в зависимостях у
слоя запросов.

Отдельно: слово «основной» выбрано верно и намеренно — вторая база есть
(`posters.db`, `backend/config.py:25`).

### В2. `backend/model/rating.py:1` — «и», и оно тоже честное

> «Своя оценка **и** пересчёт средней по шкалам.»

Здесь «и» не оговорка: `average_score` (`backend/model/rating.py:6`) и класс
`Rating` (там же:16) в коде между собой не связаны — `Rating.score` приходит
готовым, функция его не считает. Два публичных имени, две независимые вещи в
одном файле. Либо описание сворачивается в одну фразу, либо функция становится
тем, чем `score` делается, и тогда фраза схлопывается сама.

Не блокирующее: связь между ними по предмету очевидна, в отличие от
`external.py`.

### В3. Скрипт — наполовину сторож, наполовину отчёт

`scripts/module_map.py:52-66`. `main` всегда возвращает `0`, включая случай
`unnamed > 0` (строка 62), но при этом объявлен как `-> int` и завёрнут в
`sys.exit(main())` (строка 66) — точная копия скелета из
`scripts/genre_map.py:70-85`, где `return 1` реален и означает расхождение
спеки с планом. Здесь падающего пути нет ни одного.

Определиться надо: либо модуль без докстринга — это красная проверка (тогда
`return 1`, и правило 12 работает), либо это отчёт (тогда `-> int` и `sys.exit`
не нужны). Сейчас скопирована оболочка, у которой вынули содержимое.

Смежное с правилом 8: `MISSING` (строка 18) и счётчик `unnamed` (строки 53,
59-61) сегодня не срабатывают ни разу — все восемь модулей с докстрингами.
Формально это «на всякий случай», по сути — заготовка ровно под следующий
слайс, который модули добавит. Оставить можно; но если ветка так и не начнёт
ничего менять в поведении (см. выше про всегда-ноль), она останется мёртвой.

## 3. Дублирование: что общего с уже существующим

Проверялись `scripts/genre_map.py`, `scripts/collect_game_genres.py` и
`tests/backend/test_layers.py`. Совпадения есть, все — мелкие:

| Кусок | Где | Копий |
|---|---|---|
| `ROOT = Path(__file__).resolve().parents[N]` | `module_map.py:15`, `genre_map.py:14`, `test_layers.py:4` | 3 |
| `ast.parse(path.read_text(encoding="utf-8"))` | `module_map.py:41`, `test_layers.py:23` | 2 |
| `sorted((ROOT / package).rglob("*.py"))` | `module_map.py:38`, `test_layers.py:43` | 2 |
| скелет `main() -> int` + `sys.exit(main())` | `module_map.py:52-66`, `genre_map.py:70-85` | 2 |

С `collect_game_genres.py` пересечений нет — другой предмет (сеть), общего кода
ноль.

**Выносить не надо, и вот почему.** `scripts/` — не пакет: `scripts/__init__.py`
отсутствует (проверено), импортировать оттуда нельзя без правки `sys.path`.
Значит, вынос общего даёт один из двух исходов:

- тест слоёв импортирует из папки временных скриптов — и его зелёный цвет
  начинает зависеть от инструмента, который по плану чистки должен исчезнуть
  после слайса;
- общий обходчик заводится в `backend/` — но `test_layers.py` проверяет
  **сам** `backend/`, и проверка, живущая внутри проверяемого, перестаёт быть
  проверкой.

Оба хуже дубля в две строки. Плюс куски расходятся именно в том месте, ради
которого пишутся: `module_map` отбрасывает `__init__.py` и `__pycache__` и не
падает на пустоте, `test_layers` берёт всё подряд и на пустоте падает намеренно.
Правило 3 говорит про второй **похожий** кусок; здесь совпадает идиома, а не
поведение.

Забрать из соседа следовало не код, а урок — и это Б2.

## 5. Годится ли карта как инструмент

Сначала по факту: **разделы 1 и 2 этого отчёта найдены по карте, а не по
диффу.** Восемь ответственностей, выписанных в столбик, — это то, на чём видно,
что `external.py` перечисляет вместо того, чтобы описывать, а `kinds.py`
рассказывает о себе не ту историю, что соседи по пакету. По диффу, где каждая
строка приходит поодиночке, ни то ни другое не заметно. Форма выбрана верно.

Два правила из трёх заявленных обслужены:

- **«место выбирается до первой строки»** — путь плюс фраза ответственности по
  всему дереву на восьми строках вывода. Вопрос «какой существующий модуль уже
  этим занят» закрывается, не открывая файлов. Работает.
- **«одна ответственность на модуль»** — работает, см. выше.

**Третье не обслужено вовсе.** Докстринг обещает «абстракция появляется со
второй реализацией» (`scripts/module_map.py:5`), а в выводе нет ничего, по чему
об абстракции можно судить: ни базовых классов, ни `Protocol`/`ABC`, ни числа
наследников. «Базовый класс с единственным наследником» — запрет, ради которого
правило 7 и написано, — в этой карте невидим полностью. Либо печатать основания
классов и счёт наследников на каждое основание, либо убрать обещание из
докстринга. Стоит это одного обращения к `ast.ClassDef.bases`, а понадобится
ровно на плане источников: шесть клиентов шести источников — это самое место,
где базовый класс заводят раньше времени.

Чего не хватает ещё, по убыванию цены:

1. **Реэкспорты `__init__.py`** — Б1.
2. **Импорты между своими модулями.** Вопрос, который рецензент следующего
   слайса задаст первым, звучит не «что этот модуль делает», а «почему новое
   лежит под `storage/`, а не под `sources/`» — и отвечает на него то, кто кого
   импортирует. Сейчас карта показывает восемь островов без единой связи между
   ними. Обходчик для этого уже написан: `imported_modules`,
   `tests/backend/test_layers.py:21-30`.
3. **`tests/` в карте нет.** `PACKAGES` (`scripts/module_map.py:16`) — два
   имени. «Место для кода» распространяется и на тесты: `tests/backend/` — это
   четыре файла, невидимых в карте, и следующий слайс добавит ещё. Рецензент,
   который по карте решает, где место новому, про половину дерева не узнает.
4. **Отметки размера** — М5.

**Лишнего в выводе нет.** Четыре поля на модуль, ни одного декоративного. Пустой
ход один — код возврата, который всегда ноль (В3).

**Вердикт: инструмент годится и его надо оставить** — он окупился на этом же
ревью. Но перед следующим слайсом обязательны Б1 и Б2: пока карта молча прячет
`__init__.py` и молча же печатает «0 модулей» вместо «пакета нет», ей нельзя
верить в единственном режиме, ради которого она заведена, — читать её **вместо**
кода. Основания классов добавлять тогда, когда приедет первый слайс с шестью
клиентами; до тех пор строку про правило 7 из докстринга лучше убрать, чем
держать невыполненной.
