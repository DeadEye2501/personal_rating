# Ревью плана 5: полнота относительно спеки и сборка с нуля

Дата: 01.08.2026. Диапазон: `be53348..HEAD` (11 коммитов). Рецензент — одно
измерение: полнота в обе стороны и подъём из чистого клона.

Что проверено живьём, а не по чтению:

- весь набор в рабочем репозитории — **1219 тестов зелёные** (53.96 с);
- `module_map.py --check` — выход `0`, обе карты и отпечатки `not-duplicates.md`

## Полнота: чего не хватает

**Ничего из того, что спека требует от питоновской половины, не пропущено.**
Пройдено по разделам спеки `docs/specs/2026-07-31-client.md`:

| Требование спеки | Где выполнено |
|---|---|
| Семь доменов, домен на файл | `bridge/{library,marks,refs,feed,search,world,covers}.py` |
| Восьмой группы (жизненный цикл) на мосту нет | `aclose` зовёт `open_window` через `thread.close()` |
| `posters.poster_for` не в мосте | зовётся только из `bridge/serve.py` |
| Одна дверь, только простые данные | `wire.to_wire`, отказ громкий на неизвестном типе |
| Только запрос-ответ, канала событий нет | у моста нет ни одного пути от бэкенда к странице |
| Отмена настоящая | `BackendThread.cancel` → `task.cancel()`, `Api.cancel` |
| Срок на операцию держит мост | `DEADLINE = 60.0`, `Domain._reply` |
| Номер операции у отменяемого | `search`, `world`, `feed` |
| Пять родов непролезающих значений | `to_wire` (даты, `timedelta`, датаклассы, байты — отказом) и `outcome()` (метка типа) |
| Что не пролезает обратно — мост помнит | `Kept` в `Search` и в `World`, по одному значению |
| Время подставляет мост | семь мест: `marks` ×4, `covers.store_upload`, `world.link`, `serve._fetched` |
| Отказ операции — один формат | `Denied` → `kebab(имя класса)`, шестой род `stale` |
| Отказ источника — поле в ответе | `outcome()`, `ExternalSearch.refusals` |
| Обложки мимо моста, своей ручкой | `Page._poster`, `<img src="/poster?item=…">` |
| Своё WSGI-приложение, а не файловый сервер | `Page`, отдаётся окну через `url=` |
| Тип для `.woff2` объявлен сам | `serve.TYPES` |
| У кандидата поиска обложка не сохраняется | `_fetched` с `item is None` → `poster_for(None, …)` |
| Рендерер проверяется после запуска | `window._check_renderer` |
| Окно с системной рамкой, минимум по ширине | `window.MIN_WIDTH/MIN_HEIGHT` |
| Проверки моста идут обычным `pytest` | `tests/bridge/`, 13 модулей |
| Имена, которые мост зовёт, сторожит отдельная проверка | `test_bridge_surface.py`, 40 вызовов разбором исходников |

**Отложенное — всё названо в самом плане и лежит с потребителем:**
`Search.by_person` (план 11), `Refs.items_of` (не заводится вовсе, потребителя
не осталось), `sys._MEIPASS` и один `.exe` (план 10), `genres.set_for_item`,
`people.attach`, `people.ensure` (план 9), точная минимальная ширина окна по
замеру шапки (план 6). Ни одно из отложенного спека от **этого** плана не
требовала.

## Полнота: что сделано сверх спеки

Пять мест, и четыре из них объяснены планом.

1. **`World.open(url)` — открытие страницы источника системным браузером.**
   В таблице доменов спеки его нет: «внешний мир» перечислен как
   `loader.card_for_link`, `linker`, `series`, `enricher`, `parse_link`.
   Требует его решение из `CLAUDE.md` («Ссылка на страницу источника…
   открывает системный браузер через мост»), и план объявляет его в
   «Интерфейсах» задачи 9. **Объяснено, но таблица спеки не дополнена.**

2. **`BadLink` и `ForeignScheme` — свои наследники `Denied` в `bridge/world.py`.**
   План писал голый `Denied(f"чужая схема адреса: {url}")`; в коде это два
   класса, и род отказа у них выходит `bad-link` и `foreign-scheme`. Правка
   к лучшему (плашка называет причину), обоснована докстрингами. Но это **два
   рода отказа, которых не называет ни спека, ни план**, а разметке плана 6 их
   различать.

3. **`_opened` уходит в `asyncio.to_thread`.** В плане (строка 2822) —
   прямой `webbrowser.open(url)`. Довод в коде записан и он верный:
   при заданной `BROWSER` библиотека берёт `GenericBrowser` и ждёт закрытия
   браузера, то есть заморозила бы весь цикл бэкенда. Правка к лучшему,
   в плане не отражена.

4. **Разбор доводов уехал внутрь заявки в трёх местах** (`library._manual`,
   `feed._feed`, `world._link`) — относительно текста плана это изменение
   структуры; записано в `CLAUDE.md` как главная находка ревью слайсов.

5. **`serve.py`: `MAGIC`, `Cache-Control: max-age=86400`, `403` на выход за
   корень, `400` на нечисловой номер** — всё это есть в тексте задачи 11,
   сверх спеки, но с доводами; условие про кеш перезалитой обложки записано
   в `docs/deferred.md`.

Лишнего в репозитории нет: временных скриптов, черновиков, заглушки из задачи 12
и артефактов сборки не осталось, `git status` чист.

## Сборка с нуля

Клон делался в папку вне репозитория, из неё же и проверялось.

**Что приезжает в клон.** 542 файла: `backend` 77, `bridge` 14, `tests` 172,
`docs` 269, `migrations` 4, `scripts` 2, `main.py`, `Pipfile`, `Pipfile.lock`,
`alembic.ini`, `pytest.ini`, `.env.example`, `.gitignore`, `CLAUDE.md`.
**Ничего лишнего:** ни базы, ни лога, ни `client/dist`, ни `*.exe`, ни `*.spec`,
ни временных файлов. Папки `client/` в клоне нет вовсе — она пуста, а пустые
папки git не носит; это ожидаемо, её заводит план 6.

**Схема поднимается миграциями и ключей не требует.** Проверено запуском в
клоне с вычищенным окружением (все `*_API_KEY` и `DATA_DIR` сняты):
`alembic upgrade head` прошёл обе ревизии и завёл `data/library.db` —
**15 таблиц** (14 своих плюс `alembic_version`), **47 жанров**, **326
соответствий**. Папку `data/` заводит сам `migrations/env.py`.

**Приложение поднимается на пустых ключах.** Собран `build_backend`, поднят
`BackendThread`, собран `Api`, отвечено шестью доменами:

```
feed.page       → {"ok": []}
marks.tags      → {"ok": []}
refs.genres     → {"ok": [ … 47 жанров … ]}
world.parse     → {"ok": {"source": "tmdb", "source_id": "550", "kind": "movie"}}
search.local    → {"ok": []}
search.external → {"ok": {"views": [],
                          "refusals": [{"source": "tmdb", "reason": "key",
                                        "retry_after": null, "detail": ""}]}}
```

То есть **о пустом ключе приложение говорит внятно**: не падением и не
молчанием, а отказом источника с причиной `key`, а это ровно та причина, по
которой плашка снизу скажет своё. Обязательный ключ ровно один — `TMDB_API_KEY`
(без него нет фильмов и сериалов); Steam и GOG не требуют ключа вовсе, а три
оценочных источника помечены в `.env.example` как опциональные. `.env.example`
покрывает все семь переменных, которые читает код (`DATA_DIR`, `LOG_LEVEL`,
пять ключей) плюс `PR_DEBUG` из `main.py` — расхождений нет.

**Без миграций приложение не молчит.** С чистым `DATA_DIR` первый же запрос
даёт `{"fail": "broken", "detail": "(sqlite3.OperationalError) no such table:
item …"}` и запись в лог — ровно то, что обещает `CLAUDE.md`.

**Закрытие чистое:** `thread.close()` отработал и вернулся.

**Чего в «Окружении» не хватает** — см. находки 6, 10 и 12 ниже.

## Находки

### Critical (обязательно к правке)

Нет.

### Important (следует поправить)

**1. Цвет окна до отрисовки не из макета, хотя план утверждает обратное.**

`bridge/window.py:42` — `background_color="#0d0d0d"`. В макете такого цвета нет
нигде: `docs/design/styles/tokens.css:21` объявляет `--bg: #0a0a0a`, и `#0d0d0d`
не встречается ни в одном файле `docs/design/`. План (строка 3607) пишет: «Пока
стоит значение из макета» — это неверно.

Почему важно: это единственный цвет, который виден до появления страницы, и
несовпадение даст вспышку при каждом запуске, когда палитра плана 6 встанет на
`#0a0a0a`. Правило проекта — «макет источник истины», «переносить точь-в-точь»,
и придуманный самому себе цвет под него не подпадает.

Как чинить: `background_color="#0a0a0a"` и поправить фразу в плане.

**2. Таблица «кто с номером» не сходится с кодом поимённо: `world`.**

`docs/plans/2026-07-31-window-and-bridge.md:136` — строка `| world | все | — |`.
В коде номер несут пять методов из семи: `card_for_link`, `link`,
`refresh_series`, `enrich`, `expected`. **`parse` и `open` идут без номера**
(`bridge/world.py:34` и `:82`), и это правильно — ни разбор регуляркой, ни
запуск браузера отменять нечем, а `Domain._reply` на `op=None` гасить ничего и
не пытается.

Почему важно: таблица объявлена в плане как «таблица, а не догадка по
сигнатурам», и обёртка моста в плане 6 будет писаться по ней. Прочитанная
буквально, она заставит страницу заводить номер там, где его не берут.

Как чинить: `| world | всё, что ходит в сеть | parse, open |`.

**3. В той же таблице стоит `search.by_person`, которого нет.**

Строка 136 перечисляет `local`, `external`, `ensure`, **`by_person`**. В
`bridge/search.py` его нет, и это осознанно: самопроверка того же плана
(строка 3734) говорит «Нет `Search.by_person` … Первый заводит план 11 вместе
со своим потребителем». Две части одного документа противоречат друг другу.

Как чинить: пометить `by_person` в таблице как приходящий с планом 11 либо
убрать из неё до тех пор.

**4. Спека отстала от решения пользователя: у ленты нет номера операции.**

`docs/specs/2026-07-31-client.md`, раздел «Направление»: «Его несут операции,
которые есть чем отменить, — **поиск и внешний мир**». Лента не названа. При
этом решение пользователя от 31.07.2026 записано в `CLAUDE.md` («Номер несут
поиск, внешний мир и лента»), план на нём стоит (решение 2), и код ему следует —
все три метода `FeedBridge` принимают `op`.

Почему важно: план утверждает «Спека клиента приведена к ним в тот же день, так
что расхождения между ней и планом нет» — по этому пункту утверждение неверно, а
спека остаётся тем, что читают, когда планов уже нет.

Как чинить: дописать ленту в ту фразу спеки, с доводом «при смене фильтра или
сортировки старый ответ приезжать не должен».

**5. Спека числит «всё с этим человеком» за справочниками, а он в поиске.**

`docs/specs/2026-07-31-client.md:64` — «справочники | `genres.list_for_kind`,
подсказки людей и студий, **«всё с этим человеком»**». Задача 6 плана разобрала
это и решила иначе: жест забрал `Search.by_person` (план 11), а `Refs.items_of`
не заводится вовсе, потому что у него не осталось бы потребителя. `bridge/refs.py`
несёт три метода, и четвёртого там не будет.

Как чинить: перенести жест в строку «поиск» таблицы доменов спеки.

**6. Несобранный фронт даёт пустое окно и пустой лог.**

`bridge/serve.py:57-65`. `WEB_ROOT` указывает на `client/dist`, которого сегодня
нет ни в репозитории, ни в клоне. Замерено: запрос `/` отвечает
`404 Not Found`, тело пустое, **в лог не уходит ничего** — `logger.exception`
стоит только на ветке `OSError`. То есть `python main.py` из чистого клона
открывает пустое окно, и ни одна строка нигде не объясняет почему.

Почему важно: это первый опыт запуска из чистого клона, и он молчит. Правило
проекта — «Молча не глотаем: пойманное либо плашкой, либо в лог, либо и то и
другое», а тут нет ни плашки (страницы нет вовсе), ни записи.

Как чинить дёшево: одна запись `logger.error`, когда `self._root` не
существует, — при сборке `Page` или на первом промахе по `index.html`. Она
отличает «фронт не собран» от «нет такого файла», и это разные беды.

### Minor (по возможности)

**7. Докстринг `_manual` верен для заведения и обманчив для правки.**

`bridge/library.py:51-57`: «Незаполненное в форме — это «не знаю»… поле остаётся
тем, что объявлено по умолчанию». У `create` так и есть. У `replace` тот же
`_manual` едет в `LibraryRepository.replace_fields`, который **пишет все поля
карточки** (`backend/storage/repository/library.py:177`), — значит не присланное
страницей поле не «остаётся», а **сбрасывается в умолчание**: `poster_url` в
пустую строку, `year` и `runtime` в `None`. Форма правки в плане 9 будет
писаться по этому докстрингу.

Как чинить: одна фраза в `Library.replace` — «правка шлёт форму целиком:
непереданное поле затирается умолчанием, а не сохраняется».

**8. `docs/module-map.md:1125` — ответственность обрывается на полуслове.**

`bridge/world.py` описан как «Мост: всё, что смотрит наружу, — привязка по
ссылке, перезапрос сериала,». Инструмент берёт первую строку докстринга, а у
этого модуля первая строка переносится. Единственный такой случай на всю карту —
проверено по всем 1600 строкам.

Как чинить: свернуть первую строку докстринга `bridge/world.py` в законченную
фразу, карту пересобрать.

**9. `CLAUDE.md` называет 38 вызовов сторожа, а их 40.**

Раздел про план 5: «Сейчас сверяет 38 вызовов». Собрано параметризацией
`test_every_call_the_bridge_makes_fits_the_backend` — **40**. Число было верным
после задачи 10, а задача 11 добавила `bridge/serve.py` с двумя вызовами
(`library.get`, `posters.poster_for`).

**10. Миграции не читают `.env`, а приложение читает.**

`main.py:39` зовёт `load_dotenv()`; `migrations/env.py:26` берёт голый
`os.environ`. Сегодня расхождения не видно только потому, что `.env` читает сам
`pipenv run`. Вне `pipenv` — активированный venv, `python -m alembic` —
`DATA_DIR` из `.env` для миграций невидим: схема ляжет в `./data`, а приложение
откроет базу по своему пути и получит «no such table: item». Замерено в клоне:
с пустым окружением alembic завёл именно `./data/library.db`.

`CLAUDE.md` при этом утверждает: «Путь к базе миграции берут из тех же
настроек, что и приложение». Это правда про загрузчик и неправда про источник.

Как чинить: либо `load_dotenv()` первой строкой в `migrations/env.py`, либо
оговорка в «Окружении», что команда работает только через `pipenv run`.

**11. `.gitignore` в задаче 11 числится изменяемым, но не менялся.**

Правильно не менялся: строка `dist/` закрывает `client/dist` на любой глубине —
проверено, и решение записано в `docs/deferred.md`. Устарел список файлов
задачи 11, а не код.

**12. В «Окружении» `CLAUDE.md` нет команды запуска самого приложения.**

Есть `pipenv run python <файл>`, но не `pipenv run python main.py`, и нет
предупреждения, что до плана 6 окно откроется пустым (это сказано только в
«Состоянии»). Раздел заявлен как то, что переживёт удаление `docs/`, — там
уместна вся последовательность: `pipenv install --dev` → скопировать
`.env.example` в `.env` → `alembic upgrade head` → `python main.py`.

**13. Память `World` держит и `Missing`, и `Refusal`.**

`bridge/world.py:94` кладёт в `Kept` то, что вернул `loader.card_for_link`,
каким бы исход ни был, а `World.link` (строка 53) сторожит только `card is None`.
Страница, позвавшая `link` после `{"outcome": "missing"}`, отдала бы `Missing()`
в `linker.link`. План это условие называет прямо («Если это перестанет быть
правдой, память обязана держать только найденное») и оставляет на дисциплине
страницы; сторожа нет.

Как чинить дёшево: класть в память только при `outcome == found` — одна ветка.

## Вердикт

**Готово к слиянию? — С правками.**

Полнота относительно спеки — чистая: **ни одного требования, обращённого к
питоновской стороне, не пропущено**, а всё отложенное названо поимённо и
привязано к плану с потребителем. Сборка с нуля тоже чистая: клон не носит
лишнего, схема поднимается миграциями без ключей (15 таблиц, 47 жанров, 326
соответствий), а бэкенд с мостом поднимаются и отвечают на пустом `.env`, причём
об отсутствующем ключе говорят отказом с причиной `key`, а не падением.

Critical нет. Из шести Important пять — расхождения записей с кодом (две в
таблице номеров плана, две в спеке, одна в плане про цвет), и все чинятся
строчкой; шестая — единственная правка кода, и та в одну запись в лог. Ни одна
не мешает плану 6 начаться, но первая и шестая обойдутся дороже, если их
оставить: цвет вспыхнет при каждом запуске после того, как встанет палитра, а
молчащая отдача страницы будет первым, обо что споткнётся сборка фронта.

Порядок правки по цене: 6 (запись в лог) → 1 (цвет) → 2, 3, 4, 5 (записи) →
7, 13 → 8, 9, 10, 11, 12.
