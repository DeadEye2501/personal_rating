## Критическое

### К1. Схема базы не попала ни в одну карту — ровно то, ради чего карту заводили

`contents` берёт с уровня модуля только имена, прошедшие `isupper()`:

```python
pair = assigned(node)
if pair and pair[0].split(":")[0].isupper():
```

Таблицы проекта объявлены строчными именами и потому невидимы целиком:

| Модуль | Что пропало |
|---|---|
| `backend/storage/tables/catalog.py` | `item`, `genre`, `genre_map`, `item_genre`, `person`, `person_credit`, `company`, `company_credit`, `external_id`, `external_rating` |
| `backend/storage/tables/mine.py` | `rating`, `tag`, `item_tag`, `wishlist` |
| `backend/storage/tables/base.py` | `metadata` |
| `backend/storage/posters.py` | `poster`, `metadata` |

В `docs/data-map.md` нет ни одного раздела на `backend/storage/tables/*` и на
`backend/storage/posters.py`. В карте модулей их тоже нет: `declared()`
показывает только `def`/`class` и псевдонимы типов, а `item = Table(...)` не то
и не другое. **Пятнадцать таблиц, то есть вся схема, не видны рецензенту нигде.**

Это не косметика, а промах по заявленной цели. Докстринг `contents` обещает:

> два перечисления с одними значениями или **вторая таблица под другим именем**
> видны только отсюда

`SKILL.md` повторяет то же слово в слово. Между тем `metadata = MetaData()`
заведён дважды — в `storage/tables/base.py` и в `storage/posters.py`, — и это
ровно тот случай «второе такое же под тем же именем в другом модуле», который
карта должна была показать первым. Она молчит.

Заодно молчит и о том, что колонки таблиц нигде не перечислены, тогда как поля
датаклассов, которые эти колонки повторяют, перечислены полностью: сверить
`Item` (14 полей) с `item` (14 колонок) по картам нельзя.

Фильтр `isupper()` осмыслен на уровне модуля — иначе в карту поедут `logger`,
`config`, `target_metadata`. Но он выбран по регистру имени, а не по природе
значения, и вырезает единственный случай, ради которого карту и завели.
Что делать — решать автору; варианты, которые видит рецензент: пускать в карту
строчные имена, чьё значение — вызов (`Table(...)`, `MetaData()`), либо называть
все имена уровня модуля и отсеивать только заведомый шум.

**Пока не починено, ссылаться на карту данных как на проверку правила 1 по
хранилищу нельзя.**

## Существенное

### С1. Размер набора врёт, когда в литерале есть распаковка

`brief` считает размер по синтаксису: `len(value.keys)` и `len(value.elts)`.
Распакованный элемент считается за единицу. Проверено прогоном на пробном модуле:

```python
BASE = {"a": 1, "b": 2, "c": 3, "d": 4, "e": 5}
MERGED = {**BASE, "f": 6}     # карта: «словарь из 2», фактически 6
PARTS = ["x", "y"]
JOINED = [*PARTS, "z"]        # карта: «набор из 2», фактически 3
```

Размер — единственное, что карта сообщает о наборе; если он врёт, строка карты
хуже её отсутствия: рецензент видит «словарь из 2» и проходит мимо справочника
на две сотни строк. В текущем коде проекта распаковки в литералах данных нет —
дыра пока не выстрелила, но `genre_map` собирают именно склейкой словарей, и до
неё один слайс.

Починка дешёвая: при наличии `None` среди `keys` (для словаря) или `ast.Starred`
среди `elts` дописывать признак неточности — «словарь от 2» или «словарь из 2 +
распаковка».

### С2. Цепочки и кортежные присваивания теряются молча

`assigned` разбирает только `len(node.targets) == 1` с целью-`Name`.
Всё прочее возвращает `None`, и `contents` не отличает «не присваивание» от
«присваивание, которого я не понял». Проверено прогоном:

```python
FIRST = SECOND = 1        # в карте нет ни того, ни другого
THIRD, FOURTH = 2, 3      # нет
(FIFTH, SIXTH) = 4, 5     # нет

class Outer:
    PAIRED = ALSO_PAIRED = 9   # нет ни одного
```

Опасность именно в молчании: карта заявлена как полная и как основание для
`--check`, и её пустое место читается как «данных нет», а не «разбор не потянул».
Для карты, ради которой отказались от ручного ведения, это худший вид пробела.

В боевом коде проекта таких объявлений сейчас нет — обход всего своего кода
(`backend`, `client`, `tests`, `scripts`, `migrations`) нашёл кортежные
присваивания только в телах функций, куда карта и так не заглядывает.

## Мелкое

### м1. Вложенные классы и классы внутри функций не разбираются вовсе

`contents` обходит `tree.body`, а тело класса просматривает одним `assigned`.
`ClassDef` внутри `ClassDef` даёт `None` — класс не показан и внутрь него не
зашли. Класс, объявленный внутри функции, не виден по той же причине.

```python
class Outer:
    class Inner:
        INNER_FIELD: ClassVar[int] = 2   # в карте нет

def factory():
    class Local:
        LOCAL_FIELD: ClassVar[int] = 7   # в карте нет
```

Карта модулей вложенные классы показывает (`declared` рекурсивна), карта
данных — нет. Расхождение между двумя картами по одному и тому же коду.
В проекте сейчас таких классов нет.

### м2. Константы внутри `if` и `try` на уровне модуля не видны

Обход идёт по `tree.body` без спуска в составные инструкции. `GUARDED = 42`
внутри `if True:` в карту не попал. Значимо для `if TYPE_CHECKING:` и для
запасных значений в `try/except ImportError`. В проекте сейчас таких нет.

### м3. Значение не заключено в обратные кавычки — markdown его портит

Имя обёрнуто, значение нет:

```python
lines.append(f"- `{pair[0]}` = {pair[1]}")
```

В уже собранной карте это видно живьём:

```
- `PICTURE` = b'\x89PNG\r\n\x1a\n' + b'0' * 128
```

Звёздочка и подчёркивание в значении — управляющие символы markdown. Значение с
двумя `*` или двумя `_` отрисуется курсивом, и карта покажет не то, что в коде.
Обратные кавычки вокруг значения снимают вопрос целиком.

Там же: обрезка режет строку по символам, не глядя на кавычки, и даёт
`'0123…456…` с непарной кавычкой. Знак обрезки `…` при этом на месте, граница
проверена: 47 символов проходят целиком, 51 обрезается.

### м4. `CLAUDE.md` знает только одну карту

Раздел «Порядок работы» говорит «рецензенту сначала `docs/module-map.md`»,
«**Карта** собирается из кода», «`--check` роняет сборку, если **карта**
отстала». Про `docs/data-map.md` там нет ни слова. `SKILL.md` обновлён и обе
карты описывает; проектный файл — нет. Рецензент, работающий по `CLAUDE.md`,
вторую карту не откроет.

### м5. `render_data` — второй экземпляр «шапка, перебор корней, `startswith`»

`render` и `render_data` совпадают формой: список-преамбула, цикл по `roots()`,
отбор `path.startswith(root)`, склейка. Отличаются четырьмя строками текста и
тем, что второй отсеивает пустые блоки. По правилу 3 это второе появление, а не
третье.

Заодно вместе с формой скопирован и дефект: `path.startswith(root)` — сравнение
строк, а не путей. Корни `test` и `tests` в одном проекте дали бы двойной учёт.
Своих корней с общим префиксом сейчас нет.

### м6. `modules()` разбирает проект трижды за одну запись

`main` строит `maps` из `render()` и `render_data()` — по разбору каждый, — а
потом зовёт `modules()` третий раз, только чтобы напечатать число. До правки
разборов было два. Прогон занимает 0.46 с, так что вопрос не в скорости, а в
том, что число модулей уже посчитано двумя строками выше.

### м7. `data_block` возвращает пустую строку как сигнал «нечего показывать»

Четырёхстрочная функция, чей результат вызывающий обязан проверить на пустоту
(`filled = [block for block in blocks if block]`). `contents` уже возвращает
пустой список — сигнал есть, и он честнее. Мелочь, но лишнее звено.

## Манифест: место, ответственность, размер

**Место (правило 2) — верное.** Разбор дерева, обход корней, `roots()`,
`modules()`, `signature`, `size` — общее для обеих карт и уже лежало здесь.
Заводить второй скрипт значило бы либо продублировать обход, либо завести
третий файл под общее — а файл обязан оставаться **одним**: `SKILL.md` велит
копировать `tools/module_map.py`, и побайтное совпадение трёх копий проверяется
вручную. Три файла вместо одного утроят эту проверку.

**Ответственность (правило 6) — описана честно.** Первая строка докстринга —
«Карты проекта, собираемые из кода» — одна фраза без «и», и именно она попадает
в карту модулей. Ниже прямо сказано, зачем карт две и по какому шву они разошлись.
Это не пряталось.

**Размер — 355 строк, сигнал в 300 пройден, предел 500 далеко.** Карта модулей
уже помечает файл: `⚠ подошёл к 300`.

Делить сейчас **не надо**, и вот почему: шов, по которому файл делился бы
естественно — «обход и разбор» против «двух отрисовок», — упирается в
требование одного файла. Плата за деление выше пользы.

Но запас невелик. Шов на будущее назвать стоит уже сейчас: `project_root`,
`roots`, `modules`, `signature`, `alias`, `size`, `assigned`, `brief` — это
разбор, ничего не знающий о markdown; `module_block`, `data_block`,
`lonely_block`, `render`, `render_data` — отрисовка, ничего не знающая об `ast`.
Если файл дорастёт до 450, резать по этой линии, и тогда же пересматривать
правило «один файл на все проекты».

**Абстракций впрок не заведено (правило 7).** Ни интерфейса, ни реестра, ни
базового класса. `assigned` — общее место для полей, значений перечислений и
констант, и это вынос по факту трёх потребителей, а не заготовка.

**Комментарии (правило 11).** Единственный новый — при `SHORT_VALUE`, и он
объясняет решение, а не пересказывает код. Докстринги `brief`, `assigned`,
`contents` называют «зачем», а не «что». Претензий нет.

## Про отсутствие тестов

Отсутствие тестов у скрипта названо осознанным решением. По большей части оно
держится: `--check` — сторож честный, он ловит любое расхождение карты с кодом,
и проверить его самого прогоном дёшево.

Но одну часть без теста рецензент считает опасной и говорит прямо: **`brief` и
`assigned`.** Причина не в сложности, а в том, что их поломка не красная.
`--check` сравнивает карту с картой; если `brief` начнёт врать про размер или
`assigned` перестанет узнавать очередную форму присваивания, обе стороны
сравнения соврут одинаково, и `--check` останется зелёным. Ровно это и случилось
с С1 и С2: обе находки нашлись прогоном пробного модуля, ни одна — самопроверкой.
Тест на этих двух функциях — не про объявления, а про поведение (правило 13):
подать разбор куска кода, получить строку, сверить с ожидаемой; сломать `brief`
нарочно и убедиться, что покраснел (правило 14). Это десяток строк и
единственное место в скрипте, где ошибка проходит мимо всех сторожей.

Остальному тесты действительно не нужны.
