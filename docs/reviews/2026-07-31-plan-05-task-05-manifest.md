### Important (следует поправить)

**1. `tests/bridge/test_bridge_library.py:27-36` — тест не может упасть ни при
какой поломке того, ради чего написан.**

```python
def test_an_empty_field_does_not_reach_the_backend(spy, asked):
    Library(spy).create({"kind": "movie", "title": "Одиссея", "year": None})
    assert args[0].year is None
```

Что не так: выбрано единственное поле, на котором фильтр `value is not None`
ничего не меняет. У `Item.year` значение по умолчанию — `None`. Убери из
`_manual` весь фильтр — получится `new_manual_item(..., year=None)` →
`Item(year=None)`, и `assert args[0].year is None` по-прежнему зелёный. Тест
сторожит `_manual` со снятым сторожевым условием.

Почему важно: фильтр несущий, и несёт он не `year`. У `original_title`,
`synopsis` и `poster_url` значение по умолчанию — пустая строка, а не `None`:
пришедший со страницы `null` без фильтра положил бы в строковую колонку `None`.
Ещё хуже с `synced_at` — `new_manual_item` подставляет его через
`fields.setdefault`, а `setdefault` не срабатывает, если ключ есть со значением
`None`: карточка ушла бы в базу с `synced_at=None`. Ровно это условие никто не
наблюдает.

Это тот самый класс дефекта, который проект уже ловил дважды («свойство
наблюдалось только с одной стороны», «тест не мог упасть ни при какой поломке
того, ради чего написан»), и здесь он пришёл из плана дословно. По манифесту
(«Готовый тест — тоже твой») отвечает за него слайс.

Как чинить: взять поле, у которого умолчание не `None`, — одна строка:

```python
Library(spy).create({"kind": "movie", "title": "Одиссея", "synopsis": None})
...
assert args[0].synopsis == ""
```

Без фильтра здесь придёт `None`, с фильтром — `""`. Тот же тест на `year`
оставлять незачем; если хочется обоих — вторым асёртом в этом же тесте.
Правку стоит внести и в план, иначе она вернётся с следующим переписыванием.

```python

```

Ветка `else` недостижима ни в одном зелёном сценарии: если бы мост передавал

Пришло из плана.

Как чинить: убрать условие, оставить `assert args[1:4] == (9, 8, 4)`. Ценность

Как чинить: дописать в докстринг `_manual` одну фразу — «незаполненное страница

### Про правило 14 и красную фазу этого слайса

Красная фаза здесь по устройству слабая, и это стоит назвать вслух: модуля не
существовало, поэтому **все** тесты падали одним `ModuleNotFoundError`, не
исполнив ни одного своего `assert`. Манифест такую фазу принимает — на новом
модуле другой не бывает, — но она ничего не говорит о том, умеет ли конкретный
`assert` различать поломку. Находка 1 — прямое подтверждение риска: тест прошёл
красную фазу вместе со всеми и при этом не может упасть никогда. Настоящую
проверку этим тестам даст сторож поверхности (задача 10) и мутации итогового
ревью плана; между слайсами их не гоняет никто, и это правильно.
