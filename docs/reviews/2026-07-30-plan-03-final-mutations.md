Прогнан весь набор один раз: `python -m pytest -q --no-header` — 669 зелёных.
Дальше — по одной строке за раз, каждая мутация прогонялась против конкретного
файла тестов, откатывалась, набор возвращён в зелёное состояние.
`git status --short` после ревью показывает только этот отчёт.

Проверено 6 мутаций сверх той сотни, что уже прогнал исполнитель по слайсам.

## 1. `backend/service/images.py:23` — граница пропорции 2:3 не проверена ровно на границе

Было: `if width / height > TARGET_RATIO:`
Стало: `if width / height >= TARGET_RATIO:`

Единственная картинка с исходной пропорцией ровно 2:3 в тестах —
`picture(600, 900)` в `test_an_already_correct_ratio_is_only_resized`. На ней
оба условия («режем по ширине» и «режем по высоте») дают один и тот же
прямоугольник `(0, 0, 600, 900)` — обрезка при точном совпадении пропорции
вырождается в тождество независимо от того, какая ветка сработала. Тест видит
только итоговый размер после `resize`, а он одинаков в обеих ветках. Тест,
который должен был покраснеть, — `test_images.py::test_an_already_correct_ratio_is_only_resized`,
но математически не может: нужен тест, различающий ветки не по размеру
результата, а по факту, какая ветка вызвана (например, не квадратная область
между «чуть шире» и «чуть уже» 2:3 с разными сторонами).

## 2. `backend/service/card_parts.py:51-54` — порядок записи id и оценок не проверен изолированно

Было:
```python
for external in card.external_ids:
    await self._ids.put(item_id, external)
for rating in card.ratings:
    await self._ratings.record(item_id, rating)
```
Мутация: порядок циклов поменян местами (сперва оценки, потом идентификаторы).

Комментарий в коде объясняет, зачем нужен именно этот порядок: «на занятом
идентификаторе запись прерывается, и оценки в этом случае писать некуда». Но
единственный тест на срыв записи — `test_card_writer.py::test_a_taken_identifier_leaves_nothing_behind`
(и его пара `test_the_rollback_takes_the_written_half_with_it`) — откатывает
**всю карточку целиком** через `CardWriter.save`, так что после отката пусты
и жанры, и люди, и оценки, и идентификаторы вне зависимости от того, в каком
порядке они писались до срыва. У `Linker` конфликт идентификаторов проверяется
заранее в `_check_identifiers`, поэтому до `_write_external` он вообще не
доходит. Прогнаны `test_card_writer.py` и `test_linking.py` целиком — 48
тестов, все зелёные при перевёрнутом порядке. Отдельного теста на
`CardParts._write_external` нет вовсе.

## 3. `backend/service/genres.py:28` — порядок разрешённых жанров не проверен

Было: `return list(dict.fromkeys(found))`
Стало: `return sorted(set(found))`

Комментарий прямо говорит: «Порядок сохраняется: словарь помнит его с 3.7, а
`set` — нет» — но ни один тест этот порядок не проверяет. В
`test_genre_resolution.py` сравнение либо через `sorted(found)`, либо на
единственный элемент; в `test_card_writer.py` результат всегда сравнивается
как множество имён (`{g.name for g in ...}`). Прогнаны `test_genre_resolution.py`,
`test_card_writer.py`, `test_linking.py` — 52 теста, все зелёные с
`sorted(set(...))` вместо `dict.fromkeys`. Нет теста, где несовпадение номеров
жанров с порядком их числовых id сделало бы `sorted` заметно другим, чем
исходный порядок появления.

## 4. `backend/model/link.py:27` — правая граница голого числового идентификатора не проверена

Было: `_BARE = re.compile(r"^\d+$")`
Стало: `_BARE = re.compile(r"^\d+")`

Без `$` строка вроде `"157336-что-то-ещё"` или `"292030abc"` при известном
`kind=Kind.MOVIE`/`Kind.SERIES` стала бы приниматься как голый TMDB-номер,
хотя по построению голый номер обязан быть **всей** строкой. Список
`NONSENSE` в `test_links.py` не содержит ни одной строки «цифры плюс мусор
после них» для случая, когда тип передан тумблером — только строки без цифр
вовсе или содержащие завершённые адреса. Прогнан весь `test_links.py` —
32 теста, все зелёные без правой границы `$`.

## 5. `backend/service/linking.py:19-22` — не все поля `_FILLABLE` проверены индивидуально

Было:
```python
_FILLABLE = (
    "title", "original_title", "year", "released_at", "synopsis", "poster_url",
    "runtime", "seasons_count", "episodes_count",
)
```
Мутация: убрано `"seasons_count"` из списка.

`test_linking.py` проверяет слияние `merge_fields`/`overwrite_fields` только
на `title`, `synopsis`, `year`, `runtime` (плюс отдельно `poster_url` через
факт закачки обложки). Поле `seasons_count` явно фигурирует в тесте
`test_the_type_of_the_card_is_never_changed`, но там оно нужно только затем,
чтобы у входящей карточки был непустой сериал, — само значение
`seasons_count` после привязки не проверяется. Прогнан `test_linking.py`
целиком — 27 тестов, все зелёные без `seasons_count` в списке доливаемых
полей. Тот же пробел, вероятно, есть у `original_title` и `released_at`, но
их не трогал — один показательный случай достаточен.

## 6. `backend/storage/repository/external.py:101` — оценка `0.0` неотличима от «источник промолчал»

Было: `ttl = VALUE_TTL if stored.value is not None else EMPTY_TTL`
Стало: `ttl = VALUE_TTL if stored.value else EMPTY_TTL`

Три состояния оценки агрегатора (нет строки / есть строка со значением `None`
/ есть строка со значением) проверены в `test_external_ratings.py`
исключительно на значении `8.6` — истинном при любой проверке. Ни один тест
не пишет оценку `0.0` (легитимное значение — например, 0% на Rotten
Tomatoes) и не проверяет, что она живёт `VALUE_TTL`, а не по ошибке
переходит в `EMPTY_TTL` как пустой ответ. Прогнаны `test_external_ratings.py`,
`test_card_writer.py`, `test_linking.py` — 60 тестов, все зелёные с `if
stored.value` вместо `if stored.value is not None`.
