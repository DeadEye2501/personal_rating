## 2. Блокирующая находка

### 2.1. Правило 1 и 3: `alembic` теперь существует в двух экземплярах

`tests/conftest.py:37` и `tests/backend/test_migrations.py:17` — две копии одной
функции, тела совпадают строка в строку, отличается только докстринг:

```python
def alembic(db_path: Path, *command: str) -> None:
    result = subprocess.run(
        [sys.executable, "-m", "alembic", "-x", f"db={db_path}", *command],
        cwd=ROOT, capture_output=True, text=True,
    )
    if result.returncode != 0:
        joined = " ".join(command)
        pytest.fail(f"alembic {joined} провалился:\n{result.stdout}\n{result.stderr}")
```

Вместе с ней продублирована и константа `ROOT` (`conftest.py:12` через
`parents[1]`, `test_migrations.py:11` через `parents[2]` — один и тот же
каталог, посчитанный дважды).

**Это прямо противоречит тому, что записано в плане** как сделанное:

> Фикстура `migrated` и вызов `alembic` переехали в `tests/conftest.py` — иначе
> они появились бы вторым экземпляром рядом с `test_migrations.py`.

Переезда не было — было копирование. Второй экземпляр появился ровно там, где
его обещали не допустить, и запись в плане сейчас неверна.

**Почему машина промолчала.** Хук сравнения тел на записи `conftest.py` отработал
и дубля не увидел — из-за добавленного докстринга:

```
conftest.py:37        exact 8729e1a2bacd08fe   shape 4b14ada83c91b3dd
test_migrations.py:17 exact 786b5a06eca61406   shape dd383db958d0c2b2
```

Докстринг — тоже инструкция в теле, и он сдвигает оба отпечатка. Это ровно тот
случай, ради которого правила 1 и 3 оставлены человеку.

**Чинится удалением копии из `test_migrations.py`** вместе с его `ROOT` и
импортами `subprocess`/`sys`/`Path`; функция берётся оттуда же, откуда уже
берётся `TABLES`.

## 3. Важные находки

### 3.1. Правило 15: `scripts/genre_map.py` сверяет не то, что обещает, — разделитель не находится

`from_migration` (строка 43) режет текст по `"\n\n\ndef upgrade"`:

```python
body = "GAME = [" + text.split("\nGAME = [")[1].split("\n\n\ndef upgrade")[0]
```

В миграции перед `def upgrade` **одна** пустая строка, а не две — подстроки в
файле нет:

```
splitter "\n\n\ndef upgrade" present: False
one-blank "\n\ndef upgrade"     present: True
```

`str.split` по отсутствующему разделителю возвращает список из одного элемента,
`[0]` отдаёт весь остаток файла, и `exec` выполняет заодно объявления `upgrade`
и `downgrade`. Сегодня это проходит молча и даёт верные словари — потому что
дальше в файле только `def`, — то есть **проверка зелена по случайности, а не по
устройству**. Любая строка верхнего уровня, дописанная под словарями, начнёт
исполняться при каждом прогоне сверки.

Чинится либо двумя пустыми строками перед `def upgrade` в миграции (заодно это
PEP 8, который Ruff в текущем наборе правил не ловит), либо резкой по
`"\ndef upgrade"`. Первое лучше: разделитель тогда перестанет зависеть от того,
сколько пустых строк кто-то оставит.

### 3.2. Правило 2: `alembic` — не фикстура, и в `conftest.py` ей тесно

`conftest.py` — файл, который pytest сам находит и из которого сам раздаёт
фикстуры. Импортировать из него обычные функции (`from tests.conftest import
alembic`) — обход этого механизма: модуль оказывается ещё и библиотекой, которую
тестовые модули тянут по пути.

Ответственность файла теперь описывается только с «и»: раздавать фикстуры **и**
запускать Alembic отдельным процессом. Это правило 6 в чистом виде — данные
(`TABLES`, `MINIMAL`) и фикстуры (`migrated`, `engine`, `stored`) держатся
вместе законно, а вот драйвер подпроцесса к ним не относится.

Место для него — отдельный `tests/alembic_runner.py` (или `tests/helpers.py`) с
`ROOT` и `alembic`. Оттуда его импортируют оба тестовых модуля, и находка 2.1
закрывается тем же движением: копии становится негде взяться.

Фикстура `migrated` в `conftest.py` лежит правильно — она фикстура, и её видят
оба будущих потребителя.

### 3.3. Правило 11: докстринг `scripts/genre_map.py` обещает больше, чем делает

Два расхождения, оба проверены прогоном.

**`--dicts` печатает не то, что лежит в миграции.** `as_dicts` (строка 51)
выводит четыре игровых словаря без комментариев:

```
STEAM = {
    "1": ["Action"],
    "25": ["Quest"],
```

В миграции те же строки идут с чужими названиями (`# Экшены`,
`# Приключенческие игры`), и её собственный докстринг называет их обязательными:
«без них номер `323922` не значит ничего». Регенерация через `--dicts` и вставка
результата обратно потеряет все ~296 комментариев разом. Либо `as_dicts` должен
печатать их, либо докстринг не должен называть вывод «словарями миграции»:
`FILM`, `GAME` и `TMDB` он не печатает тоже.

**Сверка не покрывает TMDB.** `BOOKS` — только четыре игровых источника.
Мутации, внесённые в копию миграции:

| Мутация | Итог сверки |
|---|---|
| `"1628": ["Metroidvania"]` → `["Platformer"]` | **поймана** |
| строка `"1628"` удалена целиком | **поймана** |
| `"878": ["Фантастика"]` → `["Комедия"]` (TMDB) | **не поймана** |
| испорчен только комментарий `# Метроидвания` | не поймана |

Первые две — то, ради чего скрипт написан, и они краснеют. Третья показывает
границу: строка «сверить спеку с миграцией» верна для 296 соответствий из 326.
Формально TMDB и не описан в `2026-07-27-game-genres.md`, но из докстринга это
не следует, а со стороны тестов TMDB прикрыт (`test_tmdb_map_has_thirty_rows...`,
`test_composite_genres_are_split_in_two`), так что дыры в покрытии нет — есть
неточная формулировка.

## 4. Мелкие находки

### 4.1. Правило 11: докстринг миграции говорит обратное тому, что имел в виду

`0002_genres.py:9`:

> Числа рядом с идентификаторами — чужие названия: без них номер `323922` не
> значит ничего.

Числа — это и есть идентификаторы. Чужие названия — в комментариях рядом с
ними. Читается как «числа суть названия»; вторая половина фразы верна, первая
переставлена. Достаточно «Названия рядом с идентификаторами».

### 4.2. Правило 11: сами комментарии с чужими названиями — уместны

Проверено удалением: убрать `# Мусоу` из `"323922": ["Action"]` — и строку
нельзя ни прочитать, ни проверить, ни исправить. Комментарий несёт то, чего в
коде нет, а не пересказывает его. Правило 11 соблюдено, и это верное решение,
несмотря на то что комментариев почти триста.

Оговорка: у них нет никакой машинной сверки (мутация комментария в таблице
раздела 3.3 не ловится), а исходник тот же — спека. Ошибка в названии будет жить
до тех пор, пока кто-нибудь не полезет сверять руками. Заводить проверку ради
этого не предлагаю — цена выше пользы, — но знать об этом стоит.

### 4.3. Правило 4: 402 строки одним файлом — здесь правильно

Файл в полосе «сигнал» (300) и далеко от предела (500), причём кода в нём 36
строк, остальное — литералы. Растаскивать данные в отдельный модуль было бы
**хуже**, а не лучше: ревизия Alembic обязана быть неизменяемой, а импорт из
общего модуля означает, что правка справочника завтра тихо изменит то, что
делает вчерашняя миграция. Данные и код одной ревизии живут вместе. Возражений
нет, отмечено, чтобы следующий рецензент не открывал заново.

### 4.4. Правило 6: докстринг миграции с «и» — допустимо

«Справочник жанров и соответствия к нему» — формально два предмета, фактически
одна атомарная ревизия: `genre_map` без `genre` бессмыслен, разнести их по двум
ревизиям значит завести состояние, в котором база наполовину наполнена. Оставить
как есть.

### 4.5. Правило 5: `upgrade` на пределе вложенности

Три вложенных `for` подряд (строки 380–396) — ровно 3 уровня, предел правила 5.
Ruff молчит, дописывать туда нельзя. Если понадобится четвёртый источник с иным
устройством, внутренний цикл придётся вынести отдельной функцией.

### 4.6. Правило 1: мелкий повтор в `test_genre_reference.py`

Строки 139–143 открывают движок, читают два счётчика и закрывают его — то же,
что делает фикстура `migrated`, только вручную и по чужому пути базы. Фикстуру
здесь взять нельзя (тесту нужен свой круг миграций), так что дубль вынужденный;
он короче пяти инструкций и хук его не увидит. Оставить можно, но если такой
тест появится второй раз — выносить.
