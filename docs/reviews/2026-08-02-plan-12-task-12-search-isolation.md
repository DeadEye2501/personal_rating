`client/state/session.js`, `client/api/bridge.js`, `client/api/owned.svelte.js`,

## Critical

### 1. Ответ уже начатого поиска приезжает после снятия запроса — прежний симптом возвращается гонкой, и это регрессия

`client/app/App.svelte:256-260`, `client/app/SearchScreen.svelte:45-54, 71-88`.

Снятие запроса теперь **не порождает нового вызова моста**, а только гасит
ленту:

```js
$effect(() => {
  const clicked = person
  turns = rowTurns()
  if (clicked) { about(clicked, kind).catch(lost); return }
  if (!query?.text) { views = []; return }   // ← новая ветка становится частой
  look(query.text, kind).catch(lost)
})
```

Устаревшее на странице отбрасывается ровно одним механизмом — номером канала в
`client/api/bridge.js:66-68`:

```js
if (latest.get(channel) !== op) throw new Failed('stale')
```

`latest['search']` меняется **только** при новом `numbered(...)` по этому каналу.
Ветка `views = []` нового вызова не делает, значит номер прежней операции
остаётся последним, и её ответ считается своевременным. `owned()`
(`client/api/owned.svelte.js:16`) здесь тоже не сторож: его уборщик срабатывает
на размонтировании раздела, а смена типа `SearchScreen` не размонтирует —
`{#key}` в `App.svelte:274` стоит по `session.section`, не по `kind`.

Что из этого следует, по шагам:

1. Во вкладке «Игры» ищем «fallout». `search.local` отвечает мгновенно,
   `search.external` летит — по спеке отказов до 20 секунд на запрос.
2. Не дождавшись, переключаемся на «Сериалы». `switched` снимает `query`,
   эффект перезапускается и ставит `views = []`.
3. Приезжает `search.external` прежней операции. Номер совпадает, `stale` не
   выбрасывается, `arrived()` кладёт **игровую** выдачу в `views` — во вкладке
   сериалов, под пустым полем. Плюс плашка «Внешняя база недоступна» за поиск,
   от которого человек уже ушёл.

То есть ровно тот экран, с которого задача началась.

Отдельно важно, что **это регрессия, а не унаследованный долг**. До правки смена
вкладки перезапускала поиск с сохранённым запросом, и этот новый вызов сам
занимал канал — прежняя операция становилась `stale` и отбрасывалась молча.
Правка убрала перезапуск и вместе с ним единственную защиту. Тем же путём
ломается и крестик в своей вкладке: очистили поле, а через секунду выдача
вернулась сама.

Замечание к возможной починке: одного `cancel(ops)` мало. `bridge/thread.py:67-71`
прямо пишет, что отмена, обогнавшая заявку, молчит и «страницу это не задевает —
её ответ всё равно отброшен по номеру». Здесь по номеру он как раз не
отбрасывается, а успевший закончиться бэкенд на отмену вовсе не реагирует. Снятие
запроса обязано занять канал `search` так же, как это делает настоящий вызов
(явная негодность номера в `bridge.js` либо равносильное средство); отмена
операции — полезная добавка, но не замена.

## Important

### 2. Пустая строка снимает и человека: клик по имени убивается крестиком и случайным Enter

`client/app/App.svelte:256-257`.

```js
onsearch={(text) => { person = null
                      query = text ? { text } : null
                      ...
```

`person = null` стоит **до** ветвления и потому срабатывает и на пустой строке.
Пути к этому два, и оба дешёвые:

- выдача по клику на имя показана (`typed` при этом `''`, см. `byPerson`), человек
  что-то печатает в поле, передумывает и жмёт крестик → `onsearch('')` → человек
  снят, запрос снят, раздел поиска остаётся открытым и **пустым навсегда**:
  вернуть выдачу нечем, карточки с этим именем на экране уже нет;
- ещё дешевле: та же выдача, щелчок в поле и Enter по пустой строке — тот же
  результат без единого нажатия по крестику.

Это то самое состояние «раздел открыт, а показывать нечего и не будет», которого
задача и просила избегать. Комментарий крестика оправдывает снятие тем, что «поле
говорит, что ничего не искали», — но выдача по клику полем не заказывалась, поле
её и не описывало; отменять чужой жест у пустой строки основания нет.

Половина про Enter существовала и до правки (там пустая строка уезжала как
`query = { text: '' }`), но правка сделала этот путь штатным и добавила к нему
крестик, поэтому пункт в объёме задачи, а не унаследованный.

Спека, дописанная этой же правкой, положение не покрывает: она говорит про
переживание **вкладки**, а про очистку поля молчит. Что бы ни было решено — снимать
человека или нет, — согласовать надо оба места сразу.

### 3. Докстринг `byPerson` теперь описывает `switched`

`client/app/App.svelte:159-180`.

Новый блок вставлен **между** старым докстрингом и его функцией. Получилось два
подряд идущих `/** */`, и первый — «Клик по имени открывает поиск по человеку, а
не отдельный вид…» — оказался комментарием к `switched(next)`, которая про клик по
имени не знает вовсе. `byPerson` при этом осталась без объяснения, хотя объяснять
там есть что: она снимает строку и набранное.

Правило 11: комментарий объясняет решение, а не соседнее. Здесь он ещё и прямо
вводит в заблуждение — читающий `switched` получает рассказ про другой жест.
Проект этот класс дефекта («докстринг утверждает неправду») ловил уже трижды.

## Minor

### 4. Три снятия строки в трёх видах, и одно из них — ветка в разметке

`client/app/App.svelte:174-187, 256-260`.

Один и тот же переход «строки больше нет» записан теперь трижды и по-разному:

- `switched`: `query = null; typed = ''` под условием;
- `byPerson`: те же две строки дословно;
- обработчик `onsearch`: `query = text ? { text } : null` плюс `if (text)` вокруг
  смены раздела — прямо в разметке.

Две дословно совпавшие строки — это правило 3 на втором появлении; ветвление в
теле обработчика внутри шаблона — правило 10 («сборка только собирает») и
асимметрия с только что вынесенным соседом: `switched` уехала в скрипт, её
близнец остался в разметке. Названная функция рядом с `switched` и `byPerson`
собрала бы все три жеста в одно место — и, к слову, оказалась бы естественным
местом для починки находки 1.

Про слой замечаний нет: `query` и `typed` в `session` не входят, `state/session.js`
их снять не может, и `switched` в сборке лежит правильно; `withKind` она не
дублирует, а достраивает.

### 5. Комментарий приписывает решению возраст, которого у него нет

`client/app/App.svelte:172-173`: «Клик по имени вкладку переживает нарочно, и это
решение старше».

По записям — плану и спеке, дописанным этой же правкой, — исключение
**подтверждено пользователем 02.08.2026**, то есть тогда же. До того человек
переживал вкладку не нарочно, а потому, что его никто не снимал: ни `withKind`,
ни эффект `SearchScreen` к `person` не прикасаются. «Нарочно» верно с сегодняшнего
дня, «старше» — нет.

### 6. Запись в плане неточна в причине и неполна в правке

`docs/plans/2026-08-01-search-and-candidates.md:654-670`.

- «Причин было две, и обе в одном месте» — места два и разные: `SearchField.clear`
  (крестик не трогал запрос) и эффект `SearchScreen`, зависящий от `kind`
  (перезапуск с сохранённым запросом). Задача в брифе так и описана — двумя
  причинами в двух местах.
- Про саму правку сказано только то, что́ было сломано. Ни `switched`, ни то, что
  пустая строка больше **не** открывает раздел поиска, в записи не названы — а
  второе это видимая смена поведения: раньше Enter по пустому полю уводил в поиск.

## Что проверено и оказалось верным

- **Человек переживает смену вкладки.** `switched` (`App.svelte:174-180`) к
  `person` не прикасается, эффект `SearchScreen:45-54` зависит от `person` и
  `kind`, ранняя ветка при непустом человеке строку не читает вовсе — при смене
  типа уходит новый `search.by_person` с новым типом. `query`/`typed` при этом не
  воскресают: `byPerson` их снял, `switched` снимает повторно.
- **Гонки при переключении вкладки с активным человеком нет:** новый вызов по
  каналу `search` занимает номер, и ответ прежнего отбрасывается как `stale`.
  Дыра только в ветке «запроса нет» — см. находку 1.
- **Условие в `switched` равносильно настоящей смене типа.** `withKind` возвращает
  тот же объект при совпадении, `kind` меняет только `Segmented` в шапке, и все
  прочие переходы шапки (`section`, `sort`, `collapsed`) через `switched` проходят
  не задевая строку.
- **Enter по строке из пробелов ведёт себя как крестик:** `value.trim()` даёт
  пустую строку, дальше та же ветка. Разъезда между двумя жестами нет; в поле при
  этом остаются сами пробелы, но это было и раньше.
- **Крестик при активном человеке сам по себе не нажимается** — кнопка живёт под
  `{#if value}`, а `byPerson` ставит `typed = ''`. Путь к находке 2 идёт только
  через набранный и брошенный текст (или Enter).
- **Строчные догрузки старой вкладки вреда не приносят:** `patch` ищет строку в
  `views`, а он пуст; своих каналов `views:*` смена запроса не касается.
- В `docs/deferred.md` записей, которые эта правка сделала бы неправдой, не
  нашлось.

Замечание не в счёт находок: `docs/front-map.md:17` числит в `App.svelte` 327
строк при нынешних 345 — карты перед коммитом пересобираются, `--check` это и так
уронит.
