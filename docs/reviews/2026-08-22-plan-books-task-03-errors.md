# Ревью: план books-and-music, задача 3 — «Адаптация интерфейса»

Измерение: настоящие поломки поведения в незакоммиченном рабочем дереве.
Диапазон: `git diff` на момент ревью (без `.claude/settings.json` — чужая правка,
не рассматривается).

## Что сделано хорошо

- **`WISHES`/`wishOf` и `LINKED`/`linkableOf`** — обе таблицы полные (все пять
  типов у `WISHES`, ровно три у `LINKED`), и обе имеют ровно двух читателей,
  как и написано в плане. Проверено поиском по всему `client/` — других мест,
  где могла бы понадобиться третья копия решения, нет.
- **`LINKED` сверен с бэкендом напрямую.** `backend/sources/registry.py`:
  `ROUTES[Kind.BOOK].catalogs == ()`, `ROUTES[Kind.MUSIC].catalogs == ()`, у
  `MOVIE`/`SERIES`/`GAME` — непусто. Новый тест
  `test_the_page_offers_a_link_field_only_where_a_catalog_exists` действительно
  вычисляет `with_catalog` из `ROUTES`, а не переписывает список руками — сторож
  настоящий, а не тавтологичный.
- **`Aggregates.svelte`: разметка под `{#if shown.length}` цела.** Открывающий
  и закрывающий теги `<div class="film__aggr">`/`</div>`, `{#each}`/`{/each}`,
  все внутренние `{#if}`/`{:else if}`/`{:else}`/`{/if}` на месте, отступ
  добавлен равномерно на два пробела по всему блоку — сверено построчно с
  версией до диффа.
- **`shown` для книг/музыки действительно пуст.** `expected` по умолчанию `[]`
  у `Aggregates`, `arrived` строится из `view.external`, которого для типов без
  источников оценки взяться неоткуда, — обе половины пустого множества сходятся
  с комментарием в коде.
- **`linker?.link(item_id)` в `CardModal.svelte` уже был с опциональной
  цепочкой** до этого слайса, и она ровно то, что нужно теперь: когда
  `linkableOf(form.kind)` ложно, `<LinkField>` не монтируется, `linker` остаётся
  `undefined`, и `write()` просто не пытается привязать — без исключения через
  границу. Единственный вызов `linker.link` в файле проверен явно.
- **`Acts.svelte`: `wish` ровно один читатель, `Film.svelte`, и там он всегда
  приходит из `wishOf(view.kind)`**, который покрывает все пять типов — других
  мест, создающих `<Acts>`, в проекте нет (проверено `grep`).
- **Разборщик `values_of` не задевает существующих потребителей.** У обоих
  прежних вызовов (`KINDS`, теперь ещё и `VIEWS`) первая `[` после
  `const ИМЯ = ` стоит там же, где раньше стоял литерал `= [` — новый `VIEWS`
  под `$derived([` тоже находится верно, проверено на самом файле.
- **Карты (`front-map.md`, `module-map.md`) отражают ровно то, что в диффе** —
  новые сигнатуры, новые размеры файлов, новая зависимость теста от
  `backend.sources.registry`.

Ни одной поломки поведения не найдено.

## Вердикт

**Готово к коммиту.** Все три места слайса (подпись раздела, пустой ряд
агрегаторов, условное поле ссылки) реализованы согласованно между собой,
проверены на всех вызывающих местах, а не только в диффе, и сверены с
бэкендом там, где план это требует (`LINKED` против `ROUTES`). Поломок,
которые не поймал бы прогон тестов, не найдено — но это уже не в измерении
этого ревью.
