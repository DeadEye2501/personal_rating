## Кандидаты

### 1. `SectionsRepository.histogram` против `SectionsRepository.ids` (общий `_narrow`)

Прочитаны оба метода и `_narrow`. Это не «один метод с флагом»: `_narrow`
уже и есть вынесенное общее (условия раздела, кино/игры, включённые и
исключённые признаки). Остальное расходится по форме запроса, а не по
значению параметра — `ids` строит `select(item.c.id)` с сортировкой и
пагинацией, `histogram` строит два разных агрегата (`GROUP BY` по столбцу и
отдельно `count`+`avg`) без пагинации вовсе. Слияние потребовало бы разбирать
внутри одного метода, какой из трёх разных `select` собирать. **Отклонён** —
это осознанное разделение поверх уже вынесенного общего, не повтор.

### 2. Главный вопрос: `func.avg(rating.c.score)` в `histogram` против `average_score` в `backend/model/rating.py`

Прочитаны оба места. Это разные дела, а не одно, посчитанное дважды:

- `average_score(*aspects)` — чистая функция в Python, усредняет **шкалы
  одной оценки** (visual/narrative/gameplay), причём заведомо не больше трёх
  чисел, и невыставленная шкала не в счёт. Зовётся один раз, из
  `RatingsRepository.set_aspects`, в момент, когда пишется `score` в базу.
- `func.avg(rating.c.score)` в `histogram` — SQL-агрегат, усредняет уже
  **готовые `score` многих карточек** (произвольное число строк, отобранных
  фильтром) для подвала гистограммы. Через API `average_score` в SQL и не
  выразить: он про поля одной записи, а не про строки таблицы.

Docstring `histogram` прямо объясняет, почему они не могут быть одним: если
считать среднюю по столбцам (округлённым `average_score` вниз до целого), она
занижается почти на полбалла у игр — ровно из-за того, что `average_score`
уже сделал своё усреднение раньше и по другому предмету. Тест
`test_the_average_is_not_collected_from_the_columns` это и проверяет.
**Отклонён** — разный предмет усреднения (шкалы одной оценки против оценок
многих карточек) и разный слой (модель на чистом Python против агрегата в
SQL).

### 3. `columns`/`make` в `tests/backend/test_histogram.py` против `an_item`/`card` (`tests/conftest.py`) и `make_item` (`tests/backend/test_library.py`)

Прочитаны все четыре. Расхождение содержательное:

- `an_item` (conftest) — собирает **незаписанный** `Item` в памяти.
- `card` (conftest) — пишет карточку через репозиторий, оценки не касается.
- `make_item` (`test_library.py`) — тоже незаписанный `Item`, но с другим
  набором полей под свои проверки; уже сверен с `card` в
  `docs/not-duplicates.md`.
- `make` (`test_histogram.py`) — пишет карточку **и** при непустом `score`
  тут же выставляет оценку через `RatingsRepository.set_score`; это
  единственный помощник, который делает оба шага вместе, и он существует
  ровно потому, что предмет проверок в этом файле — оценка, а не карточка
  сама по себе.
- `columns` — своя пара строке: превращает `Histogram` в `dict[int, int]`
  для удобства ассертов; такого нигде больше нет.

**Отклонён** — общее слово в имени (`make`) над разными предметами
(написанная в память запись против записи в базу плюс оценка), уже видимая
форма из «Похоже в тестах, но проверяет разное».

### 4. `dict.fromkeys(range(1, 11), 0)` / `range(1, 11)` против других шкал 1–10

Грепом по всему проекту (`backend`, `migrations`, `scripts`, `tests`):
второе появление в реальном коде — только внутри самого `sections.py` (два
раза в одном методе `histogram`, для наполнения нулями и для сборки

`catalog.py`) `rating.score` объявлен без `CHECK`-ограничения на диапазон, а
клиентские упоминания `range(1, 11)` — только в текстах планов
(`docs/plans/2026-07-27-client-shell.md`,
`docs/plans/2026-07-27-client-modals.md`), не в коде: клиент ещё не написан
(`client — 0 модулей` в `docs/module-map.md`). **Отклонён** — второй
реализации шкалы в коде не существует.

### 5. Фикстура `sections` в `tests/backend/test_histogram.py` против `tests/backend/test_sections.py`

Подтверждено чтением: тела дословно совпадают в обоих файлах —

```python
@pytest.fixture
async def sections(sessions):
    return SectionsRepository(sessions)
```

Разного смысла за именем нет: обе просто оборачивают `SectionsRepository` в
фикстуру без вариаций. Под исключения («один глагол над разными
предметами», «общее слово в имени») это не подходит — совпадают и глагол, и
предмет, и тело целиком. **Подтверждённый повтор.** Стоит вынести в
`tests/conftest.py`, рядом с фикстурой `sessions`, от которой она зависит;
из `test_sections.py` и `test_histogram.py` локальные объявления убрать.
