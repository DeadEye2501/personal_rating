# Ревью тестов — план 2, задача 11 (Кинопоиск, два зеркала)

Измерение: тесты слайса. Только чтение, мутаций не делал.

## Сильные стороны

- Главное правило слайса (код важнее тела) закреплено ровно так, как нужно:
  `test_a_quota_body_under_a_404_is_still_an_absence` подсовывает 404 с телом,
  которое по смыслу — квота (`statusCode: 403`, «Превышен дневной лимит!»), и
  ждёт `Missing`. Код (`poiskkino.py:75-88`) вообще не читает содержимое тела
  для классификации, только пытается его распарсить, — значит откат к
  «верить телу» на этом тесте гарантированно упадёт.
- Тест на срок отката квоты (`test_the_quota_closes_the_mirror_for_six_hours`)
  не сверяется с константой `QUOTA_BACKOFF` из того же модуля — использует
  независимые `timedelta(hours=5)` и `timedelta(hours=2)`, гранича с обеих
  сторон шестичасовой отметки. Это ровно то, что просило задание проверить
  (рекомендованное в п.3) — здесь чисто.
- В файле не нашлось ни одного теста, который сверял бы результат с
  константой (`FIELDS`, `BASE`, `QUOTA_BACKOFF`, `RATE_BACKOFF`), импортированной
  из проверяемого модуля кинопоиска, — везде независимые литералы.
- Различение зеркал по коду (403/402), а не по угадыванию, разложено по
  отдельным тестам с уважением к разным семантикам (`test_fallback_quota_has_its_own_code`
  с комментарием «не путать с 429 по частоте»).

## Находки

### Важно

1. `tests/backend/sources/test_kinopoisk.py:311-315` (внутри
   `test_a_refusal_switches_to_the_fallback`) и весь файл — ни один тест не
   проверяет поле `Refusal.source`. Оно жёстко прописано литералом `"kinopoisk"`
   в `backend/sources/ratings/kinopoisk/poiskkino.py` (строки 56, 59, 67, 71) и
   `unofficial.py` (48, 54, 57, 60). Опечатка вроде `"kinopoisk_primary"` не
   уронит ни один из 27 тестов.
2. Ни один тест не проверяет `Refusal.retry_after`. И у квоты, и у частоты
   (`poiskkino.py:56-57, 66-67`; `unofficial.py:47-48, 53-54`) поле выставляется,
   но нигде не сверяется со значением `QUOTA_BACKOFF`/`RATE_BACKOFF` — можно
   убрать аргумент вовсе, ни один тест этого не заметит.
3. `test_fallback_rate_limit_trips_its_breaker_too`
   (`tests/backend/sources/test_kinopoisk.py:228-242`) не проверяет исход
   первого вызова вовсе — только счётчик `calls == 1`. У парного теста для
   основного зеркала (`test_primary_rate_limit_trips_the_breaker_too`, строка
   111) есть `assert first.reason is Reason.RATE`, здесь такой строки нет.
   Слабее, но не критично: сам факт «предохранитель взвёлся» тест ловит, а
   вот подмену причины (`Reason.RATE` → `Reason.BROKEN` при взводе
   предохранителя) — нет.
4. Точная длительность `RATE_BACKOFF` (`limits.py:12`, 1 минута) нигде не
   проверяется через часы — в отличие от `QUOTA_BACKOFF`, у которого есть
   отдельный тест с `FakeClock`. Подмена на любое другое положительное
   значение пройдёт незамеченной.
5. Фактическое числовое значение оценки и идентификатора запасного зеркала
   на боевой фикстуре не проверяется: `test_fallback_rating_comes_with_the_search`
   (строки 193-201) проверяет только `source` рейтинга и truthy
   `external_ids`, но не `8.7` и не `"258687"` из `unofficial_found.json`.
   Не критично: подмена поля `ratingKinopoisk` на `ratingImdb` всё равно
   поймана — но не этим тестом, а `test_an_honest_zero_is_not_an_absence`
   (там у `ratingImdb` в теле попросту нет значения). Числовая порча именно
   идентификатора (`kinopoiskId`) на боевой фикстуре осталась бы незамеченной
   вовсе — ни один тест не сверяет его значение для запасного зеркала.

### Мелочь

6. `test_primary_survives_a_message_that_came_as_a_list`
   (строки 115-124) фактически дублирует проверку `reason is Reason.QUOTA` из
   `test_primary_quota_is_a_refusal_and_trips_the_breaker` — код нигде не
   читает поле `message`, поэтому странная форма (список вместо строки) на
   сегодняшний код никак не влияет, и тест прошёл бы одинаково с любым другим
   403-телом. Полезен как страховка от будущей регрессии (если код начнёт
   парсить `message`), но сегодня не отличает «умеет пережить список» от
   «просто 403».
7. `test_fallback_sends_the_key_in_the_header_and_keeps_the_tt_prefix`
   (строки 274-288) в текущем коде тоже не имеет «своей» строки для поломки —
   `unofficial.py:36` никак не трогает префикс `tt`, поэтому тест ловит только
   гипотетическую будущую порчу (как и было при мутационном прогоне —
   пункт 19 из списка). Отметил не как проблему, а как то же соображение, что
   и в находке 6.

## Проверка тестов (кратко, по требованию задания)

которая его роняет, кроме случаев из «Мелочь» (пункты 6–7 выше, где строки нет
— код и так не читает соответствующее поле) и находок 3–5, где отсутствует не

проверяемого модуля.

## Фикстуры

Рукописные (`poiskkino_found`, `poiskkino_not_found`, `poiskkino_quota`,
`poiskkino_message_list`, `unofficial_rate`, `unofficial_quota`) — все, кроме
`poiskkino_message_list`, воспроизводят задокументированные в спецификации
Кинопоиска случаи (коды и структура тел правдоподобны и соответствуют
`README.md`). `poiskkino_message_list` — единственная, где рукописное тело
проверяет, по сути, фантазию автора о форме поля `message`: она не привязана
ни к какому наблюдаемому в спеке случаю (README не даёт для неё источника
достоверности, в отличие от остальных пяти), и, как показано в находке 6,
сегодняшний код к её содержимому не чувствителен вообще — тест с ней не
отличается по покрытию от обычного 403. Не вредна, но и не подтверждена
ничем, кроме «а вдруг так придёт».
