## Находки

### Critical

**Задача 5, `test_aspects_answer_with_the_derived_score`.** Единственный тест
на `Marks.aspects`, и он не проверяет ни один аргумент вызова — только то, что
возвращённое число прошло насквозь:
```python
answers["ratings.set_aspects"] = 7.333333333333333
assert Marks(spy).aspects(12, 8, 7, 7) == {"ok": 7.333333333333333}
```
Поменяй местами `visual`/`narrative`/`gameplay`, забудь передать `item_id`
или не подставь время — тест останется зелёным: он сторожит только то, что
готовое значение вернулось назад. Переписать по образцу
`test_setting_a_score_carries_the_moment`: разобрать `log[0]` и проверить
`args[:4] == (12, 8, 7, 7)` и `args[4].year >= 2026`.

**Задача 5, `client/bridge/marks.py`: шесть методов вовсе без теста.**
`review`, `create_tag`, `delete_tag`, `assign`, `unassign`, `unwish` объявлены
в интерфейсе задачи, но ни в `test_bridge_marks.py`, ни где-либо ещё нет
теста, вызывающего их. Сторож поверхности (`test_bridge_surface.py`)
проверяет только то, что имя `tags.create`/`wishlist.remove` существует у
`Backend`, — не то, что мостовой метод передаёт туда правильные аргументы.
Перепутанный порядок доводов у любого из шести (например, `assign(item_id,
tag_id)` вызванный как `unassign(tag_id, item_id)`) пройдёт молча. Нужно
минимум по одному тесту на метод в стиле уже написанных для `score`/`wish`.

### Important

### Minor

- **Повторяющийся слабый довод `*.year >= 2026`** для проверки «момент
  подставил мост» (`test_setting_a_score_carries_the_moment`,
  `test_wishing_carries_the_moment`, `test_an_uploaded_picture_arrives_as_bytes`).
  Проходит для любой даты 2026 года и позже — не отличит `datetime.now()` от
  захардкоженного `datetime(2099, 1, 1)`. Не критично (перепутать реальный
  `datetime.now()` с константой — редкая ошибка), но усилить легко:
  `abs((datetime.now() - args[-1]).total_seconds()) < 5`.
- **Задача 1, `test_the_ancestor_does_not_catch_everything` и
  `test_a_closed_poster_store_is_not_a_denial`** читают `issubclass(...)`
  напрямую, а не через `pytest.raises`/`except`. В Python оба пути
  эквивалентны (диспетчеризация исключений и есть `issubclass`), поэтому это
  не чтение оторванного от поведения объявления в духе примера из скилла —
  но по духу правила 13 чище было бы обернуть в `pytest.raises`, как это
  сделано в соседнем параметризованном тесте того же файла.

## Свойства без стража

- **Соглашение об имени довода `back` в `client/bridge/*.py` и `serve.py`.**
  Плей сам признаёт хрупкость: «переименованный довод молча выключил бы
  проверку» (комментарий в `test_bridge_surface.py`). Единственная защита —
  `test_something_is_actually_collected` (`len(asked()) > 30`) — не поймает
  переименование в одном-единственном модуле, если остальные шесть доменов
  дают достаточно вызовов, чтобы перевалить порог. Порог общий, а не
  «нашлось хоть что-то в каждом файле».
- **`Marks.review`, `create_tag`, `delete_tag`, `assign`, `unassign`,
  `unwish`** — см. Critical выше; свойство «мост передаёт нужные аргументы»
  не проверено ни для одного из шести.
- **Задача 11, отдача обложки:** нет теста на случай, когда `library.get`
  возвращает карточку без `poster_url` (`None`) — какой код ответит,
  план не говорит и тест не проверяет; закрыто отчасти тестом «не приехала»,
  но тот идёт через `posters.poster_for` вернувший `None`, а не через
  отсутствующий `poster_url` до вызова.

## Вердикт

**Готов к работе?** С правками.
**Довод:** основной корпус (мост, поток, wire, answer, serve, surface) — крепкие
поведенческие тесты с корректной привязкой, лучшее в этом плане — сторож
поверхности через AST. Но один публичный метод (`aspects`) не проверяет свои
аргументы вовсе, а шесть методов `Marks` не проверены ни разу — до кода эти
два пункта стоит закрыть, иначе первая же реализация с перепутанными
аргументами тегов или закладок пройдёт весь набор зелёным.
