# Ревью: повторы по картам — план 3, задача 2 (подсказка при вводе имени)

Дата: 29.07.2026. Измерение — **повторы по всему проекту**, дифф не читался.
Источники: `docs/module-map.md`, `docs/data-map.md`, `docs/not-duplicates.md` и
чтение кода по каждому кандидату.

Пары из `docs/not-duplicates.md` пропущены.

## Вердикт

**Подтверждено два повтора.** Оба — не в новом коде слайса, а между старыми
файлами, которых слайс не касался: ровно то, чего не видит ни машинная проверка
дублей (она сравнивает только записываемый файл), ни слайсовое ревью.

Новое слайсом — `Suggestion`, `suggest`, `_hint`, `_linked`, `_folded_name`,
`_name_starts_with`, `person_with` — повторов не даёт: всё проверено чтением
против названных соседей, разборы ниже.

---

## Находка 1. «Строка в свой тип или `None`» написана трижды под тремя именами

Средняя серьёзность. У `Repository` есть `_mapped` — «много строк сразу в свои
типы», — а его единственного двойника нет, и каждый репозиторий пишет его сам.

- `backend/storage/repository/credits.py:79-81` — `CreditRepository._found_id`:

  ```python
  row = await self._row(statement)
  return row.id if row is not None else None
  ```

- `backend/storage/repository/library.py:61-63` — `LibraryRepository._one`:

  ```python
  row = await self._row(statement)
  return _to_item(row) if row else None
  ```

- `backend/storage/repository/ratings.py:50-63` — `RatingsRepository.get`: та же
  форма, но развёрнутая по месту (`if row is None: return None`), плюс сборка
  `Rating` прямо в теле метода — своего `_to_rating` у этого репозитория нет,
  хотя `_to_item`, `_to_genre`, `_to_credit` и `_named` есть у всех остальных.

Дело одно: прочитать одну строку и либо перевести её в свой тип, либо отдать
`None`. Расходятся только преобразователем, то есть ровно тем, что у `_mapped`
уже вынесено в параметр. От машинной проверки повтор укрыт длиной: тела короче
пяти инструкций она не сравнивает.

**Какое объявление должно остаться:** одно — в `backend/storage/repository/base.py`,
рядом с `_mapped` и с той же сигнатурой (`statement`, `make`). `_found_id` и
`_one` становятся вызовами и исчезают как отдельные объявления либо остаются
однострочными обёртками с говорящим именем; `RatingsRepository.get` зовёт то же
с вынесенным `_to_rating` — и заодно перестаёт быть единственным репозиторием,
собирающим свой тип внутри публичного метода.

Если исполнитель сочтёт, что три вызова не окупают ещё одного метода в базовом
классе, — это решение, и его место в `docs/not-duplicates.md` строкой с доводом,
а не в молчании: пары `_found_id` ≠ `_one` там сейчас нет, и следующий проход
найдёт её заново.

## Находка 2. Один и тот же момент времени объявлен дважды

Низкая серьёзность, но это ровно тот случай, ради которого ведётся карта данных:
в карте модулей повтор не виден вовсе.

- `tests/conftest.py:23` — `MOMENT = datetime(2026, 7, 29, 12, 0)`;
- `tests/backend/sources/test_convert.py:10` — `NOW = datetime(2026, 7, 29, 12, 0)`.

Значения совпадают дословно. Все остальные десять тестовых модулей берут момент
из `tests/conftest.py` — семь из них под псевдонимом `WHEN`, что повтором не
является (`import ... as`, одно объявление на всех). Своё объявление ровно одно —
в `test_convert.py`, и оно противоречит доводу, записанному в самом
`tests/conftest.py:19-22`: моменты, заводимые в каждом модуле заново, расходятся
значениями, ничего этим не проверяя.

**Какое объявление должно остаться:** `tests/conftest.py:MOMENT`;
`test_convert.py` импортирует его. Если импорт из корневого `conftest.py` в
тесты источников нежелателен нарочно (тесты источников не поднимают базу и своего
`conftest.py` в `tests/backend/sources/` не связывают с корневым), — довод годный,
но тогда он пишется строкой в `docs/not-duplicates.md`, а не остаётся устным.

## Проверено и отклонено — повтором не является

Ни одна из пар ниже в находки не идёт: подтверждено чтением обоих мест.

**`Suggestion` против датаклассов границы слоёв.** Ближайшие по составу —
`Genre(id, name, kind)` и пара `(int, str)`, которую отдают
`TagsRepository.list_for_kind`/`tags_of`. Совпадает только «номер строки плюс
имя» — общее слово в составе, а не общее дело: `Genre.kind` — закрытый набор из
двух значений, а `Suggestion` несёт `hint` и `hint_item_id`, то есть **чужую**
карточку, по которой человека узнают. С `Credit` не пересекается вовсе: у того
роль, позиция в титрах и идентичность в источнике, и он ходит в обе стороны, а
`Suggestion` — только наружу. С `SearchHit` и `Item` не сравнивается: те про
карточку, эта про человека.

**Три ступени `_hint` против `LibraryRepository.list_by_kind`,
`WishlistRepository.list_ids` и `RatingsRepository.get`.** Такого запроса в
проекте нет ни одного. Совпадает идиома `order_by(...).limit(...)`, и на этом
всё: `list_ids` отдаёт номера карточек из `wishlist` порциями (`limit`+`offset`),
`_hint` — одну строку с названием и номером карточки, добытую соединением через
таблицу связей конкретного человека; `list_by_kind` фильтрует по типу
содержимого и не соединяется ни с чем; `RatingsRepository.get` читает строку
оценки по ключу и собирает `Rating`, а `_hint` использует `rating.score` только
как порядок сортировки и саму оценку наружу не отдаёт.

**`suggest` против `find_by_name`.** Предикаты разные по существу — равенство
против префикса, — и результаты разные: номера всех тёзок против строк подсказки
с хинтами. Общее (`_rows`, `_folded_name`) уже вынесено внутри модуля.

**`_folded_name` и `_name_starts_with` против `LibraryRepository.find_by_title`.**
Пара «сравнение регистра у имени против названия» уже разобрана в
`docs/not-duplicates.md` (`find_by_name` ≠ `find_by_title`), и довод после этого
слайса не изменился, а окреп: `credits.py` идиому у себя как раз **свернул** — три
её потребителя (`_same_name`, `_name_starts_with` и через них `find_by_name`,
`find_anonymous_by_name`, `suggest`) ходят через одно объявление `_folded_name`.
В `library.py` остаётся одно вхождение (`find_by_title`, две колонки через `|`
плюс фильтр по `kind`), то есть второго появления одного и того же кода в
проекте больше нет — есть два разных применения общей функции `fold`/`py_lower`,
которая и является здесь вынесенным общим (`backend/storage/session.py:14,29`).

**`_linked`.** Строитель `Select`, общий для трёх ступеней `_hint`; ничего
похожего в проекте нет — остальные репозитории собирают запрос по месту, потому
что переиспользовать его внутри модуля некому.

**`person_with` против фикстур и помощников других тестовых модулей.**
`tests/conftest.py:card` заводит карточку, `person_with` — человека и его связи
с уже готовыми карточками; предметы разные. С `test_delete.py:furnished`
совпадает только форма «навесить на готовое»: тот вешает оценку, тег, закладку и
постер (проверяется удаление), этот — роли на списке карточек. С
`test_library.py:in_both_stores` общего нет. В `tests/backend/test_credits.py`
похожего помощника нет и быть не может: тамошним тестам нужны именно разные
способы завести человека (`create` против `create_manual`, с идентичностью и
без, с позициями и ролями), а `person_with` жёстко берёт `create_manual` и
`PersonRole.DIRECTOR`. Один потребитель — один модуль; в `conftest.py` ему рано.

**`suggest` против `Repository._mapped`.** Не повтор и не пропущенное
переиспользование: `_mapped` зовёт `make(row)` синхронно, а `_hint` —
корутина, и по строке она ходит в базу ещё раз.

**`KinopoiskClient.ratings` против `_hint`.** Обе «берут первое, что ответило»,
но у зеркал перебор идёт по типу исхода (`isinstance(..., Refusal)`) и живёт в
слое источников, у подсказки — по наличию строки в трёх разных запросах слоя
данных. Общий глагол, разные предметы и разные слои.
