# Вопросы по плану 9

Что решено не мной и ждёт слова пользователя. Работа на этих местах не
останавливалась: сделано по названному здесь допущению, и переделка каждого —
недорогая.

## 1. Подсказка у ролей-одиночек против раскладки макета

**Открыт.** Задача 2, `client/app/CardModal.svelte`.

**Как в макете.** Режиссёр, шоураннер, разработчик и издатель — обычные поля в
правой колонке, рядом с годом и длительностью (`docs/design/index.html:1709-1728`).
Подсказка есть только у актёров и жанров: `createPicker` в макете зовётся ровно
дважды.

**Как сделано.** Все пятеро — поля с подсказкой, и потому уехали из колонки в
свои широкие строки под постером.

**Почему так.** Спека людей (`docs/specs/2026-07-27-people.md`) требует жеста
различения полных тёзок для **человека**, а не для актёра: «поле ввода одно, и в
нём два разных жеста». Обычное поле такого жеста не даёт — режиссёра пришлось бы
искать по имени, то есть ровно тем способом, который спека запрещает. Макет тут
черновик: его подсказка работает на рыбе из списка строк, где тёзок нет вовсе.

**Чем это стоило.** Раскладка изменилась: у окна на одну широкую строку больше,
синопсис вырос со 165 до 225 пикселей, у игры разработчик с издателем встали
столбиком, а не в строку.

**Если решение обратное** — вернуть четыре поля в `.cardform__fields` рядом с
годом, оставив подсказку актёрам и жанрам. Правка в одном файле, `Picker` при
этом не меняется.

## 2. Как зовётся выбранная строка внутри формы

**Открыт, но неспешно** — упрётся в задачу 4, где форма пойдёт на запись.

Поле с подсказкой отдаёт выбранное парой `{ id, name }`, и `id` там нейтрален
нарочно: тем же полем выбирают жанр, у которого никакого `entity_id` нет. Со
стороны базы номер человека зовётся `entity_id` (`Credit.entity_id`,
`Suggestion.entity_id`).

Разойдутся имена молча: запись просто не увидит номера и заведёт человека заново
на каждое сохранение. Сторожа у этой пары сегодня нет ни одного — он появится
вместе с самой записью.
