# Четвёртая вкладка «Книги» — разведка

21.08.2026. Кода не тронуто ни строки, решений не принято ни одного. Здесь
только то, что найдено в коде и замерено; развилки названы развилками.

Разведка шла тремя агентами по измерению: тип содержимого в питоне и схеме, тип
содержимого во фронте, цена нового источника.

## Короткий ответ

Возможность есть, и архитектура ей не мешает: **тип содержимого вшит
неглубоко**. База не знает о нём ничего, мост прозрачен целиком, хранилище и
большинство сервисов держат `kind` как значение фильтра, а не разбирают его.

Дорого не в коде, а в двух других местах: **данных о книгах взять неоткуда без
нового источника**, и **модель книгу не описывает** — нет автора как роли, нет
страниц, нет ISBN.

По объёму это **отдельный план размером с план 13**, а не слайс: ~600–900 строк
боевого кода и ~900–1200 строк тестов (~70–90 тестов), плюс 14–16 файлов фронта
и до 13 файлов его тестов.

## Что не мешает вовсе

**База не знает про типы.** `kind` — `sa.Text(), nullable=False` в четырёх
таблицах: `item` (`migrations/versions/0001_schema.py:38`), `genre` (`:32`),
`tag` (`:67`), `removed` (`:140`, там он ещё и в первичном ключе). Ни одного
`CheckConstraint`, ни одного `sa.Enum` — проверено поиском по `migrations/` и
`backend/storage/`. Строка `"book"` ложится как есть, **миграции ради самого
типа не нужны**.

**Мост прозрачен целиком.** В `bridge/` нет ни одного сравнения `Kind` со
значением — только конструирование из строки: `bridge/feed.py:35,43`,
`library.py:46,67,102`, `marks.py:36,39,42`, `search.py:60,75,81`,
`world.py:70,107,134`, `refs.py:22`. Четвёртое значение проедет без правок.

**Хранилище и сервисы** держат `kind` как значение фильтра:
`storage/repository/sections.py:186-195`, `library.py:61,73,92,109`,
`credits.py:202`, `tags.py:33,41`, `removed.py:31,51`.

**`backend/app.py` не ветвится по типу ни разу.** `Kind` появляется только в
подписи `restore_removed` (`:102`).

**Капсула вкладок обобщена.** `client/components/Segmented.svelte:8-17` —
`{#each items}`; `client/styles/seg.css:7-13` — `grid-auto-flow: column;
grid-auto-columns: 1fr`. Четвёртая кнопка просто добавит колонку.

**Реестр источников рассчитан на добавление.** Существующие клиенты не
трогаются: контракт держится утиной типизацией (`search(query, kind)`,
`card(source_id, kind)`, `name`, `aclose`), а сторожит его
`tests/backend/sources/test_registry.py` через `inspect.signature` — имена
параметров сверяются буквально.

## Что мешает

### 1. Один файл, где ветка по умолчанию врёт

`backend/sources/registry.py` — три метода написаны как «игра или всё
остальное», и `else` молча заберёт книги себе:

| Место | Что сделает с книгой |
|---|---|
| `catalog_for:45-47` | отправит искать в TMDB |
| `people_for:54` | даст поиск по людям через TMDB |
| `rating_sources:69-71` | пойдёт спрашивать оценки в MDBList, OMDB, Кинопоиск |

Дальше по этому пути `backend/sources/tmdb/parse.py:113-116` — словарь `_KEYS`,
индексируемый **без `.get`** (`:123`), то есть `KeyError` на четвёртом типе.

Это три обязательные правки, и они содержательные, а не механические.

### 2. Данных о книгах нет — нужен источник

Ни один из семи нынешних клиентов книг не знает. Бесплатные варианты, найденные
поиском по вебу 21.08.2026. **Живьём не мерялся ни один** — это отдельная
работа, как день замеров перед планом 13.

| Источник | Ключ | Замечание |
|---|---|---|
| Open Library | не нужен вовсе | поиск, авторы, обложки; просят кешировать и слать свой `User-Agent` |
| Google Books | свой бесплатный, 10 000 запросов в день | без ключа квота общая на всех пользователей мира |
| FantLab | — | по-русски, но только фантастика; API в статусе v0.9, «выходы могут заметно меняться» |

**Оценок агрегаторов для книг практически нет:** Goodreads закрыл выдачу ключей
в 2020, у LiveLib публичного API нет. То есть ряд агрегаторов на книжной
карточке будет пуст, и это надо либо принять, либо прятать.

### 3. Модель книгу не описывает

`SourceCard` (`backend/model/card.py`) и вложенный `Item`
(`backend/model/item.py`):

| Поле | Для книги |
|---|---|
| `title`, `original_title`, `year`, `released_at`, `synopsis`, `poster_url` | подходят как есть |
| `genre_ext_ids` | подходит, но нужен свой справочник и правила |
| `people` | **роль не влезает**: `PersonRole` = DIRECTOR / ACTOR / SHOWRUNNER, автора нет |
| `companies` | издательство ложится в `PUBLISHER`, `DEVELOPER` остаётся пустым |
| `external_ids` | `IdSource` = IMDB / KINOPOISK / STEAM / GOG, ISBN добавлять |
| `ratings` | `RatingSource` без книжных |
| `runtime` | **нет** — поле подписано минутами, страницы туда класть нельзя |
| `seasons_count`, `episodes_count` | нет, только сериал |

Чего нет вовсе: автора как роли, ISBN, числа страниц, цикла или серии, языка
оригинала, переводчика. Каждое новое поле — миграция плюс
`backend/storage/rows.py`, `backend/model/view.py` (`CardView`), мост и карточка
на экране.

### 4. Третий набор жанров

Сегодня наборов два — `GenreKind.FILM` и `GAME` (`backend/model/kinds.py:65-69`),
25 и 19 имён (`migrations/reference/names.py:7-13` и `:15-20`). Правила перевода
чужих меток — ~475 строк на четыре источника (`migrations/reference/tmdb.py`,
`steam.py` 252 строки, `gog.py` 134, `old_games.py`).

Заливка справочника — `migrations/versions/0002_genres.py`, и **`:39` —
единственное место в миграциях, где оба набора перечислены разом**:
`for kind, names in (("film", FILM), ("game", GAME))`.

Сторожа, которые покраснеют: `tests/backend/test_genre_reference.py:27,35,74-88`
и особенно `:228-234` — `test_film_and_game_sets_never_mix` с зашитым SQL
`WHERE (r.source = 'tmdb') = (g.kind = 'film')`.

**Отображения `Kind → GenreKind` в питоне нет вовсе** — оно живёт только на
клиенте, `client/state/genres.js:6`, а мост принимает уже готовую строку
(`bridge/refs.py:22`).

### 5. Ширина окна посчитана под три подписи

Капсула обобщена, а раскладка вокруг неё — нет:

- `client/app/Topbar.svelte:34-54` — `ResizeObserver` ставит
  `--side-w = seg.offsetWidth` и `--content-w = seg.offsetWidth * 3 + gap * 2`;
- `client/styles/topbar.css:1-32` — `--side-w: 370px` запасом, с комментарием
  «367 на капсулу по её подписям»;
- `client/styles/palette.css:44` — `--content-w: 1146px`;
- `bridge/window.py:24-29` — `MIN_WIDTH = 1200`, выведен из тех же 367 px.

Четвёртая вкладка расширит капсулу, а вместе с ней обе боковые зоны: минимум
окна уйдёт примерно к 1500 px. Не пересчитав — на минимальном окне обрежется
правый ряд кнопок.

## Развилки, которые принадлежит закрыть пользователю

**1. Правило «миграции не наслаиваются» упирается в боевую базу.** Оно принято
02.08.2026 с оговоркой «пока в базе нет ничего, что жалко потерять». Сейчас в
базе настоящие оценки, а справочник жанров правится в `0002_genres.py`, которая
уже применена. Либо новая ревизия вопреки правилу, либо снос базы вместе с
оценками, либо третий путь — правка справочника кодом на старте, как сделан
пересчёт шкалы.

**2. Шкала оценки книги.** У игры три стороны — колонки `visual`, `narrative`,
`gameplay` в таблице `rating` (`0001_schema.py:146-157`,
`backend/model/rating.py:20-22`); у кино одна. Средняя считается в
`storage/repository/ratings.py:55-72`, и комментарий `:63-64` прямо говорит, что
правило зависит от `item.kind`, которого в таблице нет. От ответа зависит, нужна
ли миграция таблицы оценок.

**3. Что делать с пустым рядом агрегаторов** — книжных источников оценки нет.

**4. Роль «автор»** — новое значение `PersonRole`. Миграции не требует (`role`
тоже текстовый), но требует правки `storage/repository/credits.py` и ролей в
интерфейсе.

**5. Поля, которых нет:** страницы, ISBN, цикл. Каждое — миграция плюс четыре
звена до экрана. Или не заводить вовсе и обойтись общими.
