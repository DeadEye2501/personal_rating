# Структура кода

Как разложены папки и файлы и какие правила это раскладывание держат.

## Верхний уровень

Три части: **бэкенд**, **клиент**, **тесты**.

```
personal_rating/
├─ main.py                собирает зависимости и поднимает окно
├─ migrations/            alembic
├─ backend/
│  ├─ config.py           ключи из .env и пути к файлам
│  ├─ model/              типы границы: Item, Rating, SearchHit, Credit…
│  ├─ storage/
│  │  ├─ session.py       движок и фабрика сессий
│  │  ├─ tables/          объявления таблиц
│  │  ├─ repository/      library, ratings, tags, wishlist, genres
│  │  └─ posters.py       вторая база: картинка по хешу URL
│  ├─ sources/
│  │  ├─ http.py          общий клиент: таймауты, откат, предохранитель
│  │  ├─ errors.py        единая классификация отказов
│  │  ├─ tmdb/            client.py + parse.py
│  │  ├─ steam/
│  │  ├─ gog/
│  │  └─ ratings/         mdblist, omdb, kinopoisk
│  └─ service/            search, library, rate, enrich
├─ client/
│  ├─ theme/              палитра, шкала оценок, типографика, отступы, иконки, qss
│  ├─ widgets/            карточка, лента, звёзды, чип, каркас модалки
│  ├─ pages/              search, rated, wish, stats
│  ├─ window.py           окно, шапка, переходы между страницами
│  └─ runtime.py          стык asyncio с циклом Qt
└─ tests/
   ├─ backend/
   └─ client/
```

## Правила

**Зависимость строго в одну сторону: `client → backend → ничего`.** Проверяется
тестом: `backend` нигде не импортирует `client`, `client` нигде не импортирует
`sqlalchemy` и `httpx`. Разделение слоёв перестаёт быть договорённостью, о
которой можно забыть через полгода.

**Типы границы лежат в `backend/model/`.** Клиент импортирует их напрямую.
Отдельный третий пакет рядом с `backend` и `client` не заводим: бэкенд эти типы
производит, он же ими и владеет.

**Каждый источник — своя папка из двух файлов.** `client.py` разговаривает по
сети, `parse.py` переводит чужой JSON в наши типы. Седьмой источник добавляется
новой папкой, ни один существующий файл не трогается.

Общие `http.py` и `errors.py` есть с самого начала — не в ожидании второй
реализации, а потому что источников уже шесть.

Исключение одно: **у Кинопоиска в папке два клиента.** Зеркала отдают одни и те
же данные под одним идентификатором, и наружу это один источник — просто с
запасным путём, когда основное зеркало отказало.

**Страницы разделов — тонкие.** `search`, `rated` и `wish` показывают одну и ту
же ленту, отличаясь только тем, что спрашивают у бэкенда и в каком порядке.
Виджет ленты и карточка живут в `widgets/` и об этих различиях не знают.

**Виджет не знает, откуда данные.** Звёзды получают число, карточка — готовый
объект; загрузкой занимается страница. Виджет, импортирующий сервис, лежит не
там.

**`theme/` — единственное место, где есть цвет.** Десять цветов шкалы оценок
уже живут в макете одним объявлением и используются в фильтре, на звёздах и в
гистограмме. В чистовике так же.

**Папки `utils` нет.** Логирование настраивается в `main.py`, оба слоя берут
логгер по имени модуля.

## Файлы на диске

**Всё лежит рядом с программой** — база, хранилище постеров, лог. Приложение
переносится копированием папки вместе со всеми оценками.

```
data/
├─ library.db      основная база
├─ posters.db      хранилище постеров
└─ app.log         лог, 5 МБ на файл, три файла по кругу
```

Путь переопределяется переменной `DATA_DIR` в `.env`: в `Program Files` Windows
писать не даст, и на этот случай нужен запасной выход.

## Оформление и ресурсы

**Токены объявлены в Python, стили лежат в файлах `.qss`.** В самом QSS
переменных нет, поэтому файлы пишутся с подстановками вида `{surface}`, которые
подставляются при запуске. Цвет объявлен один раз, а не повторён шестнадцатью
шестнадцатеричными значениями по файлам.

Шкала оценок из десяти цветов собирается циклом, как и в макете, где имя
переменной строится из значения.

**Шрифт Material Symbols и иконки лежат файлами в `client/theme/assets/`** и
подключаются при старте. Система ресурсов Qt не используется: она требует
отдельного шага компиляции при каждом изменении, а выигрыша здесь не даёт —
упаковка решается на этапе сборки исполняемого файла.

Правило «контур в покое, заливка во включённом состоянии» держится на оси `FILL`
переменного шрифта. Если ось не заведётся в Qt, ставим два статических
начертания — само правило от этого не меняется.
