# План: список убранного и снятие пометки

Спека — `docs/specs/2026-08-03-removed-list.md`: там решения пользователя
дословно, закрытый список из шести слов и то, что именно восстанавливается.

**Что делаем.** Шесть слов в строке поиска показывают список убранного этой
вкладки; у каждой строки кнопка `restore`, которая снимает пометку. Карточка при
этом не возвращается — её нет.

## Развилка, которую надо решить до кода

**Кто решает, что набранное слово — команда, а не название.**

Правило 10 манифеста: логика не живёт в интерфейсе. «Строка `deleted` означает
показать убранное» — логика, и странице её отдавать нельзя. Значит решает
бэкенд.

Тогда встаёт второе: **чем ответ отличается от обычной выдачи**, чтобы страница
нарисовала свёрнутые карточки с `restore` вместо обычных.

Три выхода:

1. **Отдельный вызов моста** — `removed.listing(kind)`. Чисто, но страница
   должна знать, **когда** его звать, то есть логика всё равно уезжает в
   интерфейс.
2. **Признак в ответе поиска** — тот же вызов, результат помечен «это
   убранное». Страница ветвится по признаку, а не по строке; знание остаётся в
   бэкенде.
3. **Свой тип ответа** — поиск возвращает либо выдачу, либо список убранного.
   Честнее по смыслу, дороже по границе: мост переводит значения вручную, и
   новый тип надо провести и через него, и через сторожа поверхности.

**Выбран второй.** Он единственный держит правило 10 без нового типа на границе:
страница спрашивает поиск как обычно и ветвится по одному полю ответа.

## Что придётся завести

**В хранилище.** У `RemovedRepository` есть `remember` и `known`; нужны ещё два:
перечисление убранного по типу содержимого и снятие пометки по тройке.

**В сервисе поиска.** Ветка «строка — команда»: приведение строки, сверка с
шестёркой, ответ из хранилища вместо похода в источники. Сеть при этом не
трогается вовсе.

**В мосте.** Снятие пометки — новая ручка. Номер операции ей не нужен: это
запись, а записи не отменяются, как оценки и теги.

**На странице.** Свёрнутая карточка без разворота: слева название, справа
`restore`.

## Места, где легко ошибиться

1. **`ё` не сводится к `е` сама.** Общее приведение названий пропускает её
   наравне с прочими буквами, значит «удалённые» и «удаленные» — разные строки.
2. **Сравнивается вся строка целиком.** Вхождение слова означало бы, что игра с
   `deleted` в названии перестала искаться вовсе — тихо.
3. **Вкладка сужает.** Во вкладке фильмов только убранное кино: вкладка у нас
   первичный фильтр везде.
4. **Ручных карточек тут не бывает.** `remember` выходит на `Source.MANUAL`
   первой строкой, так что список для них всегда пуст — это свойство, а не
   недоделка.
5. **Снятие пометки не воскрешает карточку.** Ни оценки, ни тегов, ни закладки:
   их нет. Игра просто снова находится поиском.
6. **Своя половина поиска.** Строка идёт и в `local`, и в `external`. Команда
   обязана перехватить обе — иначе рядом со списком убранного покажется ещё и
   своя выдача по слову «удалено».

## Шаги

- [ ] **Шаг 1. Хранилище.** Перечисление и снятие пометки, тесты до кода.
- [ ] **Шаг 2. Ветка в поиске.** Приведение строки, шестёрка слов, признак в
      ответе. Тесты до кода, включая «игра с `deleted` в названии ищется как
      обычно».
- [ ] **Шаг 3. Мост.** Ручка снятия, сторож поверхности.
- [ ] **Шаг 4. Страница.** Свёрнутая карточка с `restore`, ветвление по
      признаку.
- [ ] **Шаг 5.** Прогон, живая проверка, карты, ревью, коммит.

## Чего этот план не делает

Не возвращает удалённые карточки — их нет. Не заводит ручку «показать убранное»
нигде, кроме строки поиска: точка входа одна.
