# План 10. Поставка

> **Исполнителю:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ — `superpowers:subagent-driven-development`
> или `superpowers:executing-plans`. Шаги помечены чекбоксами (`- [ ]`) для отметки
> хода работ.

**Цель:** приложение уезжает одним `.exe`, который запускается на машине, где
нет ни Python, ни Node. После этого плана проект закончен.

**Архитектура:** цепочек выпуска две — сборка фронта, затем PyInstaller, — и это
принято ценой ещё при выборе стека. Всё, что первая положила в `client/dist`,
вторая кладёт в бандл; путь к ним при заморозке идёт через `sys._MEIPASS`.

**Стек:** плюс одна зависимость разработки — PyInstaller. В приложение она не
уезжает.

## Глобальные ограничения

Действуют на каждую задачу, повторять в них не нужно.

- **Зависит от планов 5–9.** Приложение работает целиком из исходников.
- **Проверять надо собранное, а не исходники.** Половина того, что чинится в
  этом плане, из-под `python main.py` не видна вовсе: пути внутри бандла,
  отсутствие рантайма WebView2, права на запись рядом с программой.
- **Схему поднимают миграции, а не код.** В собранном приложении это остаётся
  правдой, и как именно — решает задача 3.
- **Комментарий объясняет неочевидное решение и пишется коротко.**

### Задача 1: Путь к странице при заморозке

Первое, что ломается в собранном приложении, и ломается молча: страница не
находится, окно белое, в логе ничего.

**`sys._MEIPASS` — это папка, куда PyInstaller распаковал бандл.** Относительные
пути от неё и разворачиваются, поэтому фронт в бандле должен лежать по тому же
относительному пути, что и в разработке.

**До этого плана `sys._MEIPASS` в коде не было намеренно:** ветка без
сегодняшнего потребителя не пишется, а потребитель у неё появляется ровно здесь.

**Файлы:**
- Изменить: `bridge/serve.py`, `tests/bridge/test_serve.py`

**Интерфейсы:**
- Потребляет: ничего нового.
- Отдаёт: `WEB_ROOT` считается функцией, а не константой модуля.

- [ ] **Шаг 1: Написать падающий тест**

Дописать в `tests/bridge/test_serve.py`:

```python
def test_the_page_is_looked_for_inside_the_bundle(monkeypatch, tmp_path):
    """Под PyInstaller корень другой, и не угадать его значит белое окно без
    единой записи в логе."""
    monkeypatch.setattr(sys, "_MEIPASS", str(tmp_path), raising=False)

    assert web_root() == tmp_path / "client" / "dist"


def test_without_the_bundle_the_page_lies_next_to_the_sources(monkeypatch):
    """Из-под `python main.py` путь обязан остаться прежним."""
    monkeypatch.delattr(sys, "_MEIPASS", raising=False)

    assert web_root().parts[-2:] == ("client", "dist")
```

- [ ] **Шаг 2: Прогнать и увидеть красное**

Запустить: `pipenv run pytest tests/bridge/test_serve.py -v`
Ожидание: FAIL, `ImportError: cannot import name 'web_root'`.

- [ ] **Шаг 3: Считать корень**

В `bridge/serve.py` заменить константу функцией:

```python
def web_root() -> Path:
    """Под PyInstaller бандл распакован во временную папку, и относительные пути
    разворачиваются от неё. В разработке корень лежит рядом с исходниками."""
    bundle = getattr(sys, "_MEIPASS", None)
    base = Path(bundle) if bundle else Path(__file__).resolve().parent.parent
    return base / "client" / "dist"
```

и `Page.__init__` берёт `root=None` со значением по умолчанию из `web_root()` —
считать его при импорте нельзя, `_MEIPASS` появляется позже.

- [ ] **Шаг 4: Прогнать и увидеть зелёное**

Запустить: `pipenv run pytest tests/bridge/ -v`
Ожидание: PASS.

```bash

git commit -m "feat: путь к странице внутри бандла"
```

### Задача 2: Сборка в один файл

**Хук pywebview подхватывается сам** — он объявлен точкой входа `pyinstaller40`
в метаданных пакета, и `--additional-hooks-dir` дописывать не нужно. Кладёт он
`webview/lib/*` (интеропные обёртки WebView2), динамические библиотеки и
`webview/js/*` — без последнего мост не инъецируется вовсе.

**Чего хук не делает и что придётся дописать самим:** собранный фронт,
`pythonnet` с `clr`, миграции и `alembic.ini`.

**Рантайм WebView2 библиотека не несёт.** В `lib/` только обёртки; сам движок
либо стоит в системе Evergreen-рантаймом, либо кладётся рядом fixed-version. Если
его нет, приложение молча уедет на MSHTML — ровно та беда, из-за которой отброшен
Qt, и ловит её проверка рендерера из плана 5.

**Файлы:**
- Создать: `personal_rating.spec`
- Изменить: `Pipfile`, `.gitignore`

**Интерфейсы:**
- Потребляет: `client/dist` от `npm run build`.
- Отдаёт: `dist/PersonalRating.exe`.

- [ ] **Шаг 1: Поставить сборщик**

```bash
pipenv install --dev pyinstaller
```

Версию закрепить тем же порядком, что и `ruff`: незакреплённая мажорная меняет
поведение сборки, а «собирается» — это то же самое обещание, что и «чисто».

- [ ] **Шаг 2: Открыть `.spec` от общего правила**

В `.gitignore` строка `*.spec` закрывает и файл сборки. Заменить на точечное:

```
# Артефакты PyInstaller, кроме самого описания сборки
build/
dist/
*.exe
!personal_rating.spec
```

Проверить `git check-ignore -v personal_rating.spec` — файл обязан
**не** игнорироваться.

- [ ] **Шаг 3: Написать описание сборки**

Создать `personal_rating.spec`:

```python
# Сборка одним файлом. Хук pywebview подхватывается сам — он объявлен точкой
# входа в метаданных пакета и кладёт webview/lib, webview/js и обёртки WebView2.

a = Analysis(
    ["main.py"],
    datas=[
        # Собранный фронт. Путь в бандле обязан совпасть с путём в разработке:
        # `sys._MEIPASS` разворачивает относительные пути от себя.
        ("client/dist", "client/dist"),
        # Схему поднимают миграции, и без них первый запуск даёт «no such
        # table: item».
        ("migrations", "migrations"),
        ("alembic.ini", "."),
    ],
    # pythonnet тянется за pywebview на Windows ради WinForms, но своего хука у
    # него нет.
    hiddenimports=["clr"],
    noarchive=False,
)

pyz = PYZ(a.pure)

exe = EXE(
    pyz, a.scripts, a.binaries, a.datas,
    name="PersonalRating",
    console=False,          # окно консоли за приложением не нужно
    upx=False,              # сжатие ломает подпись обёрток WebView2
)
```

- [ ] **Шаг 4: Собрать**

```bash
cd client && npm run build && cd ..
pipenv run pyinstaller personal_rating.spec --noconfirm
```

Ожидание: `dist/PersonalRating.exe`.

### Задача 3: Первый запуск на чистой машине

Половина того, что чинится здесь, из-под исходников не видна вовсе.

**Файлы лежат рядом с программой.** База, хранилище постеров и лог — в `data/`
рядом с `.exe`; приложение переносится копированием папки вместе со всеми
оценками. Путь переопределяется `DATA_DIR`: в `Program Files` Windows писать не
даст, и на этот случай нужен запасной выход.

**Ключи API в бандл не уезжают.** `.env` лежит рядом с `.exe` и читается оттуда;
без него работает всё, кроме внешних источников, — то есть ровно та граница,
которая записана в проекте.

**Файлы:**
- Изменить: `main.py`, `CLAUDE.md`

**Интерфейсы:**
- Потребляет: ничего нового.
- Отдаёт: `base_dir()` — папка, рядом с которой лежат данные.

- [ ] **Шаг 1: Считать папку данных от `.exe`, а не от бандла**

В `main.py` `BASE_DIR` сейчас — папка исходника. Под PyInstaller это временная
распакованная папка, и база с логом уехали бы туда, а после закрытия исчезли
вместе с ней.

```python
def base_dir() -> Path:
    """Данные лежат рядом с программой, а не внутри бандла: бандл — временная
    папка, и всё записанное в неё пропадает при закрытии."""
    if getattr(sys, "frozen", False):
        return Path(sys.executable).resolve().parent
    return Path(__file__).resolve().parent
```

и `load_dotenv(base_dir() / ".env")` вместо поиска по текущему каталогу: у
запущенного двойным щелчком `.exe` текущий каталог — не его собственный.

- [ ] **Шаг 2: Поднять схему при первом запуске**

Из чистого клона схему поднимает `alembic upgrade head`, и это записано в
`CLAUDE.md`. У собранного приложения такой команды нет, а без схемы первый же
запрос даёт «no such table: item».

Ветка одна и в `main.py`: миграции прогоняются программно перед поднятием окна.
Довод, по которому это не противоречит правилу «схему поднимают миграции, а не
код»: миграции её и поднимают — меняется только то, кто их зовёт, а не что
исполняется.

- [ ] **Шаг 3: Проверить на машине без Python**

Скопировать `dist/PersonalRating.exe` и `.env` в пустую папку на машине, где нет
ни Python, ни Node, ни исходников проекта, и запустить.

Проверить по списку:

- окно открывается, страница на месте, шрифты местные — оформление не поехало;
- в `data/app.log` **нет** записи про рендерер: значит рисует `edgechromium`, а
  не MSHTML;
- рядом с `.exe` появилась `data/` с `library.db`, `posters.db` и `app.log`;
- поиск находит и заводит карточку;
- закрытие окна не оставляет висящего процесса в диспетчере задач;
- повторный запуск видит вчерашние оценки.

Отдельно — **на машине без рантайма WebView2**: в логе обязана быть запись
уровня CRITICAL про подменённый рендерер. Молчание тут хуже отказа: приложение
просто выглядело бы сломанным.

- [ ] **Шаг 4: Записать, как собирать**

В `CLAUDE.md`, раздел «Окружение», дописать обе цепочки:

```powershell

cd ..; pipenv run pyinstaller personal_rating.spec --noconfirm
```

Без этого из чистого клона собрать `.exe` сможет только тот, кто уже собирал.

## Самопроверка плана

**Покрытие.** Спека клиента, «Сборка и поставка» — целиком: один `.exe`,
`sys._MEIPASS`, страница по HTTP, две цепочки выпуска, проверка рендерера после
запуска. `code-structure.md`, «Файлы на диске» — задача 3: `data/` рядом с
программой, `DATA_DIR` как запасной выход.

**Что этот план сознательно не делает.** Установщика нет, автообновления нет,
подписи нет, fixed-version рантайма WebView2 в комплекте нет — ничего этого в
спеках не описано, и придумывать здесь нечего. Если рантайма на машине не
окажется, приложение скажет об этом в лог; что делать дальше — вопрос к
пользователю.

**Чем измеряется готовность.** `.exe` запускается на машине без Python и Node,
находит и заводит карточку, переживает перезапуск и не оставляет процессов.
