# План 4. Чтение: поиск, загрузка, лента

> **Исполнителю:** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ — `superpowers:subagent-driven-development`
> или `superpowers:executing-plans`. Шаги помечены чекбоксами (`- [ ]`) для отметки
> хода работ.

**Цель:** бэкенд отвечает на всё, что спрашивает интерфейс. Поиск идёт по своей
базе и по внешней, кандидат превращается в карточку тремя кругами загрузки,
оценки агрегаторов доливаются фоном, разделы отдают ленту с фильтрами и
сортировкой, статистика — гистограмму. После этого плана бэкенд закончен: плану 5
остаётся только окно.

**Архитектура:** два репозитория чтения и четыре сервиса. Репозитории отвечают на
вопросы «какие карточки» (`sections.py`) и «что в них показывать»
(`views.py`) — разделены потому, что первый знает про фильтры и порядок, а второй
про состав карточки, и меняются они по разным поводам. Сервисы оркеструют:
`search.py` склеивает две выдачи, `loading.py` водит три круга, `enrich.py`
решает, у кого спрашивать оценки и что записывать, `library.py` собирает страницу
раздела. Завершает всё `backend/app.py` — единственное место, где бэкенд
собирается целиком.

Часть задач дописывает методы в файлы планов 1–3. Это не переделка: контракт
чтения виден только отсюда, и заводить второй `TmdbClient` ради одного дешёвого
запроса было бы хуже.

**Стек:** тот же, что в планах 1–3. Ни одной новой зависимости.

## Глобальные ограничения

Действуют на каждую задачу, повторять в них не нужно.

- **Зависит от планов 1, 2 и 3.** Готовы схема и репозитории; шесть клиентов
  источников с исходами `Found`/`Missing`/`Refusal`; `CardWriter`, `PosterService`,
  `ExternalRatingsRepository`, `CreditRepository`, `Linker`.
- **`backend` не импортирует `client`.** Тест из плана 1 это стережёт.
- **В сеть тесты не ходят.** Сеть подменяется `httpx.MockTransport` либо
  подставным клиентом.
- **База в тестах — временный файл**, свой на каждый прогон. Файлов два:
  основной и хранилище постеров.
- **Исключений из сервисов наружу не летит.** Отказ источника — это значение в
  результате, а не второй канал доставки.
- **Молча не глотаем ничего.** Пойманное исключение ведёт либо к отказу в
  результате, либо к записи в лог — минимум одно из двух.
- **Три состояния `external_rating`:** строки нет — не спрашивали; строка с
  пустым значением — спрашивали, у источника нет; строка со значением — есть
  оценка. Отказ не пишется никогда.
- **Выдача поиска в базу не попадает.** В базу попадает только детальный ответ,
  и сразу целиком.
- **Байтовые литералы только ASCII.** `b"текст"` с кириллицей — это
  `SyntaxError` на сборе, который валит весь прогон.
- **Дописывая метод в чужой файл, сверяйся с файлом.** Имена полей, констант и
  псевдонимов таблиц берутся оттуда, а не из головы, и новая функция из
  соседнего модуля добавляется в перечисление импортов явно.
- **Через границу слоёв ходят только простые данные.** Ни сессий, ни
  `httpx.Response`, ни объектов Qt. Постер — байты.
- **Комментарий объясняет неочевидное решение и пишется коротко.**

### Задача 1: Типы чтения

То, что ходит из бэкенда в ленту и обратно. Всё замороженное: лента держит эти
объекты у себя, и меняться под ней они не должны.

**`CardView` — один тип и для кандидата, и для карточки из базы.** Виджет у них
общий, у кандидата просто пустуют строки, которых нет в ответе поиска:
длительность, состав, свои оценки. Отличает их `item_id` — у кандидата, которого
ещё нет в базе, он пуст. Другого признака не нужно, а лишний завёл бы второе
место, где хранится один и тот же факт.

- Изменить: `backend/model/__init__.py`

- Отдаёт: `Tag`, `CardView`, `view_from_hit(hit, genres=()) -> CardView`,

```python
from dataclasses import dataclass
from datetime import datetime

from backend.model.credit import Credit
from backend.model.external import ExternalId, ExternalRating
from backend.model.genre import Genre
from backend.model.item import Item
from backend.model.kinds import Kind, RatingSource, Source
from backend.model.rating import Rating
from backend.model.search import SearchHit


@dataclass(frozen=True, slots=True)
class Tag:
    """Своя метка. В отличие от жанра, снаружи не приходит никогда."""

    id: int
    name: str


@dataclass(frozen=True, slots=True)
class CardView:
    """Всё, что показывает карточка ленты, одним объектом.

    Кандидат из выдачи и карточка из базы — это один тип: виджет у них общий, а
    строки, которых нет в ответе поиска, просто пустуют. Отличает их item_id."""

    kind: Kind
    source: Source
    source_id: str
    title: str

    item_id: int | None = None
    original_title: str = ""
    year: int | None = None
    synopsis: str = ""
    poster_url: str = ""
    runtime: int | None = None
    seasons_count: int | None = None
    episodes_count: int | None = None
    synced_at: datetime | None = None

    genres: tuple[Genre, ...] = ()
    tags: tuple[Tag, ...] = ()
    people: tuple[Credit, ...] = ()
    companies: tuple[Credit, ...] = ()
    external: tuple[ExternalRating, ...] = ()
    # Кого ещё спрашивают: на их месте в карточке крутится кольцо, а имя
    # источника стоит на месте, чтобы строка не прыгнула, когда цифра
    # приедет. Наполняет это поле показ, а не база: «ещё едет» — состояние
    # клиента, и знать его может только тот, кто отправил запрос.
    waiting: tuple[RatingSource, ...] = ()
    # На них собираются ссылки «открыть на IMDb» из карточки. Тащить их
    # отдельным запросом на карточку — ровно та цена, ради устранения которой
    # заведено пачечное чтение.
    external_ids: tuple[ExternalId, ...] = ()
    rating: Rating | None = None
    in_wishlist: bool = False


# Бесплатная оценка из выдачи принадлежит тому, кто её отдал. У Steam в поиске
# оценки нет вовсе, поэтому его тут и нет.
_OWN_RATING = {
    Source.TMDB: RatingSource.TMDB,
    Source.GOG: RatingSource.GOG,
}


def view_from_hit(hit: SearchHit, genres: tuple[Genre, ...] = ()) -> CardView:
    """Кандидат в выдаче. Жанры разворачивает справочник — в самом ответе
    поиска приходят голые идентификаторы."""
    own = _OWN_RATING.get(hit.source)
    external: tuple[ExternalRating, ...] = ()
    if own is not None and hit.source_rating is not None:
        external = (ExternalRating(source=own, value=hit.source_rating,
                                   fetched_at=datetime.now()),)

    return CardView(
        kind=hit.kind,
        source=hit.source,
        source_id=hit.source_id,
        title=hit.title,
        original_title=hit.original_title,
        year=hit.year,
        synopsis=hit.synopsis,
        poster_url=hit.poster_url,
        genres=genres,
        external=external,
    )


def view_from_item(item: Item) -> CardView:
    """Карточка из базы без довесков: жанры, теги, состав и оценки доливает
    ViewsRepository. Здесь только поля самой строки item."""
    return CardView(
        item_id=item.id,
        kind=item.kind,
        source=item.source,
        source_id=item.source_id,
        title=item.title,
        original_title=item.original_title,
        year=item.year,
        synopsis=item.synopsis,
        poster_url=item.poster_url,
        runtime=item.runtime,
        seasons_count=item.seasons_count,
        episodes_count=item.episodes_count,
        synced_at=item.synced_at,
    )
```

там называется иначе, импорт в шапке правится по факту — тип один и тот же.

```python
from dataclasses import dataclass
from enum import StrEnum


class Section(StrEnum):
    """Разделы, которые спрашивают у базы. Поиска тут нет: он спрашивает у
    источников, и фильтры на него не действуют."""

    RATED = "rated"
    WISHLIST = "wishlist"


class Sort(StrEnum):
    """Критерии порядка. Четыре первых перебирает кнопка в шапке, каждый в две
    стороны; ADDED_AT в переборе не участвует — это порядок по умолчанию в
    «Хочу посмотреть»."""

    SCORE = "score"          # своя оценка
    RATED_AT = "rated_at"    # когда оценивал
    YEAR = "year"            # год выхода
    TITLE = "title"          # по алфавиту
    ADDED_AT = "added_at"    # когда отложил


@dataclass(frozen=True, slots=True)
class Order:
    """Критерий и сторона. Умолчание — сверху то, чего больше: высокие оценки,
    свежие даты, новые фильмы."""

    key: Sort
    descending: bool = True


@dataclass(frozen=True, slots=True)
class Filters:
    """Пустой набор — это «показать всё».

    Внутри одного признака включённые складываются по «или», между признаками —
    по «и». Исключённые вычитаются последними и сильнее включённых: выбрал
    драму, исключил ужасы — получил драмы, среди которых нет ни одного ужаса,
    даже если он заодно и драма."""

    tag_ids: tuple[int, ...] = ()
    genre_ids: tuple[int, ...] = ()
    scores: tuple[int, ...] = ()   # столбцы гистограммы, дробные округляются вниз

    excluded_tag_ids: tuple[int, ...] = ()
    excluded_genre_ids: tuple[int, ...] = ()
    excluded_scores: tuple[int, ...] = ()


@dataclass(frozen=True, slots=True)
class Bucket:
    """Столбец гистограммы."""

    score: int
    count: int


@dataclass(frozen=True, slots=True)
class Histogram:
    """Столбцы и подвал под ними.

    `average` считает база по неокруглённым оценкам, а не клиент по столбцам:
    у игр оценка — среднее трёх шкал, и сумма по округлённым вниз столбцам
    занижала бы результат почти на полбалла."""

    buckets: tuple[Bucket, ...]
    total: int
    average: float | None   # пусто — считать нечего
```

```python
from collections import defaultdict
from dataclasses import replace as _replace

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker

from backend.model import (
    CardView,
    CompanyRole,
    Credit,
    ExternalId,
    ExternalRating,
    Genre,
    GenreKind,
    GenreSource,
    IdSource,
    PersonRole,
    Rating,
    RatingSource,
    Source,
    Tag,
    view_from_item,
)
from backend.storage.rows import to_item
from backend.storage.tables import (
    company,
    company_credit,
    external_id,
    external_rating,
    genre,
    item,
    item_genre,
    item_tag,
    person,
    person_credit,
    rating,
    tag,
    wishlist,
)


class ViewsRepository:
    """Собирает карточки для показа пачкой: по запросу на признак, а не на
    карточку. Порция ленты — 50 строк, и разница тут не косметическая."""

    def __init__(self, sessions: async_sessionmaker[AsyncSession]) -> None:
        self._sessions = sessions

    async def views_for(self, item_ids: list[int]) -> dict[int, CardView]:
        if not item_ids:
            return {}
        async with self._sessions() as session:
            return await self._fetch_all(session, item_ids)

    async def _fetch_all(
        self, session: AsyncSession, item_ids: list[int]
    ) -> dict[int, CardView]:
        views = {
            row.id: view_from_item(to_item(row))
            for row in (
                await session.execute(select(item).where(item.c.id.in_(item_ids)))
            ).all()
        }
        if not views:
            return {}

        known = list(views)
        genres = await self._genres(session, known)
        tags = await self._tags(session, known)
        people = await self._credits(session, known, person, person_credit,
                                     person_credit.c.person_id, PersonRole,
                                     with_position=True)
        studios = await self._credits(session, known, company, company_credit,
                                      company_credit.c.company_id, CompanyRole,
                                      with_position=False)
        external = await self._external(session, known)
        identifiers = await self._identifiers(session, known)
        ratings = await self._ratings(session, known)
        bookmarked = await self._wishlist(session, known)

        for item_id, view in views.items():
            views[item_id] = _replace(
                view,
                genres=tuple(genres[item_id]),
                tags=tuple(tags[item_id]),
                people=tuple(people[item_id]),
                companies=tuple(studios[item_id]),
                external=tuple(external[item_id]),
                external_ids=tuple(identifiers[item_id]),
                rating=ratings.get(item_id),
                in_wishlist=item_id in bookmarked,
            )
        return views

    async def _genres(self, session, item_ids):
        rows = (
            await session.execute(
                select(item_genre.c.item_id, genre)
                .join(genre, genre.c.id == item_genre.c.genre_id)
                .where(item_genre.c.item_id.in_(item_ids))
                .order_by(genre.c.name)
            )
        ).all()
        found = defaultdict(list)
        for row in rows:
            found[row.item_id].append(
                Genre(id=row.id, name=row.name, kind=GenreKind(row.kind))
            )
        return found

    async def _tags(self, session, item_ids):
        rows = (
            await session.execute(
                select(item_tag.c.item_id, tag.c.id, tag.c.name)
                .join(tag, tag.c.id == item_tag.c.tag_id)
                .where(item_tag.c.item_id.in_(item_ids))
                .order_by(tag.c.position)
            )
        ).all()
        found = defaultdict(list)
        for row in rows:
            found[row.item_id].append(Tag(id=row.id, name=row.name))
        return found

    async def _credits(self, session, item_ids, entity, credit, entity_column,
                       roles, with_position: bool):
        """Люди и студии читаются одним кодом: для приложения эти две сущности
        различаются только тем, что у людей есть порядок в титрах.

        entity_column передаётся снаружи, потому что колонка называется
        по-своему в каждой таблице связи: person_id и company_id."""
        columns = [credit.c.item_id, entity.c.name, credit.c.role,
                   entity.c.source, entity.c.source_id]
        if with_position:
            columns.append(credit.c.position)

        query = (
            select(*columns)
            .join(entity, entity.c.id == entity_column)
            .where(credit.c.item_id.in_(item_ids))
        )
        # У студий порядка в титрах нет, но устойчивый нужен и им: без него
        # они перетасовывались бы между показами одной и той же карточки.
        query = query.order_by(credit.c.position if with_position
                               else entity.c.id)

        found = defaultdict(list)
        for row in (await session.execute(query)).all():
            found[row.item_id].append(
                Credit(
                    name=row.name,
                    role=roles(row.role),
                    position=row.position if with_position else None,
                    source=Source(row.source) if row.source else None,
                    source_id=row.source_id,
                )
            )
        return found

    async def _external(self, session, item_ids):
        rows = (
            await session.execute(
                select(external_rating)
                .where(external_rating.c.item_id.in_(item_ids))
                .order_by(external_rating.c.source)
            )
        ).all()
        found = defaultdict(list)
        for row in rows:
            found[row.item_id].append(
                ExternalRating(source=RatingSource(row.source), value=row.value,
                               fetched_at=row.fetched_at)
            )
        return found

    async def _identifiers(self, session, item_ids):
        rows = (
            await session.execute(
                select(external_id)
                .where(external_id.c.item_id.in_(item_ids))
                .order_by(external_id.c.source)
            )
        ).all()
        found = defaultdict(list)
        for row in rows:
            found[row.item_id].append(
                ExternalId(source=IdSource(row.source), value=row.value)
            )
        return found

    async def _ratings(self, session, item_ids):
        rows = (
            await session.execute(
                select(rating).where(rating.c.item_id.in_(item_ids))
            )
        ).all()
        return {
            row.item_id: Rating(
                item_id=row.item_id, score=row.score, visual=row.visual,
                narrative=row.narrative, gameplay=row.gameplay,
                review=row.review or "",
            )
            for row in rows
        }

    async def _wishlist(self, session, item_ids):
        rows = (
            await session.execute(
                select(wishlist.c.item_id).where(wishlist.c.item_id.in_(item_ids))
            )
        ).all()
        return {row.item_id for row in rows}
```

**Из восемнадцати мутаций четыре прошли молча; две закрыты, две ненаблюдаемы.**
Молчали порядок в титрах (`position` наружу не сверялся) и общая закладка
(`bool(bookmarked)` вместо `item_id in bookmarked`) — обе закрыты. Ревью нашло
пятую того же рода: раскладка **всего** найденного под номер первой карточки
проходила молча, потому что каждый признак висел ровно на одной карточке из
двух. Теперь метка, оценка и жанр есть у обеих, но разные, а закладок две из
трёх: с одной не отличить «все достались первой», с тремя — «стоит у кого-то,
значит у всех».

Ненаблюдаемы две, и это измерено, а не предположено:

1. **Снятие отбора по номеру в чтении признака.** Найденное раскладывается в
   словарь по `item_id` из самой строки, а наружу берутся только запрошенные
   номера — лишние строки попадают в чужие ключи и отбрасываются. Выдача не
   меняется ни при каком расположении данных, дорожает только запрос.
2. **Снятие порядка по источнику у чужих оценок и идентификаторов.** Первичный
   ключ у обеих таблиц — `(item_id, source)`, и при отборе по номеру SQLite идёт
   по автоиндексу, возвращая строки уже в порядке источника: `EXPLAIN QUERY PLAN`
   даёт `SEARCH ... USING INDEX sqlite_autoindex_external_rating_1`, а выдача без
   `ORDER BY` алфавитна даже при обратном порядке вставки — при полном обзоре той
   же таблицы порядок вставки возвращается. `ORDER BY` остаётся: порядок нужен
   карточке, и держаться он должен на нём, а не на том, какой план выберет SQLite.

Ветка «ни одной из спрошенных карточек нет» тоже не наблюдалась выдачей — без неё
получается тот же пустой словарь, — и сторожит её теперь счёт запросов: один
вместо девяти, там же, где проверяется цена страницы.

```python
from sqlalchemy import Integer, cast, func, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker
from sqlalchemy.sql import Select

from backend.model import Filters, Kind, Order, Section, Sort
from backend.storage.tables import item, item_genre, item_tag, rating, wishlist

# Округление вниз делаем через CAST, а не через floor(): математические функции
# в SQLite включаются при сборке, и рассчитывать на них нельзя. Оценки
# положительные, для них CAST и есть округление вниз.
_COLUMN = cast(rating.c.score, Integer)

# Сортировка по названию идёт по приведённой строке: встроенный в SQLite
# lower() умеет только ASCII, и «Аватар» с «аватаром» разъехались бы.
_KEYS = {
    Sort.SCORE: rating.c.score,
    Sort.RATED_AT: rating.c.updated_at,
    Sort.YEAR: item.c.year,
    Sort.TITLE: func.py_lower(item.c.title),
    Sort.ADDED_AT: wishlist.c.added_at,
}


class SectionsRepository:
    """Кто попадает в ленту и в каком порядке. Отдаёт идентификаторы: состав
    карточки собирает ViewsRepository."""

    def __init__(self, sessions: async_sessionmaker[AsyncSession]) -> None:
        self._sessions = sessions

    async def ids(self, section: Section, kind: Kind, filters: Filters,
                  order: Order, limit: int, offset: int) -> list[int]:
        key = _KEYS[order.key]
        query = self._narrow(select(item.c.id), kind, section, filters)
        # Второй ключ — идентификатор: без него равные оценки перетасовывались
        # бы между порциями, и карточка попадала бы в две сразу либо ни в одну.
        query = query.order_by(
            key.desc() if order.descending else key.asc(), item.c.id
        ).limit(limit).offset(offset)

        async with self._sessions() as session:
            result = await session.execute(query)
            return [row.id for row in result.all()]

    def _narrow(self, query: Select, kind: Kind, section: Section,
                filters: Filters) -> Select:
        """Общая часть запроса раздела и гистограммы: они обязаны считать по
        одному и тому же набору, иначе отфильтрованную гистограмму не увидеть."""
        query = query.select_from(
            item
            .outerjoin(rating, rating.c.item_id == item.c.id)
            .outerjoin(wishlist, wishlist.c.item_id == item.c.id)
        ).where(item.c.kind == str(kind))

        if section is Section.RATED:
            query = query.where(rating.c.score.is_not(None))
        elif section is Section.WISHLIST:
            query = query.where(wishlist.c.item_id.is_not(None))

        if filters.tag_ids:
            query = query.where(item.c.id.in_(
                select(item_tag.c.item_id)
                .where(item_tag.c.tag_id.in_(filters.tag_ids))
            ))
        if filters.genre_ids:
            query = query.where(item.c.id.in_(
                select(item_genre.c.item_id)
                .where(item_genre.c.genre_id.in_(filters.genre_ids))
            ))
        if filters.scores:
            query = query.where(_COLUMN.in_(filters.scores))

        # Исключённое вычитается последним и сильнее включённого: выбрал драму,
        # исключил ужасы — ужас, который заодно и драма, всё равно не покажется.
        if filters.excluded_tag_ids:
            query = query.where(item.c.id.not_in(
                select(item_tag.c.item_id)
                .where(item_tag.c.tag_id.in_(filters.excluded_tag_ids))
            ))
        if filters.excluded_genre_ids:
            query = query.where(item.c.id.not_in(
                select(item_genre.c.item_id)
                .where(item_genre.c.genre_id.in_(filters.excluded_genre_ids))
            ))
        if filters.excluded_scores:
            # NULL здесь обязателен. В разделе «Хочу посмотреть» у отложенного,
            # но не оценённого, score пуст, а `NULL NOT IN (3)` в SQL — это
            # NULL, а не истина: строка отсеется, и карточки молча пропадут из
            # раздела. Неоценённое исключением по оценке не задевается.
            query = query.where(
                _COLUMN.is_(None) | _COLUMN.not_in(filters.excluded_scores)
            )

        return query
```

мутации.** Тест на алфавит брал «яблоко», «Аватар» и «автобус» — у этой троицы
побайтовый порядок совпадает с алфавитным, и потеря приведения регистра
проходила незамеченной. Заглавная «Я» их разводит. Ревью по тестам нашло ту же
болезнь ещё в пяти проверках порядка: с двумя карточками ожидаемый порядок
совпадает либо с порядком появления, либо с обратным, и подмена ключа сортировки
на номер строки зеленела. Во всех пяти теперь три карточки, расставленные так,
что ни то, ни другое не совпадает.

**Про второй ключ порядка ревью и исполнитель разошлись, и правы оба
наполовину.** Исполнитель объявил его ненаблюдаемым, сославшись на то, что
`rating.item_id` служит rowid; рецензент опроверг это замером на своей схеме, где
порядок пошёл по годам. Оба замера верны, а причина в другом: индексов,
начинающихся с `kind`, в схеме два. По `ix_item_kind` порядок при равных оценках
совпадает с порядком номеров, по `ix_item_kind_year` — с порядком годов, и выбор
между ними делает планировщик. Оба выбора получены на одной и той же схеме,
одних данных и одном запросе — в прогоне тестов и в отдельном скрипте.
`ORDER BY item.id` остаётся именно поэтому: полагаться на выбор планировщика
нельзя. Тест сторожит его настолько, насколько может: годы в нём идут против
номеров, и при выборе годового индекса он краснеет.

Ненаблюдаема одна мутация, и это подтвердили оба: перестановка `_included` и
`_excluded`. Оба добавляют условия в одну конъюнкцию, порядок добавления
результат не меняет; сила исключения держится на виде условия — `NOT IN`, — а не
на месте вызова. Докстринг `_excluded` про «вычитается последним» поэтому и
переписан: он объяснял решение, которого в коде нет.

### Задача 4: Гистограмма

Десять столбцов, дробные оценки округляются вниз. **Считается по тому же
отфильтрованному набору, что и лента** — за это отвечает общий `_narrow` из
задачи 3, и разойтись эти два ответа не могут по построению.

**Одно исключение: фильтр по оценке гистограмма не применяет.** Он выражен теми
же десятью столбцами, что и она сама, — то есть это один и тот же признак.
Применив его к себе, гистограмма схлопнулась бы в один столбец: выбрал семёрки —
и увидел, что у тебя только семёрки. Признак не фильтрует сам себя; теги и жанры
— другие признаки, и их гистограмма слушается.

Спека этого случая не разбирает: требование «по тому же отфильтрованному набору»
там мотивировано тегами и жанрами. Решение записано в «Числа и правила, взятые не
из спек».

```python
    async def histogram(self, kind: Kind, filters: Filters) -> Histogram:
        """Десять столбцов всегда, включая пустые: пустой столбец — это
        сведение, а не отсутствие данных. Плюс подвал: сколько всего и средняя.

        Раздел здесь всегда «Оценённые»: гистограмма строится по выставленным
        оценкам, и в «Хочу посмотреть» считать нечего.

        Фильтр по оценке снимаем — и включение, и исключение: он выражен теми
        же столбцами, что и сама гистограмма, и применённый к себе схлопнул бы
        её в один столбец."""
        narrowed = replace(filters, scores=(), excluded_scores=())

        columns = self._narrow(
            select(_COLUMN.label("bucket"), func.count().label("total")),
            kind, Section.RATED, narrowed,
        ).group_by("bucket")

        # Средняя считается по неокруглённым оценкам: у игр score — среднее
        # трёх шкал, и сумма по столбцам занизила бы её почти на полбалла.
        summary = self._narrow(
            select(func.count().label("total"), func.avg(rating.c.score).label("mean")),
            kind, Section.RATED, narrowed,
        )

        async with self._sessions() as session:
            rows = (await session.execute(columns)).all()
            totals = (await session.execute(summary)).one()

        counts = dict.fromkeys(range(1, 11), 0)
        for row in rows:
            # Шкала 1–10, но столбец не теряем, даже если в базе оказалось иное.
            counts[min(10, max(1, row.bucket))] += row.total

        return Histogram(
            buckets=tuple(Bucket(score=score, count=counts[score])
                          for score in range(1, 11)),
            total=totals.total,
            average=float(totals.mean) if totals.mean is not None else None,
        )
```

```python
from backend.model import CardView, Filters, Histogram, Kind, Order, Section, Sort
from backend.storage.repository.sections import SectionsRepository
from backend.storage.repository.views import ViewsRepository

# Лента читается с диска и стоит дёшево. Величина — настройка, а не свойство
# схемы: меняется этой строкой.
PAGE_SIZE = 50


class LibraryService:
    """Страница раздела и гистограмма.

    «Оценённые» и «Хочу посмотреть» отличаются только тем, что спрашивают у
    базы, — поэтому метод у них один. Поиск ходит в SearchService: он
    спрашивает не базу, статистика — это histogram."""

    def __init__(self, sections: SectionsRepository,
                 views: ViewsRepository) -> None:
        self._sections = sections
        self._views = views

    async def page(self, section: Section, kind: Kind, filters: Filters,
                   order: Order, offset: int = 0,
                   limit: int = PAGE_SIZE) -> list[CardView]:
        item_ids = await self._sections.ids(section, kind, filters, order,
                                            limit=limit, offset=offset)
        found = await self._views.views_for(item_ids)
        # Порядок принадлежит запросу раздела: словарь его не хранит.
        return [found[item_id] for item_id in item_ids if item_id in found]

    async def histogram(self, kind: Kind, filters: Filters) -> Histogram:
        return await self._sections.histogram(kind, filters)
```

```python
        return [found[item_id] for item_id in item_ids if item_id in found]
```

### Задача 7: Внешний поиск и снятие дублей

```python
    популярности и совпадении с запросом, которых у нас нет.

    Дубли снимаются по паре «источник + идентификатор». Одна и та же игра из
    Steam и из GOG под эту пару не попадает и показывается дважды."""
    mine = {(view.source, view.source_id): view for view in local}

    merged: list[CardView] = []
    seen: set[tuple[Source, str]] = set()
    for view in external:
        key = (view.source, view.source_id)
        if key in seen:
            continue
        seen.add(key)
        # Своё стоит на своём месте и ничем не выделено — но показываем именно
        # его: у него есть оценка, теги и закладка.
        merged.append(mine.get(key, view))

    merged.extend(view for view in local
                  if (view.source, view.source_id) not in seen)
    return merged


def _weave(answers: list[list[SearchHit]]) -> list[SearchHit]:
    """Выдачи нескольких источников — вперемешку, по одному кандидату по кругу.

    У игр магазина два, и склеить их подряд нельзя: поиск GOG никогда не
    отвечает «не найдено» и на бессмыслицу отдаёт два десятка несвязанных игр.
    Подряд это значит, что вторая половина страницы — всегда мусор GOG, а его
    настоящие находки начинаются там, куда никто не доскроллит.

    Порядок внутри каждой выдачи сохраняется: он задан источником."""
    if len(answers) == 1:
        return answers[0]

    woven = []
    for position in range(max((len(answer) for answer in answers), default=0)):
        for answer in answers:
            if position < len(answer):
                woven.append(answer[position])
    return woven
```

```python
import asyncio
import logging
from datetime import datetime

from backend.model import CardView
from backend.service.cards import CardWriter
from backend.service.posters import PosterService
from backend.sources.errors import Found, Missing, Reason, Refusal
from backend.sources.registry import Sources
from backend.storage.repository.library import LibraryRepository

logger = logging.getLogger(__name__)


class Loader:
    """Три круга загрузки. Первый — выдача поиска, она уже позади: на входе
    кандидат. Здесь второй, детальный ответ и обложка разом, и запись."""

    def __init__(self, library: LibraryRepository, writer: CardWriter,
                 sources: Sources, posters: PosterService,
                 clock=datetime.now) -> None:
        self._library = library
        self._writer = writer
        self._sources = sources
        self._posters = posters
        self._clock = clock

    async def ensure(self, view: CardView) -> int | Missing | Refusal:
        """Идентификатор карточки в базе: уже лежавшей или только что
        записанной. Missing — источник её больше не знает."""
        if view.item_id is not None:
            return view.item_id

        existing = await self._library.find_by_source(view.source, view.source_id)
        if existing is not None:
            return existing.id

        client = self._sources.client_for(view.source)
        if client is None:
            logger.warning("нечем загрузить карточку источника %s", view.source)
            return Refusal(source=str(view.source), reason=Reason.BROKEN,
                           detail=f"нет каталожного клиента для {view.source}")

        # Круги 2а и 2б: адрес обложки пришёл ещё с выдачей поиска, поэтому
        # детальный ответ её не ждёт.
        card, poster = await asyncio.gather(
            client.card(view.source_id, view.kind),
            self._posters.fetch(view.source, view.poster_url),
            return_exceptions=True,
        )

        for outcome in (card, poster):
            # Сорвалось не отказом, а исключением — наружу оно не летит:
            # у границы потоков второго канала доставки нет.
            if isinstance(outcome, BaseException):
                logger.exception("загрузка карточки %s сорвалась",
                                 view.source_id, exc_info=outcome)
                return Refusal(source=str(view.source), reason=Reason.BROKEN,
                               detail=str(outcome))

        if isinstance(poster, Refusal):
            # Не скачалась — карточка не пишется вовсе: повторим при следующем
            # показе. Отдельного случая тут нет, это общее правило.
            return poster
        if not isinstance(card, Found):
            return card

        return await self._writer.save(card.value, poster)
```

```python
    async def refresh(self, item_id: int) -> None:
        """Число сезонов и серий у сериала — единственное, что перезапрашивается.
        Всё остальное с момента создания карточки принадлежит тебе."""
        item = await self._library.get(item_id)
        if item is None or item.kind is not Kind.SERIES:
            return
        if item.source is not Source.TMDB:
            # Ручной карточке перезапрашивать нечего: она ниоткуда не приезжала.
            return
        if self._clock() - item.synced_at <= REFRESH_TTL:
            return

        outcome = await self._sources.client_for(Source.TMDB).series_counts(
            item.source_id
        )
        if isinstance(outcome, Missing):
            logger.warning("TMDB больше не знает сериал %s", item.source_id)
            return
        if not isinstance(outcome, Found):
            # Отказ — состояние данных: повторим при следующем показе.
            return

        await self._library.refresh_series_counts(
            item_id, outcome.value.seasons, outcome.value.episodes,
            now=self._clock(),
        )
```

```python
import asyncio
import logging
from datetime import datetime

from backend.model import ExternalRating, IdSource, Kind, RatingSource
from backend.sources.errors import Found, Missing, Refusal
from backend.sources.registry import Sources
from backend.storage.repository.external import (
    ExternalIdsRepository,
    ExternalRatingsRepository,
    IdentityTaken,
)

logger = logging.getLogger(__name__)


class Enricher:
    """Третий круг: чужие оценки. Идёт после второго не по удобству, а по
    данным — imdb_id есть только в детальном ответе.

    Здесь производится второе из трёх состояний external_rating: строка с
    пустым значением, «спрашивали, у источника нет»."""

    def __init__(self, sources: Sources, ids: ExternalIdsRepository,
                 ratings: ExternalRatingsRepository,
                 clock=datetime.now) -> None:
        self._sources = sources
        self._ids = ids
        self._ratings = ratings
        self._clock = clock

    async def enrich(self, item_id: int, kind: Kind) -> list[ExternalRating]:
        clients = self._sources.rating_sources(kind)
        wanted = self.expected(kind)
        if not wanted:
            # У игр оценки приезжают вместе с карточкой: спрашивать некого.
            return await self._ratings.ratings_of(item_id)

        now = self._clock()
        stale = await self._ratings.stale_sources(item_id, wanted, now)
        if not stale:
            return await self._ratings.ratings_of(item_id)

        imdb_id = await self._imdb_id(item_id)
        if imdb_id is None:
            logger.info("карточка %s без imdb_id: агрегаторов спросить нечем",
                        item_id)
            return await self._ratings.ratings_of(item_id)

        asked = [client for client in clients
                 if set(client.PROVIDES) & set(stale)]
        outcomes = await asyncio.gather(
            *(client.ratings(imdb_id, kind) for client in asked),
            return_exceptions=True,
        )

        await self._write(item_id, stale, now, asked, outcomes)
        return await self._ratings.ratings_of(item_id)

    def expected(self, kind: Kind) -> list[RatingSource]:
        """Кого вообще спрашивают у этого типа содержимого.

        Нужно показу: пока ответы едут, на их месте крутится кольцо, а вычесть
        приехавшее из ожидаемого можно только зная второе. Внутри бэкенда это
        известно, снаружи — нет."""
        return _union(client.PROVIDES
                      for client in self._sources.rating_sources(kind))

    async def _imdb_id(self, item_id: int) -> str | None:
        for external in await self._ids.ids_of(item_id):
            if external.source is IdSource.IMDB:
                return external.value
        return None

    async def _write(self, item_id, stale, now, asked, outcomes) -> None:
        values: dict[RatingSource, float] = {}
        answered: set[RatingSource] = set()
        refused: set[RatingSource] = set()

        for client, outcome in zip(asked, outcomes):
            if isinstance(outcome, BaseException):
                # Сорвалось исключением — считаем отказом: писать пустоту по
                # источнику, который до ответа не дошёл, нельзя, иначе в базе
                # на неделю поселится «у него такого нет».
                logger.exception("обогащение %s сорвалось", client,
                                 exc_info=outcome)
                refused.update(client.PROVIDES)
                continue
            if isinstance(outcome, Refusal):
                # Отказ не пишется никогда — ни значением, ни пустотой.
                refused.update(client.PROVIDES)
                continue
            answered.update(client.PROVIDES)
            if not isinstance(outcome, Found):
                # Missing: источник ответил, что такого не знает.
                continue
            for rating in outcome.value.values:
                if rating.value is not None and rating.source not in values:
                    values[rating.source] = rating.value
            for external in outcome.value.external_ids:
                await self._keep(item_id, external)

        # Значение пишем и то, которого не просили: оно уже приехало даром.
        for source, value in values.items():
            await self._ratings.record(item_id,
                                       ExternalRating(source, value, now))

        for source in stale:
            if source in values or source not in answered or source in refused:
                # Отказавший знающий источник — это «не смогли посмотреть», а
                # не «такого нет». Пустоту тут писать нельзя.
                continue
            await self._ratings.record(item_id, ExternalRating(source, None, now))

    async def _keep(self, item_id: int, external) -> None:
        try:
            await self._ids.put(item_id, external)
        except IdentityTaken as error:
            logger.warning("идентификатор %s занят: %s", external.value, error)


def _union(groups) -> list[RatingSource]:
    """Список, а не множество: у stale_sources порядок задаёт, в каком виде
    вернётся ответ, и воспроизводимость тут дешевле недетерминизма."""
    seen: list[RatingSource] = []
    for group in groups:
        for source in group:
            if source not in seen:
                seen.append(source)
    return seen
```

**Списка ответивших нет.** Ревью доказало построением, что он избыточен: каждый

отказал, либо ответил, — значит «про него не ответил никто» это ровно «все, кто
его знает, отказали». Осталось одно множество, отказавших.

**Снятие повторов с сохранением порядка вынесено** в `backend/unique.py`: ревью
нашло четыре независимые реализации одного приёма — в разрешении жанров, в их
разборе на записи, в развороте жанров кандидата и в подсчёте ожидаемых
источников. Две были через `dict.fromkeys`, две — ручным циклом.

**Необъявленную оценку не берём.** Ревью нашло дыру, которой не видела ни одна
мутация: `PROVIDES` — единственная правда про источник, на ней стоит и запись
пустого значения, и подсчёт ожидаемого. Оценка от того, кто её не обещал,
попадала в базу как есть: в карточке появился бы источник, которого показ не
ждёт, а пустое значение по нему уже никто бы не написал. Теперь такая оценка
отбрасывается с записью в лог, и на это есть проверка.

источник ответил null, а второй числом; снятый ранний выход — закрыт счётом

```python
        self, link: ExternalLink
    ) -> SourceCard | Missing | Refusal:
        """Разобранная ссылка — в карточку источника, готовую для Linker.

        if link.source is Source.GOG:
            resolved = await client.resolve_slug(source_id)
            if not isinstance(resolved, Found):
                return resolved
            source_id = resolved.value

        outcome = await client.card(source_id, link.kind)
```

```python
)
from backend.storage.repository.genres import GenresRepository
from backend.storage.repository.library import LibraryRepository
from backend.storage.repository.ratings import RatingsRepository
from backend.storage.repository.sections import SectionsRepository
from backend.storage.repository.tags import TagsRepository
from backend.storage.repository.views import ViewsRepository
from backend.storage.repository.wishlist import WishlistRepository
from backend.storage.session import create_engine, session_factory


@dataclass(slots=True)
class Backend:
    """Всё, что клиент может спросить. Один объект вместо десятка ссылок,
    которые пришлось бы тащить через границу потоков поодиночке."""

    library: LibraryRepository
    ratings: RatingsRepository
    tags: TagsRepository
    wishlist: WishlistRepository
    genres: GenresRepository
    people: CreditRepository
    companies: CreditRepository
    ids: ExternalIdsRepository
    external_ratings: ExternalRatingsRepository
    # Одна карточка по идентификатору: после загрузки кандидата и после
    # простановки оценки ленте надо перерисовать её, а не всю страницу.
    views: ViewsRepository

    search: SearchService
    feed: LibraryService
    loader: Loader
    enricher: Enricher
    linker: Linker
    posters: PosterService
    sources: Sources

    _engine: object
    _closed: bool = False

    async def aclose(self) -> None:
        # Закрыть могут и владелец, и фикстура теста — второй раз тихо.
        if self._closed:
            return
        self._closed = True
        await self.sources.aclose()
        await self.posters.aclose()
        await self._engine.dispose()


async def build_backend(
    config: Config, transport: httpx.AsyncBaseTransport | None = None
) -> Backend:
    """Единственное место, где бэкенд собирается целиком.

    Транспорт внедряется ради тестов: без него каждый клиент поднимает
    настоящий AsyncClient со своим SSL-контекстом."""
    config.data_dir.mkdir(parents=True, exist_ok=True)

    engine = create_engine(config.library_db)
    sessions = session_factory(engine)

    store = PosterStore(config.posters_db)
    await store.open()

    sources = build_sources(config, transport=transport)
    # Своя ветка на источник: у каждого свой предохранитель и свой заголовок.
    posters = PosterService(
        {
            Source.TMDB: SourceHttp("tmdb-poster", transport=transport),
            Source.STEAM: SourceHttp("steam-poster", transport=transport),
            Source.GOG: SourceHttp("gog-poster", transport=transport),
        },
        store,
    )

    library = LibraryRepository(sessions)
    genres = GenresRepository(sessions)
    person_repository = people(sessions)
    company_repository = companies(sessions)
    ids = ExternalIdsRepository(sessions)
    external_ratings = ExternalRatingsRepository(sessions)
    views = ViewsRepository(sessions)

    writer = CardWriter(library=library, genres=genres, people=person_repository,
                        companies=company_repository, ids=ids,
                        ratings=external_ratings, posters=posters)

    return Backend(
        library=library,
        ratings=RatingsRepository(sessions),
        tags=TagsRepository(sessions),
        wishlist=WishlistRepository(sessions),
        genres=genres,
        people=person_repository,
        companies=company_repository,
        ids=ids,
        external_ratings=external_ratings,
        views=views,
        search=SearchService(library=library, views=views, sources=sources,
                             genres=genres),
        feed=LibraryService(SectionsRepository(sessions), views),
        loader=Loader(library=library, writer=writer, sources=sources,
                      posters=posters),
        enricher=Enricher(sources=sources, ids=ids, ratings=external_ratings),
        linker=Linker(library=library, genres=genres, people=person_repository,
                      companies=company_repository, ids=ids,
                      ratings=external_ratings, posters=posters),
        sources=sources,
        posters=posters,
        _engine=engine,
    )
```

## Числа и правила, взятые не из спек

Решения этого плана. Ни одно ниоткуда не следует, менять свободно:

| Что | Значение | Почему так |
|---|---|---|
| Фильтр по оценке | набор столбцов, а не диапазон | шкала из десяти цветов общая у фильтра и гистограммы; диапазон — частный случай набора, и переход к нему не меняет ни схему, ни запрос |
| **Гистограмма фильтр по оценке не применяет** | ни включение, ни исключение | это тот же признак, что она сама: применённый к себе, он схлопнул бы её в один столбец. Теги и жанры — другие признаки, их она слушается. Записано и в спеке разделов |
| Внутри признака «или», между признаками «и» | так | обычное поведение фасетного фильтра; спека молчит |
| Алфавитный порядок идёт по `py_lower(title)` | так | у названия индекса нет, и это цена, принятая ради того, чтобы «Аватар» и «аватар» не разъезжались |
| Второй ключ сортировки | `item.id` | без него равные оценки перетасовываются между порциями |
| Порядок жанров в карточке | по названию | спека молчит; источник порядка не даёт |
| Порядок оценок агрегаторов и внешних идентификаторов | по имени источника | то же |
| Порядок студий в карточке | по идентификатору | порядка в титрах у них нет, но перетасовываться между показами они не должны |
| **Выдачи двух магазинов переплетаются**, по кандидату по кругу | так | спека требует «показывают вперемешку». Подряд вторая половина страницы всегда была бы GOG, а он на бессмыслицу отдаёт два десятка несвязанных игр |
| Порядок в «показать всё с этим человеком» | по своей оценке, неоценённые следом | спека молчит; вопрос тот же, что в «Оценённых» — что у него стоит смотреть |
| `REFRESH_TTL` | 30 дней | «срок прежний, месяц» из модели данных — тот же, что у оценки со значением |
| Пустая строка `external_rating` при отказе знающего источника | не пишется | продолжение правила «плашка только когда база не ответила» |
| При двух знающих источниках побеждает первый | так | иначе значение зависело бы от того, кто быстрее ответил по сети |
| Значение, приехавшее сверх запрошенного | записывается | оно уже приехало даром, а `fetched_at` от этого только свежее |
| Порция внешнего поиска | 20 на источник, не на выдачу | у игр магазина два, и по 20 у каждого — это два запроса, как и сказано в спеке |
| **`Refusal`, `Missing` и `Reason` клиент импортирует из `backend.sources.errors`** | так | структура кода велит держать типы границы в `backend/model/`, но эти три производят источники, а модель — самый нижний слой и зависеть от них не должна. Обратное направление хуже: `model` начал бы знать про `sources` |

## Открытые вопросы

**Пагинация внешнего поиска.** Спека говорит «20 кандидатов **за раз**», то есть
предполагает вторую порцию. Контракт клиентов из плана 2 её не позволяет:
`search(query, kind)` без номера страницы, и это проверяется тестом реестра.
Добавление — новый необязательный аргумент у трёх каталожных клиентов и правка
того теста; сейчас поиск отдаёт одну страницу и на этом останавливается.

**Слаг GOG живьём не проверен** — ни имя поля `slug` в ответе каталога, ни то,
что каталог вообще находит игру по её собственному слагу. Фикстура написана
руками и помечена в README.

**Что делает интерфейс с `Missing` от загрузчика.** Кандидат был в выдаче, а
детального ответа по нему нет — источник его потерял между двумя запросами.
Загрузчик отдаёт `Missing`, но убирать ли строку с экрана, показывать ли плашку,
не записано ни в спеке, ни здесь.

**Отдельные шкалы у игр.** Фильтр, сортировка и гистограмма работают с
`rating.score`. Осмысленно смотреть гистограмму по нарративу — записано в спеке
разделов как план расширения; схема готова, здесь не делается.

**Два запроса опираются на поведение именно SQLite** — и это законно, база у нас
одна, но помнить стоит. Первое: `SELECT DISTINCT` с сортировкой по колонке вне
списка выбираемых (`items_of`) — SQLite такое принимает, PostgreSQL отказал бы.
Второе: при `DESC` пустые значения уходят вниз, и на этом стоят «неоценённые
следом» и сортировка по году у карточек без года. Проверено прогоном на
SQLite 3.45.3.
